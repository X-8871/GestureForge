# S1-T02-D6 检测评估口径与离线指标基础

## 状态与边界

本任务实现 PC 检测结果的离线绑定和指标计算基础，作为后续正式浮点/INT8 评估的固定入口。当前阶段一状态为 `PC_SCOPE_FROZEN; BOARD_AND_INT8_DETECTION_GATE_RETAINED`：冻结的固定口径和 tiny416 正式 test 结果见 `report/evidence/S1-T02/20260922_s1_t02_d6_metric_policy_r2.json` 及 `20260922_s1_t02_d6_tiny416_test_formal_clip_r1.json`。本文件保留指标实现规则，不把夹具、网页人工测试或 PC 结果升级为板上验收。

正式样本最低口径已由 Wong 于 2026-09-18 批准：当前批准 manifest（SHA-256 `fd60e7a67161f242276a1b97b09ad07c0d7f41d30067266bb99620abe6d7ed74`）中的全部官方 test 图片，共 25,484 张，作为主要最终测试集；另建独立 robustness set，五个 gesture 类别 `fist,palm,one,two_up,three` 各至少 100 张唯一图片，且每个 robustness condition bucket（`no_hand`、`non-target`、多手、遮挡、小目标）各至少 100 张唯一图片。`no_hand` 是负样本条件，不是第六类。每个 bucket 按唯一图片计数；同一图片只有在标注或其他审计证据支持时才可计入多个 condition bucket。robustness set 的 person 与 session 均须分别与 train、val、test 完全隔离。该数值口径已获批准，但 robustness set 尚未证实已构建或绑定，不能据此声称数据集已存在或验收完成。

最终 score threshold 已固定为 `0.25`，NMS IoU 为 `0.45`，每图最多输出 `15` 个框；test 和 robustness 禁止重新调参。阶段一浮点门为 mAP@0.5≥0.90、mAP@0.5:0.95≥0.70、五类逐类 precision/recall≥0.90；robustness 清单尚未作为阶段一正式结果绑定。

### 坐标越界政策（Wong 于 2026-09-21 确认）

正式计分采用 `clip_finite_positive_xyxy_to_unit_range`：预测框先按其声明格式解码为归一化 `xyxy`，要求四个 raw 坐标有限且 raw 面积为正，再对每个坐标执行 `min(max(value, 0), 1)`。Darknet `relative_coordinates` 的中心和尺寸必须有限，尺寸为正；尺寸超过 1 不因字段值本身越界而提前拒绝，最终按 raw xyxy 和裁剪后面积判定。裁剪后仍须满足 `right>left` 且 `bottom>top`；完全位于图像外、边界相切或裁剪后零面积的框拒绝。GT 标签仍严格要求原始归一化坐标在 `[0,1]` 内，不执行裁剪。

该政策保留 raw 严格拒绝作为诊断分支，不改变候选预测输入文件；旧坐标影响诊断属于已清理的中间证据。当前正式结果只认 r2 指标策略和 tiny416 final test 文件。

## 输入和严格绑定

评估器入口为 `verification/s1_t02_d6_detection_metrics.py`，只读取 UTF-8 的 manifest、YOLO 标签、class names 和预测文件。manifest 必须包含 `image,label,split` 字段；保留目标 split 的原始顺序，并按同 stem 标签绑定。标签使用五列归一化 YOLO `class_id center_x center_y width height`，空文件表示 zero-label 图片；类别严格为五类 `fist,palm,one,two_up,three`，坐标必须有限且在批准归一化范围内。

预测输入必须自描述：

- 当前 Darknet 数组 JSON 的每条记录含 `filename`、可选 `frame_id` 和 `objects`；每个 object 使用 `relative_coordinates`，并含 `name` 或 `class_id`。二者同时存在时必须一致。
- 也支持显式声明 `coordinate_format=xyxy_normalized` 的 `xyxy` 四元组；没有声明时不根据数值猜测格式。
- 预测记录数量、规范化后的 filename、可选 `frame_id` 必须与 manifest split 一一对应、同序、无缺失、无重复、无额外记录、无跨 split；预测 confidence 和类别必须有限且合法，坐标必须有限、raw 面积为正且裁剪后保留正面积。

报告保存输入文件和代码 SHA-256、split、计数、配置与状态，报告和摘要必须是不同路径，且不能覆盖输入。raw Darknet JSON 本身不等于 mAP。

## 固定计算口径

0. 预测框按上方坐标越界政策完成 raw 校验和显式裁剪；报告同时保留 raw 坐标、裁剪后坐标、裁剪数量及 raw 对照证据绑定。
1. 先保留 `confidence >= score_threshold` 的框，按 score 降序稳定排序；同分保持原输入顺序。
2. 每图最多保留 15 个框，然后执行类别内 greedy NMS，IoU=`0.45`；不同类别不相互抑制。
3. AP 在 IoU `0.50,0.55,...,0.95` 上分别计算。预测按全体图片的 score 降序（同分按 manifest 顺序、再按图内输入顺序）处理；同图同类 GT 一对一匹配，IoU 达到阈值才算 TP。
4. 每个 IoU 阈值使用 101 个 recall 点 `0..1` 的 all-point precision 插值。五类 mAP 为有 GT 类别的宏平均；无 GT 类别保留 `support_gt=0` 和 `null` AP，不静默填零或删除。报告同时保留每类各 IoU 的 AP、support、TP/FP/FN、固定 score threshold 下 IoU=0.5 的 precision/recall。
5. no_hand 和 non-target 误检率按批准的图片清单逐图统计：该图 NMS 后仍有预测即误检。未提供批准 subset 时状态为 `NOT_EXECUTED`，不能伪造为 0%。

## CLI 与复现

输入、JSON 报告、Markdown 摘要必须使用三个不同路径。例如：

```text
py -3 -B verification/s1_t02_d6_detection_metrics.py --manifest <manifest.csv> --data-root <data-root> --labels-root <labels-root> --predictions <predictions.json> --class-names <gesture.names> --split val --score-threshold 0.25 --nms-iou 0.45 --max-outputs 15 --report <独立-report.json> --summary <独立-summary.md>
```

非法输入或绑定失败返回退出码 `2`，并在 stderr 输出 `D6_ERROR`；成功生成的报告退出码为 `0`，但在本阶段仍保持 `G0_PENDING`。专项夹具测试可从仓库根目录运行：

```text
py -3 -B -m unittest verification.test_s1_t02_d6_detection_metrics -v
```
