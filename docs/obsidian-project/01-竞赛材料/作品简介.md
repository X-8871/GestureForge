# 作品简介（导师沟通版）

> 本笔记为可直接阅读和转发的完整版本。

## 选题方向

FPGA 创新设计赛道，AMD 自主选题。

## 作品名称

基于 AX7Z020 的低比特神经网络 FPGA 加速系统，实现摄像头手势识别并驱动板卡进行实时交互。

## 一句话简介

本项目拟基于 ALINX AX7Z020 构建低比特视觉指令识别系统，通过 FPGA/PL 完成图像预处理和 INT8 神经网络关键计算，由 Zynq PS 侧负责控制与结果解析，并根据手势识别结果驱动 HDMI、LED、串口或其他板载接口完成交互。

## 作品简介正文

本作品面向资源受限的端侧视觉智能场景，构建基于 Zynq-7000 的低比特视觉指令识别系统。系统以摄像头或固定图像作为输入，经图像预处理后输入轻量化 INT8 神经网络；FPGA/PL 侧承担主要乘加和推理计算，Zynq PS 侧负责任务控制、结果解析与交互逻辑。识别结果计划通过 HDMI、LED、串口或其他板载接口进行可视化和控制反馈。

作品将围绕同一模型和同一测试集，对比 ARM 软件基线与 FPGA 加速结果，记录识别准确率、端到端延迟、吞吐率、资源占用和运行稳定性，形成可复现、可测量、可现场演示的完整闭环。

## 拟解决的问题

1. 在有限的 LUT、FF、BRAM 和 DSP 资源下，实现小型视觉模型的定点推理。
2. 明确 Zynq PS 与 PL 的职责分工，建立启动、计算、结果读取和状态反馈流程。
3. 将算法模型、RTL 硬件、板卡接口和实测指标组织成一个能够现场演示的完整作品。
4. 通过软件参考结果与 RTL/PL 输出逐样本比对，保证硬件推理结果可解释、可复现。

## 默认模型和硬件分工

- 输入：`32×32` 灰度图或同等规模的定点输入；
- 任务：5 类静态手势分类；
- 数据类型：权重和激活优先采用 INT8；
- 网络：两层轻量卷积、激活/池化和全连接分类层；
- 实施路线：先在 PC 端完成浮点模型和 INT8 量化参考，再逐步迁移关键算子到 PL。

| 模块 | 主要职责 | 当前状态 |
|---|---|---|
| 输入模块 | 接收摄像头数据或固定测试图像 | 摄像头接口待核对 |
| 预处理模块 | 灰度化、缩放、归一化和定点化 | 未开始 |
| INT8 加速器 | 定点乘加、卷积或全连接计算 | 未开始 |
| 片上存储 | 保存输入、权重和中间结果 | 先用 ROM/BRAM 验证 |
| 控制模块 | 启动任务、传递数据、读取结果 | 基础 RTL 控制已验证 |
| 输出模块 | 输出类别、状态和交互控制 | 接口待核对 |

## 当前已完成和未完成

### 已完成证据

- 已完成计数器、状态机、同步 ROM 和 ROM 控制器等基础 RTL 模块；
- 已完成基础行为仿真；
- `rom_controller` 仿真中，地址 `2` 返回 `8'h33`，地址 `3` 返回 `8'h44`；
- 已完成 Vivado 综合和 Implementation 验证；
- 正式工程根目录为 `D:\FPGA_Competition\`。

### 未完成或待核对

- 摄像头型号、输入接口、输出接口和 AX7Z020 实物资料待核对；
- XDC 引脚和时序约束尚未形成完整版本；
- INT8 黄金参考、INT8 MAC RTL 和逐样本数值比对尚未完成；
- 摄像头采集、神经网络推理、真实板卡上板和交互闭环尚未完成；
- 准确率、延迟、FPS、资源占用和连续运行稳定性尚无最终实测数据。

## 希望导师指导的问题

1. 以 `32×32` 灰度图和 5 类静态手势作为第一版目标，工作量是否适合当前竞赛周期？
2. 是否建议先用固定图像完成 INT8 推理闭环，再接入真实摄像头？
3. AX7Z020 上应优先使用 LED、串口还是 HDMI 完成第一版演示？
4. PL 侧优先实现 INT8 MAC、卷积还是全连接，哪种更适合体现 FPGA 加速价值？
5. 实验室是否可以提供 AX7Z020 板卡、下载线、摄像头和相关约束文件？

## 下一阶段计划

1. 核对板卡实物、器件型号、时钟、摄像头和输出接口。
2. 建立 Python INT8 乘加参考实现，明确位宽、舍入、截断和溢出规则。
3. 编写 INT8 MAC RTL，并与 Python 结果逐样本比对。
4. 先完成固定输入到 LED 或 UART 的最小上板闭环，再扩展摄像头和显示输出。
