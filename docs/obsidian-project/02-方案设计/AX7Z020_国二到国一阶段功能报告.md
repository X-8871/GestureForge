# 基于 AX7Z020 的低比特神经网络 FPGA 加速系统：国二到国一阶段功能报告

## 一、报告定位

本报告描述本项目在完成国二提交版之后，冲刺国一强化版时计划增加、优化和证明的功能。报告依据项目总览、总体架构、模型方案、国三—国二—国一设计路线、竞赛规则和当前项目进程整理。

这里的“国一阶段”是项目内部的强化目标，不代表官方已经公布的固定评分线。报告中的准确率、延迟、FPS、加速比和资源占用均属于待实测的内部冲刺指标，不能当作已经完成的结果。

项目当前目标平台为 ALINX AX7Z020，Vivado 工程器件配置为 `xc7z020clg400-2`。正式工程根目录为：

## 三、国二提交版应达到的基线

国二阶段的核心是形成一个可上板、可测量、可复现的端到端闭环，而不是堆叠很多外围功能。基线数据流如下：

```text
摄像头或稳定固定图像
        ↓
PL 图像预处理
        ↓
PL 侧 INT8 CNN 关键计算
        ↕
BRAM/ROM/AXI 等 PS/PL 数据通道
        ↕
PS 启动任务并读取结果
        ↓
HDMI 显示类别与状态
        ↓
LED、UART 或板卡动作
```

国二基线至少应证明：

- 输入能够稳定进入系统；
- 至少 3 类手势可以识别，目标版本逐步扩展到 5 类；
- PL 承担至少一个主要 INT8 计算模块；
- PS 能启动计算、读取结果和处理状态；
- 识别结果可以被观察并驱动板卡输出；
- 有软件基线、准确率、延迟、FPS、资源和连续运行证据。

只有国二版本稳定冻结后，才进入下面的国一强化功能。强化开发不能破坏已经可演示的国二版本。

## 五、强化功能详细说明

### F1：真实摄像头连续输入

国二阶段可以用固定图像完成稳定闭环，国一阶段要尽量恢复真实摄像头输入。系统应连续接收摄像头帧，并把每一帧按照固定格式送入预处理和推理链路。

```text
摄像头
  → 行/帧同步接收
  → 像素格式整理
  → 灰度化或缩放
  → 归一化和定点化
  → CNN 输入缓存
```

需要明确并记录摄像头型号、时钟、同步信号、像素格式、输入分辨率、有效区域和丢帧行为。当前项目的摄像头接口尚未完成实物核对，因此接口名称和时序参数不能预先编造。

### F2：可复用的 INT8 数据流加速器

国二阶段先完成一个 INT8 MAC 或单个主要算子，国一阶段将其组织成可复用的数据流结构，使 MAC、卷积、池化和全连接可以在统一的控制和缓存框架下执行。

当前默认模型为 `32×32` 灰度输入、两层轻量卷积、激活/池化和全连接分类层，共 5 类输出。国一阶段的硬件结构应支持：

- 有符号 INT8 激活和权重；
- 足够宽的乘积和累加器；
- 明确的右移、舍入、截断和饱和规则；
- 层间中间结果写入 BRAM 或其他片上存储；
- 软件黄金参考与 RTL/PL 结果逐样本比对。

硬件应优先围绕一个明确的数据流模板复用，而不是为每一层复制一套无法维护的专用逻辑。

### F3：流水线、并行 MAC 和时序优化

国一强化的主要硬件价值来自缩短关键路径和提高吞吐率。计划采用以下组合策略：

1. 将乘法、加法树、舍入和写回拆成可验证的流水级；
2. 根据 LUT、DSP、BRAM 和时序余量选择 MAC 并行度；
3. 对连续输入采用流式处理，减少等待整帧完成的空闲时间；
4. 记录流水线深度、启动间隔、总延迟和稳态吞吐率；
5. 每次优化都保留优化前版本和对比数据。

不能只提高并行度而忽略资源和时序。如果并行度增加导致时序不收敛或 BRAM 带宽不足，应回退到上一个稳定配置。

### F4：片上缓存和数据复用

卷积推理的瓶颈通常不仅是乘法次数，还包括输入、权重和中间特征图的搬运。国一阶段计划使用 BRAM/ROM、行缓存或块缓存保存高复用数据，减少对 PS 或外部存储的重复访问。

需要明确：

- 输入缓存的布局；
- 权重存储的布局；
- 中间特征图的读写方式；
- 每个计算单元需要的带宽；
- 缓存深度和 BRAM 消耗；
- 缓存优化前后的端到端延迟。

优化结果必须通过带宽统计、仿真波形或硬件计数器证明，不能仅凭结构图宣称“减少了访存”。

### F5：可配置控制能力

在不改动 RTL 的情况下，通过寄存器或参数接口切换部分运行配置，计划包括：

- 固定图像输入与摄像头输入模式；
- 5 类模型与调试用少类别模式；
- 输入帧尺寸或有效区域；
- 量化缩放、右移量或输出阈值；
- 运行一次、连续运行和停止复位；
- 调试信息开关。

可配置范围必须受控。不能为了追求“通用”而支持未经验证的任意模型；每个配置都要有合法范围、默认值、错误响应和验证样例。

### F6：PS/PL 高效数据通道

国二阶段完成最小 PS/PL 控制后，国一阶段进一步固化任务协议：

```text
PS 配置输入地址和参数
        ↓
PS 发出 start
        ↓
PL 返回 busy/ready 状态
        ↓
PL 完成推理并产生 done
        ↓
PS 读取类别、置信度和统计计数
        ↓
PS 处理显示与板卡动作
```

实际采用 AXI-Lite、AXI-Stream、BRAM 或 DMA，要以 AX7Z020 工程可用资源和接口核对结果为准。报告中应给出寄存器表、握手时序、异常状态、复位行为和一次完整任务的日志。

### F7：HDMI 结果可视化与板卡交互

国一演示界面计划同时显示：

- 摄像头原图或预处理图；
- 识别类别；
- 置信度或分类分数；
- 当前帧率；
- 单帧延迟或端到端延迟；
- PS/PL 工作状态；
- 错误码、超时和输入状态。

识别结果还应映射到可观察的板卡动作，例如 LED 状态、显示模式切换、启动/停止或复位提示。HDMI 和具体板载接口是否纳入最终版本，需要结合 AX7Z020 实物、引脚和约束文件核对。

### F8：异常输入、通信丢失和安全恢复

国一系统必须在异常情况下保持可恢复，而不是只能在理想输入下运行。计划覆盖：

- 摄像头无帧或帧同步丢失；
- 输入数据格式错误；
- PS 重复启动；
- PL 计算超时；
- PS/PL 通信握手中断；
- DMA 或缓存状态异常；
- 连续运行计数达到阈值；
- 复位后重新进入已知空闲状态。

每类异常都应有状态码、超时上限、恢复动作和证据。最低恢复路径是：停止当前任务、清理或标记无效缓存、产生错误状态、重新回到 IDLE，并允许 PS 再次启动。

### F9：精度和环境鲁棒性强化

模型计划保持 5 类静态手势，但测试条件从理想样例扩展到：

- 不同手势距离；
- 左右偏移和旋转角度；
- 不同背景；
- 明暗变化；
- 部分遮挡；
- 连续手势切换；
- 无手或未知输入。

需要分别记录浮点模型准确率、INT8 模型准确率、量化误差、FPGA 输出错误类型和混淆矩阵。对每个失败样例保存输入、软件结果、硬件结果和可能原因。

### F10：自动化验证和可复现构建

国一阶段将验证链路脚本化：

```text
固定种子生成输入
        ↓
Python 生成黄金结果
        ↓
RTL 仿真
        ↓
逐样本比对
        ↓
Vivado 综合/实现
        ↓
自动收集资源、时序和构建状态
        ↓
生成报告和版本记录
```

提交包应至少提供：

- Python 黄金参考；
- RTL 仿真脚本和测试数据；
- Vivado/Vitis 重建脚本；
- 资源和时序报告采集脚本；
- 输入、权重和标签版本信息；
- 工程版本哈希和工具版本；
- 常见失败现象与排查路径。

### F11：指标、统计和工程质量强化

国二阶段记录平均延迟和平均 FPS 后，国一阶段进一步记录：

- 平均延迟、最小值、最大值和 P99 延迟；
- 首帧延迟与稳态吞吐率；
- 摄像头采集、预处理、推理、显示各阶段耗时；
- LUT、FF、BRAM、DSP 和时序裕量；
- ARM 软件基线与 PL 加速结果；
- 连续运行时的错误数、丢帧数和恢复次数。

所有指标都必须给出输入尺寸、时钟频率、测试次数、工具版本和计算方法。没有这些条件，单独的 FPS 或“实时”描述不能作为可信结论。

### F12：可迁移 Skill 与 AI 协作记录

竞赛要求保存大模型协作记录，并将有复用价值的经验整理为 `skill/` 技能包。国一阶段计划沉淀：

- INT8 位宽、舍入、饱和和溢出验证方法；
- RTL 与 Python 黄金结果逐样本比对方法；
- AXI/BRAM/DMA 数据通道调试方法；
- Vivado 时序不收敛的最小化排查流程；
- 摄像头和 HDMI 接口核对清单；
- 构建、仿真、资源和时序自动化流程。

每个 Skill 应写明适用范围、输入、步骤、输出、已验证效果和失效边界，避免把一次项目中的特例伪装成通用规律。

## 六、国一阶段目标指标

以下是项目内部冲刺目标，不是官方分数线：

| 指标 | 国一阶段内部目标 | 证明方式 |
|---|---:|---|
| 手势类别 | 5 类 | 固定测试集和真实摄像头测试 |
| 测试集准确率 | 约 90% 或以上 | 独立测试集、混淆矩阵 |
| 量化精度损失 | 不超过 1～2 个百分点 | 浮点与 INT8 对照 |
| 端到端延迟 | 争取约 100 ms 以内 | 摄像头到显示的时间戳或硬件计数器 |
| 视觉处理帧率 | 争取 20 FPS 以上 | 连续视频统计 |
| FPGA 相对 ARM 加速比 | 至少 3 倍，争取 5 倍以上 | 相同模型、相同输入和相同统计口径 |
| 资源占用 | 尽量控制在 80%～85%以内 | Vivado 综合/实现报告 |
| 连续测试 | 30 次中至少 27 次正确 | 记录每次输入、结果和错误 |
| 稳定性 | 连续运行无死机，可从异常恢复 | 长时间运行和故障注入 |

这些指标必须在 AX7Z020 实际工程上重新测量。参考作品或其他器件的数值不能直接迁移为本项目成绩。

## 七、国二到国一的实施顺序

### 阶段 A：冻结国二版本

- 固定当前可运行的模型、输入格式和输出流程；
- 保存比特流、源码、仿真结果和指标；
- 形成国二保底演示视频；
- 记录版本哈希，禁止强化开发覆盖该版本。

### 阶段 B：建立性能基线

- 测量 ARM 软件推理延迟；
- 测量 PL 单次推理延迟和端到端延迟；
- 记录资源和时序；
- 定位最主要的瓶颈是计算、访存、通信还是显示。

### 阶段 C：优先优化一个瓶颈

- 如果瓶颈是乘加，先优化流水线和并行 MAC；
- 如果瓶颈是访存，先做片上缓存和数据复用；
- 如果瓶颈是 PS/PL 传输，先优化缓冲和 DMA/AXI 通道；
- 如果瓶颈是输入或显示，先分离采集、推理和显示节拍。

每次只改变一个主要变量，保留前后数据，避免无法判断收益来源。

### 阶段 D：加入可配置与异常恢复

- 固化寄存器和状态协议；
- 增加超时、错误码和复位路径；
- 对异常输入和通信丢失做故障注入；
- 验证恢复后还能重新完成一次正常推理。

### 阶段 E：自动化和材料完善

- 自动生成黄金结果；
- 自动运行仿真；
- 自动收集资源和时序报告；
- 更新 README、设计报告、复现说明和 AI 协作记录；
- 进行现场演示和答辩问答训练。

## 八、功能完成判据

国一强化版只有同时满足以下条件，才可在项目进程中标记为完成：

1. 真实输入到板卡输出形成稳定闭环；
2. 5 类手势识别结果与软件参考一致；
3. PL 中至少有一项实质硬件优化，并有优化前后数据；
4. 流水线、缓存、并行度和数据复用的取舍能够解释；
5. PS/PL 控制、超时、复位和异常状态均有验证；
6. 具有准确率、量化误差、平均延迟、P99 延迟、FPS、资源和时序数据；
7. 连续运行和故障恢复测试通过；
8. 他人可以按照文档重建工程并复现核心结果；
9. 完成报告、演示视频、工程包、构建脚本和 AI 协作记录。

任何一项只有计划、代码草稿或单次人工观察而没有运行证据时，都只能标为“进行中”或“待验证”。

## 九、明确不扩张的边界

国一阶段仍然围绕一个主任务、一个核心模型和一个稳定闭环，不扩展以下方向：

- 同时开发多个 CNN 或多个应用场景；
- 在基础版本中加入大型目标检测网络；
- 把大语言模型、语音和机器人系统并入当前作品；
- 在没有测量数据时宣称实时、低功耗或显著加速；
- 为了增加功能而破坏已经冻结的国二版本；
- 在板卡型号、引脚、摄像头接口未核对前编造硬件结论。

如果真实摄像头链路仍然阻塞，先用固定图像完成加速器、PS/PL 和指标验证；摄像头恢复后再进行端到端强化测试。

## 十、当前阻塞和前置条件

在开始国一强化前，需要先完成：

- AX7Z020 实物、器件型号和供电/下载链路核对；
- 摄像头型号、输入接口和时序核对；
- HDMI、LED、UART 等输出接口选择；
- 完整 XDC 引脚和时序约束；
- 国二版本的固定工程、模型和测试集；
- ARM 软件基线和第一版 PL 指标；
- INT8 MAC、卷积或全连接核心的 RTL 逐样本验证。

这些前置条件没有证据时，国一功能只能作为设计目标，不能写成已经实现。

## 十一、结论

本项目从国二到国一的升级重点，是把“能运行的低比特视觉识别闭环”强化为“可测量、可配置、可恢复、可复现的硬件加速系统”。核心升级不在于无边界增加功能，而在于证明 PL 的流水线、并行 MAC、片上数据复用和软硬件协同确实带来了可重复的性能和资源收益。

最终作品应让现场人员能够看到手势输入、识别结果和板卡响应，也让评审人员能够通过源码、波形、报告、脚本和原始数据复核每一个关键结论。
