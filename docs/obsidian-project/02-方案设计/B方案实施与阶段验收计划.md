# B方案实施与阶段验收计划

## 当前阶段体系

用户已批准用 **0、1、2A、2B、3、4、5、6、7** 替代旧 S0—S8。本文为当前唯一阶段与指标维护正文；任务关口 G0—G5 不变，阶段编号不表示完成状态。日期按 UTC+8。

总体选择见 [[总控#当前用户决策（2026-09-10）]]：实时摄像头、PL预处理/卷积/池化/INT8主要计算、PS调度/配置/读取结果/显示与交互控制。HDMI方向待核实；五类、32×32及两层网络暂定。

| 阶段 | 核心输出 | 前置 |
|---|---|---|
| 0 硬件与环境 | 实物/资料对应、基础下载和LED/UART验证 | 无 |
| 1 PC模型与数值规格 | 数据集、浮点/INT8模型、固定预处理权重、逐层黄金结果 | 环境及输入方案明确 |
| 2A PL推理仿真 | 算子和整网RTL逐值验证 | 阶段1数值规格与模型 |
| 2B 固定输入上板 | ROM/BRAM→PL→PS→UART，与PC自动比对 | 阶段0上板条件、2A |
| 3 摄像头视频链路 | 摄像头→已核实输入→FPGA→HDMI原始画面 | 阶段0视频接口核实 |

阶段3可在依赖具备时提前穿插，不要求同时操作板卡。优化、异常设计与证据记录贯穿各阶段，不等到阶段7才设计。

## 阶段0：硬件与环境核对

核对板卡/PCB/芯片、DDR资源、手册/原理图、供电、工具和器件支持、下载链路、摄像头/显示能力。尤其核对HDMI端口数量、方向和接收/发送电路，不根据接口外观推断。

完成一次重新上电、下载/启动及最小LED/UART自检。使用DDR则在明确地址范围做读写比对，记录模式、次数及零错误。每个后续接口有引脚、电平、时钟与资料页码；冻结模型/视频输入及测量口径的关键前置，不留阻断性未知。

证据：实物清单、来源/引脚表、工具和器件查询、启动自检、适用DDR测试、待办关闭表。S0-T01/S0-T02保留为已有任务编号：前者为环境资料子任务，后者为纯软件预检；两者通过不代表本阶段完整通过。

## 阶段1：PC模型与数值规格

数据集→浮点模型→INT8模型→固定预处理和权重→Python逐层黄金结果。划分训练/验证/测试，避免同一人员或会话数据泄漏；保留数据、模型、参数版本和来源。

冻结尺寸、像素范围、灰度/缩放/归一化、量化scale和zero-point、舍入/饱和、padding、池化与各层布局。第一版采用固定位置ROI；自动手部定位另列扩展。训练与实时预处理必须一致。

沿用强化目标：建议独立测试不少于1000例、五类各200；INT8准确率≥90%，相对浮点下降≤2个百分点。保留逐样本预测、混淆矩阵、Macro-F1和人群/会话组成。这些为项目工程建议，相关任务G0冻结后执行，不是官方获奖保证。

证据：数据划分、训练配置、模型权重、整数规格、预处理样例、逐层黄金输出、精度报告。精度未达标可调试硬件，但阶段验收仍保留未通过。

## 阶段2A：PL推理仿真

先单算子，再完整RTL网络。覆盖符号与极值、舍入中点、饱和、padding、窗口边界、复位、握手停顿和异常。PS/PL控制接口在任务G0定义周期行为。

沿用建议：每算子至少1000组定向/随机组合，整网至少100个覆盖五类的输入逐层逐值一致，不匹配为零。综合无错误及非预期锁存器，资源可容纳，时钟风险有报告；只有MAC正确不能通过本阶段。

证据：参考输入、RTL/TB、种子、逐层比较、协议测试、波形及综合资源报告。

## 阶段2B：固定输入上板

ROM/BRAM样例→PL推理→PS读取→UART输出→PC自动比对。ROM/BRAM容量由资源决定；大量样例可经PS/UART装载，不改变固定输入验证性质。

至少100个覆盖五类样本的全部整数分数与黄金结果一致，不只比较argmax；至少1000次连续任务无丢失、重复或死锁。空闲/忙时启动、非法参数、复位与恢复行为符合约定。

实际整网顶层及必要时钟/IO约束完整，布局后setup/hold满足，TNS/THS为零，例外有依据。证据绑定源码、模型、参数、位流和板卡；不以小模块报告代替整网。

## 阶段3：摄像头视频链路

优先目标：HDMI摄像头→已确认的HDMI输入→FPGA接收→HDMI输出→显示器。若不支持，记录差距并由用户确认替代视频接口，不改成网络图片主线。

先验证原始画面：分辨率、像素格式、帧/行边界、帧率和持续运行。至少30分钟无输入/显示死锁，像素计数与配置对应；测试图案/运动场景检查花屏、撕裂与停帧。容许丢帧策略和计数口径在任务G0明确。

证据：接口来源、配置、帧/像素计数、连续日志和视频。本阶段不要求CNN接入。

## 阶段4：摄像头推理

摄像头→固定ROI/裁剪/缩放/灰度化/量化→PL CNN→UART。每条结果至少包含frame_id、类别、各类整数分数、推理耗时和状态。

保存实际送入CNN的图像，建议至少100帧与PC相同预处理逐值比较；随后比较整数推理结果。区分模型误分类、预处理不一致与硬件数值错误。

至少50次预定义交互观察、每类至少10次，完整记录成功与失败；沿用基线成功率建议≥80%，不替代阶段1独立精度。连续30分钟无需人工复位，至少1000次有效推理形成基线统计。输入帧与结果对应，推理耗时与端到端延迟分别定义。

## 阶段5：HDMI结果显示

原始画面＋识别类别、分数/置信度、FPS、延迟。logits/整数分数显示为“分数”；只有概率转换及解释明确后才称置信度，不把数值大等同可靠概率。

显示结果关联对应帧号；若采用延迟显示或最新结果叠加，明确画面语义与结果年龄，不能伪称同帧。FPS分别说明采集、推理或显示；预热、丢帧、超时不隐藏。

任务G0确定布局、测量起止事件和允许延迟。建议至少100帧检查结果对应、连续30分钟检查无显示/采集/推理死锁，并回归阶段4数值链路。截图/连续视频和原始统计均留证。

## 阶段6：交互控制

稳定手势判定→HDMI切图、界面或显示状态。冻结稳定判定窗口、保持时是否只触发一次、冷却、重新触发条件、无手/未知输入与恢复行为。

测试短暂抖动、持续保持、手势切换、手离开和未知场景。沿用强化建议：已知手势有效动作成功率≥90%；至少200个独立未知输入误接受率≤5%；无有效手势30分钟误动作≤1次。各条件样本数及阈值在任务G0固定，不能只挑成功视频。

证据：状态机规格、输入/事件/动作日志、失败案例、连续视频。交互通过不代替阶段7最终性能与可靠性验收。

## 阶段7：系统验收与交付

接收原旧阶段的性能优化、鲁棒性和复现要求，不能因重编号删掉：

- 优化前后同模型/输入/精度，零数值不匹配；至少3次独立运行收益方向一致。改变时钟与架构的影响分开报告。
- 强化目标：新结果吞吐≥20 FPS；约定输入事件到显示/动作可见的端到端P99≤100 ms；包含PS/PL必要传输的整网任务相对ARM基线≥3倍，5倍为争取项。
- 每正式性能配置至少10000次有效任务，预热、超时、丢帧单列，不筛快样本。
- LUT/FF/BRAM/DSP分别报告，初始目标各≤85%；WNS/WHS非负、TNS/THS为零。超限需显式规格变更。
- 连续运行至少1小时，无死机、持续泄漏或未解释错配。每种已定义故障注入至少20次，均进入预期状态并恢复新任务；不默认允许物理热插拔。
- 配置覆盖正常/边界/非法值；宣称运行时切换时位流哈希不变。恢复时间沿用建议：设定超时后500 ms内进入已知状态，外部输入恢复后2 s内恢复任务，按实际硬件启动时间在G0冻结。
- 保持阶段1精度、阶段6未知输入/交互要求；分环境报告样本和失败。
- 从干净工程副本或环境按文档重建并上板复现。交付源码、配置、权重、约束、构建脚本、产物清单/校验值、完整证据、演示与故障预案。
- AI协作记录保存错误—修复—验证依据；竞赛如要求技能包则按规则准备并验证复用，本地工作流Skill不是未经评估的前置要求。
