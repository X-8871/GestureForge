# 系统设计

本文件统一维护当前架构、接口和模型。阶段与验收见 [[02-方案设计/B方案实施与阶段验收计划]]，数值单元规格见 [[02-方案设计/INT8乘加接口说明]]。HDMI链路仍待实物核实，暂定模型参数不代表已验收。

## 总体架构

当前选择强化方案，决策依据 [[总控#当前用户决策（2026-09-10）]]。

### 主链路

```text
摄像头实时视频 → FPGA 接收 → PL 图像预处理
→ PL 卷积/激活/池化及 INT8 主要计算 → 识别结果
→ PS 读取结果、显示与交互控制
```

### PS/PL 分工

| 区域 | 已确定职责 | 尚需设计 |
|---|---|---|
| PL | 图像预处理、卷积、池化、INT8主要计算 | 视频接收格式、缓冲、流水线、并行度及周期接口 |
| PS | 任务调度、参数配置、读取结果、显示和交互控制 | 控制寄存器、传输、超时和具体交互方式 |

视频像素搬运、HDMI 时序和叠加模块的位置尚未冻结，不把 PS 显示控制等同于 PS 承担完整视频数据通路。

### 倾向视频链路（待硬件核实）

```text
HDMI 摄像头 → AX7Z020 HDMI 输入 → FPGA 处理
→ HDMI 输出 → 显示器
```

该链路是偏好，不是已验证能力。两个端口是否存在、输入/输出方向、接收/发送器件及摄像头是否输出 HDMI 均需依据实物和资料确认，见 [[02-方案设计/系统设计]]。

### 模型与交互

模型暂定 32×32 灰度、INT8、两层轻量卷积＋激活/池化＋全连接，五类静态手势。参数细节见 [[02-方案设计/系统设计]]。必须实现板卡交互，HDMI、LED、UART、切图/显示模式为候选，不要求全部实现。

### 开发边界

固定图片和 Python 黄金数据继续用于调试与阶段性验证；网络图片和 ESP32 下载图片不是当前主线。最终需要摄像头实时闭环。工程阶段见 [[02-方案设计/B方案实施与阶段验收计划]]。

## 接口设计

依据 [[总控#当前用户决策（2026-09-10）]]，主输入为摄像头实时视频；HDMI 路线为偏好，尚未完成硬件核实。

### 接口核对表

| 接口 | 当前选择/倾向 | 必须确认后才冻结 |
|---|---|---|
| 摄像头到板卡 | 倾向 HDMI 摄像头接 HDMI 输入 | 摄像头型号与 HDMI 输出能力；板卡/PCB版本、端口数量及方向、接收器件、视频格式/时钟、电气条件、原理图页码 |
| 板卡到显示器 | 倾向 HDMI 输出 | 发送器件、端口方向、显示器支持格式、约束和时钟来源 |
| PL 处理 | 预处理、卷积、池化及 INT8主要计算已确定 | 像素格式、缩放/灰度规则、帧号、缓存、握手、复位和数值格式 |
| PS 到 PL | 调度及参数配置已确定 | AXI-Lite/Stream/BRAM 等具体接口、寄存器和传输方式未定 |
| PL 到 PS | 读取识别结果 | 类别编码、整数分数/置信度定义、位宽、有效标志、任务号 |
| 交互控制 | PS 控制，形式未定 | HDMI结果显示、LED、UART、切图/显示模式的最终组合 |

### 冻结条件

先核对实物、手册、原理图和端口标识，再定义时钟、复位、引脚与 IOSTANDARD。不得因为有两个外形相同的接口就认定一进一出。无法支持 HDMI 目标链路时记录差距并提交方案选择，不自行切换成网络图片主线。

S0-T01 负责启动核查；具体接线、驱动、XDC 与上板测试另由任务卡约定。图像数据通路与 PS 显示控制分别设计。

## 模型方案

### 当前暂定方案（用户决策 2026-09-10）

- 输入：32×32 灰度图，来源为摄像头实时视频经 PL 预处理。
- 任务：5 类静态手势识别，暂定握拳、手掌、数字一、数字二、数字三。
- 权重与激活：优先采用 INT8 表示。
- 网络：两层轻量卷积加激活/池化，再接全连接分类层。
- 部署：先在 PC 端完成浮点基线和量化参考，再逐步在 PL 实现图像预处理、卷积、池化和 INT8 主要计算。

### 选择理由

该模型规模足够小，便于在 AX7Z020 上完成端到端验证，同时能够展示低比特计算、乘加并行和硬件资源约束之间的取舍。模型最终规模以实际准确率、资源和时延测量为准。
