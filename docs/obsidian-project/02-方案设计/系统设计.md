- 已确定：PL 承担预处理和 INT8 主要计算，PS 承担调度、配置、结果解析与交互。
- 阶段2A已冻结 tiny416、INT8、8×8空间tile和8路输出通道并行、双检测头及PS解码/NMS；模型与逻辑接口以 [[04-提交材料/阶段验收/S2A-T01_模型交付规格与G0接口冻结]] 为准。阶段2B的物理DDR分配、PS/PL传输、时钟及异常恢复尚待冻结；检测帧率和端到端延迟仍按阶段计划收集证据后确定。
- 不再采用原 32×32 灰度、两层卷积加全连接分类方案；旧版可在 Git 历史查看。固定 ROI 分类不能代替目标定位。
- 完整 YOLOv4 仅作 PC 对照，不同时实施两套 PL 网络；改变上板候选需记录精度、资源证据并由 Wong 确认。
- 当前为方案，不代表训练、量化、综合、上板或性能已经通过。四项 MAC 教学结果不等于检测网络已支持。

## 主链路与分工

```text
摄像头视频 → PL 接收、缩放/补边/颜色处理、量化
→ DDR / BRAM 缓冲 → PL 分块 INT8 网络计算
→ PS 检测头解码、阈值筛选、NMS 去重
→ 原图坐标检测框、类别、分数、帧号
→ HDMI 叠加显示 → 稳定手势交互
```

| 区域 | 计划职责 | 必须实现和验证的边界 |
|---|---|---|
| PL | 视频预处理、卷积及冻结网络所需激活/池化/路由/拼接/上采样、数据搬运、视频叠加 | 按实际配置枚举全部算子；逐层位宽、布局、时序和资源验证 |
| PS | 参数调度、检测头解码、阈值筛选、NMS、结果管理、交互状态机 | 候选框数量上限、超时、缓存一致性、坐标还原、结果年龄 |
| DDR | 存放权重、特征图和视频帧缓存 | 核实板载容量、地址范围、峰值活跃存储和实测带宽；避免相互覆盖 |
| BRAM | 分块权重、局部特征图、行缓存和队列 | 计算单元复用；不能假定整网权重与特征图全部驻留片上 |
| PC | 数据标注、训练、量化、导出、黄金参考及自动比较 | 保留数据划分、配置/权重哈希、逐层输出和失败样例 |

BN 折叠、激活近似及定点化须有独立比较依据。最终算子列表以固定 cfg/代码版本为准，不能仅凭“支持卷积”宣称整网支持。

## 接口设计

倾向链路为 HDMI 摄像头 → AX7Z020 HDMI 输入 → FPGA → HDMI 输出 → 显示器。板卡与视频资料已完成初步核对；端口方向、接收/发送器件和摄像头输出能力仍需阶段3用实际链路验证，不能从两个接口外观推断一进一出。

| 接口 | 必须冻结的字段与行为 |
|---|---|
| 视频输入/输出 | 板卡/PCB/芯片、器件、资料页码、引脚/电平、格式、分辨率、时钟、帧/行边界 |
| 预处理 | RGB/BGR 顺序、缩放插值及整数规则、等比例补边值和位置、归一化、量化、数据布局 |
| PS/PL 控制 | 地址映射、传输接口、start/busy/done/error、复位/超时、缓冲所有权、DMA 完成与缓存维护 |
| 网络输出 | 每个检测头尺寸/布局/位宽/scale、输出地址和长度、frame_id、错误状态；不是仅输出 argmax |
| 后处理结果 | frame_id、检测数量、每框 class_id/score/x1/y1/x2/y2、坐标单位与范围、采集/推理/结果时间、状态 |
| 结果与显示 | 网络坐标到原图坐标的逆映射、边界裁切、延迟显示或结果年龄、过期丢弃、叠加缓冲策略 |
| 交互 | 多框目标选择规则、连续稳定时间、冷却、重复触发、无框与目标丢失处理 |

类别编码、score 定义、anchors、阈值、NMS IoU、类别内/跨类别抑制、最大候选/输出数以及同分排序在阶段1冻结。score 不宣称为经过校准的可靠概率。无检测必须返回数量0和有效帧号，不能重复沿用旧类别。

### 阶段2B物理异常恢复原则（Wong已批准采用）

候选编号：`S2B-AXI-RECOVERY-20261008`。2A冻结规格第65、71行要求第N沿超时/复位归还PS所有权，撤销未握手请求且无后续写副作用。当前控制器第244–251行立即清busy/owner，memory master取消时清pending。若物理adapter等B响应才返回逻辑mem_ready，已经被DDR通路接受的AW/W仍可能在该取消之后完成写入。直接丢掉请求或只复位PL不能满足原保证；错误B响应也不能独立证明该写没有副作用。

采用记录：2026-10-09（UTC+8），Wong在当前阶段2B总控会话回复「可以采用这个方案」，批准采用候选 `S2B-AXI-RECOVERY-20261008` 的「停止计算→排空→归还」恢复原则。原则版本为 `s2b-axi-recovery-principles/1.0.0`；本次冻结恢复原则，完整物理PS/PL接口仍须后续设计与验证。

已批准采用的恢复原则如下：

| 事件/状态 | 已批准采用的物理恢复原则 |
|---|---|
| timeout第N沿或busy期间soft_reset | 保留2A内部事件时点，立即停止新计算及新事务；进入物理RECOVERING，旧检测头无效 |
| 已发AXI事务 | adapter保留事务状态，完成已声明或已接受事务所需的通道并消费B/R响应；旧epoch响应只消费并丢弃结果，不将旧响应送给新任务 |
| PS观察与buffer访问 | 外层门禁发布物理状态/归还条件并拦截RECOVERING期间的新start；门禁只约束控制入口，不能阻止CPU绕过驱动直接访问DDR。PS驱动等安全归还后才访问或重用buffer；内部CSR的owner位单独读到0不能证明DDR可访问 |
| 安全归还 | 全部旧事务及通路可见性条件满足后发布物理终态并归还buffer，之后才接受物理终态确认及合法start；非Bufferable属性及PS HP端口可见性须另有依据并验证 |
| ACK与soft_reset | 2A内部ACK只清逻辑完成/错误状态，不代表物理终态确认；RECOVERING及尚未排空的不可恢复状态中，内部ACK或再次soft_reset均不能解除外层隔离、归还buffer或允许新start。物理终态确认的寄存器编码在后续设计中冻结 |
| 事务始终未结束 | 保持隔离并报告不可恢复状态，不强行清outstanding或归还buffer；系统复位/重新上电属于单独恢复流程 |
| 冷启动硬复位 | 启动前统一初始化PS/互连/adapter；运行中只复位PL不能替代已发事务的排空 |

已批准采用的原则改变2B对软件可见的所有权归还和恢复条件：旧写允许在RECOVERING期间结束，软件安全重用必须等排空；不能继续声称物理层严格即时取消。恢复完成仅表示安全归还，不把超时或异常失败的任务改判成功。2A冻结源码、原周期契约、验收记录和历史候选证据保留。

后续仍须设计并验证物理MMIO寄存器及ACK编码、门禁边界、PS/PL地址映射、HP通路非Bufferable属性与读写可见性、cache一致性、错误副作用、排空失败诊断、数值期限及回归用例。物理实现和实板验收尚未执行，阶段2B G0/G3/G4/G5尚未通过；恢复原则的采用不代表上述物理接口或验收已冻结通过。

依据：[AMD UG585 PS-PL AXI接口](https://docs.amd.com/r/en-US/ug585-zynq-7000-SoC-TRM/PS-PL-AXI-Interfaces)、[AMD PG293恢复流程](https://docs.amd.com/r/en-US/pg293-axi-firewall/Recovery)、[AMD PG293事务排空与安全复位](https://docs.amd.com/r/en-US/pg293-axi-firewall/MI-Side-Mode-Block-Condition)。PG293用于说明AXI事务和复位边界；本次原则采用未选择或验证AXI Firewall IP。PS-only UART/DDR离线平台可独立推进。

### 阶段2B具体物理接口候选（未冻结）

2026-10-09新增候选 `S2B-PHYSICAL-20261009`，现修订为 `s2b-physical-candidate/0.1.1`，详见 [PS/PL物理接口候选](s2b_physical_interface_candidate.md)。保留2A内部CSR与字节连续INT8的32-bit单word/strobe逻辑接口，提出GP0控制、64-bit HP0原生AXI3窄传输、逻辑地址加`0x10000000`、外层物理所有权/epoch/终态ACK、裸机专属arena/cache维护与排空隔离的具体编码。R1修订明确既有CSR端口常驻监视/停止确认、AXI3合法早B保存至AW/W/B完整闭合、同沿首错优先和取消不交付、GP0 single beat输入前提、非exclusive EXOKAY隔离及资料读取范围。输入/权重/特征/检测头布局不作四倍展开；PL master承担自主DDR搬运，正式DMA/100样本/1000连续任务验收要求保留。旧`0.1.0`与r01原证据/快照保留，修订不代表R2已通过。

本轮是只读源码与尺寸分析、候选文档，不含RTL/平台/软件实现或测试及实物结果。恢复原则仍以已批准的`1.0.0`为准；候选编码、AXI属性完整路径、cache软件、集成资源/时序与实板跨master可见性须后续审查验证，完整2B物理接口、G0/G3/G4/G5未冻结通过。当前修订与静态绑定入口：`report/evidence/S2B-T07/physical_contract_20261009_r02/`；既有尺寸结果按原SHA复用，r01不覆盖重跑。

## 模型和数据验证

先在相同数据划分上比较完整 YOLOv4 与 tiny；tiny 优先比较 320 和 416。冻结配置、仓库版本、输入尺寸、训练设置和随机种子，禁止把不同尺寸或数据集的数字直接当作模型差异。

数据逐个标注手势框和五类标签；约定框是否覆盖整只手、遮挡/截断处理和忽略规则。加入无手、非目标手势、复杂背景、多手、距离/光照变化样本。按人员和拍摄会话隔离训练/验证/测试，相邻视频帧不得跨集合泄漏。记录各类框数、图片数、人员/会话数和目标像素大小分布。

报告 mAP@0.5、mAP@0.5:0.95、每类精确率/召回率、无手误检和量化前后差异；阈值在验证集确定，测试集只做最终评价。评估脚本定义 IoU 匹配、重复框、忽略标注和最大检测数。小手和数字一/二/三的失败样例单列。

## 选型参考依据（2026-09-11，非本项目实测）

官方原始模型在416输入下计算量：完整约60.1 BFlops、tiny约6.9 BFlops；浮点权重文件约245 MB与23.1 MB。相同输入计算量约差8.7倍。文件大小除四所得约61 MB与5.8 MB只作INT8权重粗估，不包含特征图、额外参数与缓存。五类定制后须重新统计。[Darknet 官方模型资料](https://github.com/AlexeyAB/darknet)

Z-7020 的220个DSP与约4.9 Mb片上块RAM无法让上述整网全部驻留BRAM；需结合板载DDR设计复用。完整模型可以探索低吞吐分块执行，不能仅因片上放不下断言绝对无法运行，也不能承诺实时。[AMD Zynq-7000 产品资料](https://www.amd.com/en/products/adaptive-socs-and-fpgas/soc/zynq-7000.html)

算子来源：[完整配置](https://raw.githubusercontent.com/AlexeyAB/darknet/master/cfg/yolov4.cfg)、[tiny配置](https://raw.githubusercontent.com/AlexeyAB/darknet/master/cfg/yolov4-tiny.cfg)。实施时归档实际使用版本与哈希，不仅引用可变化的master链接。
