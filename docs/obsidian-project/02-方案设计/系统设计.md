# 系统设计

本文唯一维护当前架构、模型与接口。阶段和指标见 [[02-方案设计/B方案实施与阶段验收计划]]；实际状态见 [[项目进程]]。阶段1文档与交接记录见 [[04-提交材料/阶段验收/阶段1_PC模型与数值规格收尾记录]]。

## 已批准范围与待冻结项

2026-09-11 用户批准先按以下路线推进可行性验证：YOLOv4-tiny 为优先上板候选，完整 YOLOv4 为 PC 精度对照。两者属于卷积神经网络；本次从图像分类改为目标检测。

- 已确定：摄像头实时视频；握拳、手掌、数字一、数字二、数字三共五类；输出检测框、类别和分数，并形成板卡交互。
- 已确定：PL 承担预处理和 INT8 主要计算，PS 承担调度、配置、结果解析与交互。
- 待验证后冻结：最终模型配置、320×320 或 416×416 彩色输入、量化规格、计算并行度、DDR 分配、检测帧率和端到端延迟。
- 不再采用原 32×32 灰度、两层卷积加全连接分类方案；旧版可在 Git 历史查看。固定 ROI 分类不能代替目标定位。
- 完整 YOLOv4 仅作 PC 对照，不同时实施两套 PL 网络；改变上板候选需记录精度、资源证据并由 Wong 确认。
- 当前为方案，不代表训练、量化、综合、上板或性能已经通过。四项 MAC 教学结果不等于检测网络已支持。

## 当前硬件基线（2026-09-13）

- 开发板型号为 AX7020，板载 FPGA 实物标记为 `XA7Z020`、`CLG400`。
- JTAG 已连接并读取 `IDCODE=0x23727093`；工具显示 `xc7z020_1` 仅作为 Zynq-7020 类器件识别，不作为 XC 系列或 `-2` 速度等级证明。
- XA 目标工程已完成验证，UART 线已连接。UART 功能输出属于阶段2验收，HDMI 摄像头输入和 DDR 运行测试仍按后续阶段执行。
- 精确速度后缀尚无单颗芯片原厂证明，硬件时序按 `-1` 基线设计和记录。

## 主链路与分工

```text
摄像头视频 → PL 接收、缩放/补边/颜色处理、量化
→ DDR / BRAM 缓冲 → PL 分块 INT8 网络计算
→ PS 检测头解码、阈值筛选、NMS 去重
→ 原图坐标检测框、类别、分数、帧号
→ HDMI 叠加显示 → 稳定手势交互
```

| 区域 | 计划职责 | 必须实现和验证的边界 |
|---|---|---|
| PL | 视频预处理、卷积及冻结网络所需激活/池化/路由/拼接/上采样、数据搬运、视频叠加 | 按实际配置枚举全部算子；逐层位宽、布局、时序和资源验证 |
| PS | 参数调度、检测头解码、阈值筛选、NMS、结果管理、交互状态机 | 候选框数量上限、超时、缓存一致性、坐标还原、结果年龄 |
| DDR | 存放权重、特征图和视频帧缓存 | 核实板载容量、地址范围、峰值活跃存储和实测带宽；避免相互覆盖 |
| BRAM | 分块权重、局部特征图、行缓存和队列 | 计算单元复用；不能假定整网权重与特征图全部驻留片上 |
| PC | 数据标注、训练、量化、导出、黄金参考及自动比较 | 保留数据划分、配置/权重哈希、逐层输出和失败样例 |

BN 折叠、激活近似及定点化须有独立比较依据。最终算子列表以固定 cfg/代码版本为准，不能仅凭“支持卷积”宣称整网支持。

## 接口设计

倾向链路为 HDMI 摄像头 → AX7Z020 HDMI 输入 → FPGA → HDMI 输出 → 显示器。板卡与视频资料已完成初步核对；端口方向、接收/发送器件和摄像头输出能力仍需阶段3用实际链路验证，不能从两个接口外观推断一进一出。

| 接口 | 必须冻结的字段与行为 |
|---|---|
| 视频输入/输出 | 板卡/PCB/芯片、器件、资料页码、引脚/电平、格式、分辨率、时钟、帧/行边界 |
| 预处理 | RGB/BGR 顺序、缩放插值及整数规则、等比例补边值和位置、归一化、量化、数据布局 |
| PS/PL 控制 | 地址映射、传输接口、start/busy/done/error、复位/超时、缓冲所有权、DMA 完成与缓存维护 |
| 网络输出 | 每个检测头尺寸/布局/位宽/scale、输出地址和长度、frame_id、错误状态；不是仅输出 argmax |
| 后处理结果 | frame_id、检测数量、每框 class_id/score/x1/y1/x2/y2、坐标单位与范围、采集/推理/结果时间、状态 |
| 结果与显示 | 网络坐标到原图坐标的逆映射、边界裁切、延迟显示或结果年龄、过期丢弃、叠加缓冲策略 |
| 交互 | 多框目标选择规则、连续稳定时间、冷却、重复触发、无框与目标丢失处理 |

类别编码、score 定义、anchors、阈值、NMS IoU、类别内/跨类别抑制、最大候选/输出数以及同分排序在阶段1冻结。score 不宣称为经过校准的可靠概率。无检测必须返回数量0和有效帧号，不能重复沿用旧类别。

## 模型和数据验证

先在相同数据划分上比较完整 YOLOv4 与 tiny；tiny 优先比较 320 和 416。冻结配置、仓库版本、输入尺寸、训练设置和随机种子，禁止把不同尺寸或数据集的数字直接当作模型差异。

数据逐个标注手势框和五类标签；约定框是否覆盖整只手、遮挡/截断处理和忽略规则。加入无手、非目标手势、复杂背景、多手、距离/光照变化样本。按人员和拍摄会话隔离训练/验证/测试，相邻视频帧不得跨集合泄漏。记录各类框数、图片数、人员/会话数和目标像素大小分布。

报告 mAP@0.5、mAP@0.5:0.95、每类精确率/召回率、无手误检和量化前后差异；阈值在验证集确定，测试集只做最终评价。评估脚本定义 IoU 匹配、重复框、忽略标注和最大检测数。小手和数字一/二/三的失败样例单列。

## 可行性证据与冻结关口

| 关口 | 输出证据 | 退出条件 |
|---|---|---|
| 精度关 | 同划分训练配置、两模型指标、tiny 两尺寸比较、错误案例 | 明确候选的精度/目标尺度取舍；达不到拟定门槛则继续改数据/模型 |
| 数值关 | 完整算子清单、INT8 规则、逐层参考、量化损失、解码/NMS 测例 | 无未定义算子或数值行为；量化精度达到已批准阈值 |
| 资源关 | 代表算子综合/周期、DDR 吞吐、峰值存储、整网计算与传输预算 | 无已知容量/时序阻断；预算覆盖后处理和视频竞争，才能冻结性能目标 |

资源关可穿插阶段0/1进行独立原型验证，不等于阶段2A整网仿真或2B上板通过。各关口的实际通过情况只写入项目进程及任务记录。

## 选型参考依据（2026-09-11，非本项目实测）

官方原始模型在416输入下计算量：完整约60.1 BFlops、tiny约6.9 BFlops；浮点权重文件约245 MB与23.1 MB。相同输入计算量约差8.7倍。文件大小除四所得约61 MB与5.8 MB只作INT8权重粗估，不包含特征图、额外参数与缓存。五类定制后须重新统计。[Darknet 官方模型资料](https://github.com/AlexeyAB/darknet)

Z-7020 的220个DSP与约4.9 Mb片上块RAM无法让上述整网全部驻留BRAM；需结合板载DDR设计复用。完整模型可以探索低吞吐分块执行，不能仅因片上放不下断言绝对无法运行，也不能承诺实时。[AMD Zynq-7000 产品资料](https://www.amd.com/en/products/adaptive-socs-and-fpgas/soc/zynq-7000.html)

算子来源：[完整配置](https://raw.githubusercontent.com/AlexeyAB/darknet/master/cfg/yolov4.cfg)、[tiny配置](https://raw.githubusercontent.com/AlexeyAB/darknet/master/cfg/yolov4-tiny.cfg)。实施时归档实际使用版本与哈希，不仅引用可变化的master链接。
