## 1. 板级事实（来自厂商原件，`D:\FPGA\AX7Z020`，只读）

| 项 | 事实 | 来源 |
|---|---|---|
| HDMI 输出 | 板上**有 HDMI TX**（TMDS 差分对 + 使能） | `course_s1/02_hdmi_out_test/hdmi_out_test.srcs/constrs_1/new/hdmi_out_test.xdc` |
| TMDS 时钟 | `TMDS_clk_p = U13`、`TMDS_clk_n` 同对，`IOSTANDARD TMDS_33` | 同上 |
| TMDS 数据 | `TMDS_data_p[0]=W14`、`[1]=Y18`、`[2]=Y16` | 同上 |
| HDMI 使能 | `hdmi_oen = V16`（LVCMOS33，低有效/按参考设计驱动） | 同上 |
| 系统时钟 | `sys_clk = U18`，LVCMOS33，**50 MHz**（period 20 ns） | 同上 |
| 参考 IP | `rgb2dvi_v1_3`（RGB→TMDS，含 5× 串行时钟） | `repo/ip/rgb2dvi_v1_3` |
| 参考像素时钟 | `clk_wiz 5.4`，**输入 100 MHz → 74.25 MHz 像素 + 371.25 MHz 串行**（分数分频 `MMCM_CLKFBOUT_MULT_F=59.375`） | `video_clock.xci` MODELPARAM |

**结论**：像素时钟**可从 100 MHz 参考经分数 MMCM 生成 74.25 MHz**（厂商参考已验证该参数组合），因此 **FCLK1 取 100 MHz** 即可，不需要外部 27 MHz 晶振，也不需要 axi_dynclk 动态重配（若后续要动态切分辨率再引入）。

## 2. 范围（阶段6 = 显示链）

| 编号 | 交付 | 说明 |
|---|---|---|
| S5D-01 | 像素时钟 | `clk_wiz`（分数 MMCM）：100 MHz → 74.25 MHz（像素）+ 371.25 MHz（串行，供 rgb2dvi） |
| S5D-02 | 时序发生 | `v_tc`（VTC）产生 1280×720p60 时序（HS/VS/DE），AXI-Lite 可配 |
| S5D-03 | 帧缓存读取 | `axi_vdma`（读通道，MM2S）从 DDR 取显示帧（RGB888/RGB565），AXI4-Stream 输出 |
| S5D-04 | 叠加 | `v_tc` + AXI4-Stream 混合（检测框/文字叠加），可用 `axis_subset_converter` + 简单 mixer 或用 `v_mix`（若 IP 可用） |
| S5D-05 | 输出 | `rgb2dvi`（或 `v_axi4s_vid_out` + rgb2dvi）→ TMDS 差分 → HDMI |
| S5D-06 | 数据面端口 | VDMA 用 **S_AXI_HP2（64-bit）**，与 2B（HP0）、preproc+DMA（HP1）**物理隔离** |
| S5D-07 | 地址 | VTC AXI-Lite、VDMA 寄存器；**注意与现有 DMA `0x43C20000` 冲突**（见 §3） |
| S5D-08 | 冒烟验收 | 棋盘/彩条 + 检测框叠加上屏；1080p 不要求，先 720p60 |

**非目标**：摄像头采集（本阶段用 DDR 中已有帧/生成图）；硬件加速缩放；多分辨率动态切换（可选后续）。

## 3. 地址与时钟（关键冲突修正）

| 资源 | 原草案（阶段5） | **阶段6 定稿建议** | 理由 |
|---|---|---|---|
| VTC | `0x43C20000` | **`0x43C30000`**（64K） | `0x43C20000` 已被 **AXI DMA** 占用（P2d 实测），不能复用 |
| clk_wiz | `0x43C30000`（若用 axi_dynclk） | **无地址**（clk_wiz 无 AXI-Lite，纯 MMCM） | 降低复杂度；动态重配需求出现再换 `axi_dynclk` 并另分配 `0x43C40000` |
| VDMA | — | `0x43C40000`（64K，AXI-Lite） | 与 VTC 相邻、留扩展 |
| 时钟 | FCLK1=150 | **FCLK1=100 MHz**；FCLK0 保持 50 MHz | 厂商参考以 100 MHz 生成 74.25；150 无法分数得到 74.25，且会增加时序压力 |
| HP 端口 | HP1 | **HP2 专用给 VDMA** | HP0=2B、HP1=preproc+DMA 已用满；HP2/HP3 空闲 |

## 4. 资源预算（以 P2d 实测为基线）

| 资源 | P2d 已用 | 视频链估算（720p60 + 叠加） | 预计合计 | 上限 | 余量判断 |
|---|---|---|---|---|---|
| LUT | 23,451（44.08%） | +6,000～9,000 | 29.5k–32.5k（55%–61%） | 53,200 | 可行，但需控叠加逻辑 |
| FF | 10,414（9.79%） | +6,000～8,000 | 16k–18k（15%–17%） | 106,400 | 充裕 |
| BRAM | 33.5（23.93%） | +8～20（VDMA 行缓存/叠加缓冲） | 42–54（30%–39%） | 140 | 可行 |
| DSP | 158（71.82%） | **+0**（视频链不用 DSP） | 158（71.82%） | 220 | 不变 |
| MMCM | 0 | +1（像素时钟，另 rgb2dvi 内部 1 个） | 1–2 | 4 | 充裕 |

> 风险：LUT 与 **DSP 71.82% 的余量（62 个）** 是阶段6 的真实约束——若后续在显示链加缩放/图像处理，需先做 DSP 复用或砍功能。

## 5. BD 拓扑（草案）

```
PS7 (FCLK0=50, FCLK1=100, GP0, HP0/HP1/HP2)
 ├─ M_AXI_GP0 ─ smc_ctrl(1S/4M) ─┬─ 2B CSR 0x43C00000
 │                                ├─ preproc CSR 0x43C10000
 │                                ├─ AXI DMA 0x43C20000（既有）
 │                                ├─ VTC 0x43C30000
 │                                └─ VDMA 0x43C40000
 ├─ S_AXI_HP0 ─ 2B 推理核 M_AXI（直连，勿并入 SmartConnect）
 ├─ S_AXI_HP1 ─ smc_data(2S/1M) ─ preproc 读 + DMA 写
 └─ S_AXI_HP2 ─ vdma/M_AXI_MM2S（读显示帧）
clk_wiz(100→74.25/371.25) ─ v_tc / vdma(s_axis_aclk) / v_axi4s_vid_out / rgb2dvi
vdma/M_AXIS_MM2S ─ overlay(axis 混流) ─ v_axi4s_vid_out ─ rgb2dvi ─ TMDS 引脚
```

## 8. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 74.25 MHz 生成失败（MMCM 参数不可行） | 先用 `clk_wiz` OOC 生成并校核 `74.25±0.5%`，不可行则退 1280×720@59.94（74.176）或 60 Hz 近似；不接线前先在仿真确认 |
| LUT 超 60% 导致布线恶化 | 叠加逻辑精简（只画框，文字用 ROM）；必要时降低分辨率 |
| HP2 引入带宽竞争 | 720p60 RGB888 带宽 ≈ 1.2 Gbps，远低于 HP 理论值；监控 VDMA 无欠载 |
| 显示链改动破坏 P2d 既有行为 | S6-E 强制全量冻结回归（7 项） |
| 引脚/电平与实物不符 | 只用厂商 XDC 的 TMDS 引脚；**上板前按原理图核对 PCB 版本**（本项目规则要求） |
| HDMI 热插拔/EDID | 本阶段不做 EDID 读取，固定 720p60 输出；显示器不支持时降 720p50（需另算时钟） |
