## 操作顺序

1. 开发在工程根目录记录 Git 基线与状态；未解释改动先核实来源。
2. 开发调用已知完整 Python 路径执行 `--version`。
3. 开发执行 `& 'D:\Xilinx\2026.1\Vivado\bin\vivado.bat' -version`。正常通常数秒到数十秒；超过 120 秒仍无输出记录超时，检查进程和日志，不直接判成功。
4. Wong 提供型号/PCB/外设信息。无需为了拍照通电；开发依据资料核对并写页码，PDF 未读不写“已确认引脚”。
5. 开发交付核对结果和证据；审查检查对应关系；总控判断子任务是否通过。关键身份不明标受阻，软件子任务可以继续。

## ENV-03 的目标器件核查操作补充

在 Vivado GUI 的 Tcl Console 执行 `get_parts xc7z020clg400-2`，保存完整输出；应返回精确器件名，空列表或报错为未通过。该查询只检查安装的器件支持，不代替综合许可证、工程器件配置或板卡实物核验。若 GUI 无法启动，交付错误日志，不猜“应该支持”。

## 本轮决策对应的优先核对项

优先核实用户倾向的 HDMI 链路：板卡/PCB对应手册、两个端口的实际数量和方向、收发器件、摄像头型号及 HDMI 输出、显示器输入与支持格式。将实物标识及资料页码写入 HW-01/HW-02，不把用户对端口数量的判断当作已核实事实。接口结论回填 [[02-方案设计/系统设计]]；实时摄像头主线及 PS/PL 分工见 [[总控#当前用户决策（2026-09-10）]]。
