# S1-T01 训练环境与数据准备

## 任务卡（总控）

- 阶段：1；状态：待定义（任务卡已准备，G0尚未核实）。
- 目标：形成可复现PC环境、五类带框数据规范和小样本训练/评估闭环，为正式浮点基线提供输入。
- 边界：不正式长训、不做INT8量化或RTL、不以小样本精度作为阶段1通过依据。
- 启动输入：现有电脑和项目文件、五类标签需求、已有数据或来源候选；无需已有最终权重与量化参数。
- 基线提交、Python/框架/GPU版本、可用显存/磁盘：开工实查填写，当前未核实。
- 修改范围：data/的数据说明与清单，verification/的PC准备与检查程序，scripts/的适用启动命令，report/evidence/S1-T01/及本任务记录；目录职责沿用工程规范。
- 数据/检查点等大文件存放位置及备份方法须在G0登记，不直接混入Git。记录来源、使用许可与校验值。
- 输出：环境依赖与复现命令、标签规范、数据/划分清单、检查脚本、可视化、训练/恢复/评估日志、交接清单。

## G0核实项

确认五类编码及标签示例、框覆盖规则、遮挡/截断与多手规则；清点现有数据并核实来源。先检查环境，选定本次小样本框架和YOLOv4-tiny配置版本，记录安装/运行命令与依据。框架选择不能默默改成其他YOLO版本。必要需求由Wong确认，普通环境检查由AI执行。

小样本集用于流程验证，不用于正式精度验收。以下为本任务流程门槛；若实际数据无法满足，保留缺项并提供采集单，不自行降低要求。

## 验收矩阵

| 编号 | 要求与方法 | 通过条件 | 证据 |
|---|---|---|---|
| AC01 | 环境查询及小张量运算 | Python/框架可导入，选定设备运算退出码0；记录GPU可用性与显存，CPU备选须说明耗时影响 | 环境、依赖版本、命令与日志 |
| AC02 | 标签与来源规范 | 五类编码唯一且含示例；框、遮挡、多手、无手规则完整；Wong确认语义；来源及使用条件可查 | 标签文档、示例、确认记录 |
| AC03 | 检查小样本与划分 | 至少30张真实图片，每类至少5个标注框、至少5张无手图；训练/验证分组不交叉；两集合均覆盖五类与无手样本（同图可多框）；数据不足标未通过 | 图片/框/人员/会话统计、分组清单 |
| AC04 | 全量检查该小样本及可视化抽查 | 图片可读；类号合法；框面积为正且坐标在范围；重复内容跨集合为0；人工抽查每类2框及5张无手图，问题全部修复 | 检查输出、叠框图和Wong观察 |
| AC05 | 小样本训练、保存及恢复 | 至少10个更新步，loss/梯度无NaN或Inf；保存检查点并从记录步数继续至少1步，模型/优化器状态及计数恢复有证据 | 配置、运行日志、检查点哈希、恢复命令 |
| AC06 | 小样本评估和输出 | 所有验证图可完成推理与评估；评估数量与清单一致，输出框/类别/分数；零预测可完成评估而不报错；不设置mAP下限 | 评估日志、输出及可视化 |
| AC07 | 复现与交接 | 数据/配置/代码/检查点版本一致；复跑数据检查和评估成功；入口、命令、未完成项明确 | 版本清单、复跑日志、交接消息 |

以上分组检查针对人员和会话；来源无法给出可靠分组时记录风险并补数据，不以随机逐帧划分代替。流程测试集不要冒充正式独立测试集。

## 长任务与恢复约定

本任务仅执行上述短程验证。开发须在执行前登记准确命令、工作目录、预计时间及估计依据、日志与检查点路径。停止条件包含NaN/Inf、OOM、数据损坏及超过预先记录的无进度超时。中断先保存日志、确认进程是否仍在运行，再按恢复命令继续，不能重复启动占用同一设备的训练。正式长训由后续任务确定训练预算和检查点策略。
