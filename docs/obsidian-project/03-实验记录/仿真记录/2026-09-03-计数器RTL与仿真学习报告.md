## 三、核心概念学习

### 1. SystemVerilog 模块结构

```text
参数列表：决定模块如何配置
端口列表：决定模块如何与外部连接
模块主体：描述内部电路逻辑
```

- `module`：定义一个硬件模块；
- `parameter`：定义可配置的常量；
- `input`、`output`：定义端口方向；
- `logic`：定义逻辑信号类型；
- `[WIDTH-1:0]`：定义信号位宽。

### 2. 计数器时序行为

计数器只在时钟上升沿更新：

```text
rst=1       → count 清零
rst=0,en=0  → count 保持
rst=0,en=1  → 未到最大值时加一
达到最大值  → 根据回绕参数清零或保持最大值
```

### 3. `always_ff @(posedge clk)`

- `always_ff` 表示描述触发器或寄存器等时序逻辑；
- `@` 表示等待事件；
- `posedge clk` 表示等待时钟上升沿；
- 时序逻辑使用非阻塞赋值 `<=`。

### 4. 测试平台中的系统任务

测试平台不是上板硬件，而是用于仿真验证的代码：

- `$error`：实际结果错误时报告错误；
- `$display`：向仿真控制台打印信息；
- `$finish`：结束仿真。

`@(posedge clk)` 用于等待一个时钟上升沿，`#5` 在测试平台中表示仿真延时。

## 四、实际验证结果

测试参数为：

```text

MAX_COUNT=5
```

### 回绕模式

```text
WRAP_ON_OVERFLOW=1
```

波形观察结果：

```text
0 → 1 → 2 → 3 → 4 → 5 → 0
```

结论：达到最大值后能够正确回绕到 0。

### 不回绕模式

```text

```

波形观察结果：

```text
0 → 1 → 2 → 3 → 4 → 5 → 5 → 5
```

结论：达到最大值后能够保持 5。

## 五、问题与排障记录

### 问题 1：参数和事件控制语法错误

- 现象：`MAX_COUNT5`、`postage clk` 等写法无法正确解析；
- 原因：参数缺少赋值符号，`posedge` 拼写错误且缺少 `@`；
- 修复：改为 `parameter int MAX_COUNT = 5` 和 `always_ff @(posedge clk)`；
- 结果：模块能够进入仿真。

### 问题 2：赋值和比较混用

- 现象：条件判断中使用了 `=`，时序赋值中使用了阻塞赋值；
- 原因：`=` 是赋值，`==` 是比较，时序逻辑应使用 `<=`；
- 修复：使用 `if (rst)`、`if (count < MAX_COUNT)` 和非阻塞赋值 `<=`；
- 结果：判断条件和寄存器更新符合预期。

### 问题 3：使能关闭时错误进入溢出处理

- 现象：`en=0` 时计数器没有保持原值；
- 原因：溢出分支没有放在 `else if (en)` 内部；
- 修复：先判断 `en`，再在内部判断是否达到最大值；
- 结果：`en=0` 时 `count` 保持不变。

### 问题 4：不回绕模式只看到一个数字 5

- 现象：波形中只显示一个 5，似乎没有连续保持；
- 原因：总线数值不变时只显示一个连续的 5，且测试平台很快执行了 `$finish`；
- 修复：使用 `repeat (3)` 连续等待三个时钟上升沿并检查 `count=5`；
- 结果：波形中 5 的持续区间变宽，确认了最大值保持行为。

### 问题 5：仿真时间单位理解错误

- 现象：波形横坐标显示 `ps`，但测试时钟按 `ns` 计算；
- 原因：`timescale` 设置为 `1ns/1ps`，Vivado 在放大视图中使用 ps 显示；
- 结论：`76,000 ps = 76 ns`，`always #5` 表示每 5 ns 翻转一次，完整时钟周期为 10 ns。

### 问题 6：仿真开始时出现 `X`

- 现象：时间 0 附近 `count` 显示 `X`；
- 原因：计数器是同步复位，第一次时钟上升沿到来前尚未执行复位；
- 结果：经过复位有效的时钟上升沿后，`count` 正确变为 0；
- 结论：在本测试条件下属于预期的未初始化状态，不是计数逻辑错误。
