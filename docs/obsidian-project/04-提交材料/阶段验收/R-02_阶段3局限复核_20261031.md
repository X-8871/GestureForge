# R-02：阶段3「记录性局限」逐条复核 · 2026-10-31

- 编制：DSH 项目总控；依据：主 STATE 阶段3 行（2026-10-26）、阶段3 收尾证据入口、阶段5/6 实测现状
- 结论：**4 条局限中 1 条已由架构变更消解、3 条仍开放**；其中 2 条属 Codex/阶段3 范围，1 条为环境许可限制

## 1. 逐条复核

| # | 阶段3 记录的局限 | 现状核实 | 结论 | 归属 |
|---|---|---|---|---|
| ① | **VDMA 首帧 bit11 根因 `PARTIAL_OPEN`** | 阶段5/6 的显示 VDMA（P3n/P3q，MM2S 双帧存、非 SG、100/50 MHz）**从未观察到 bit11 类错误**：`SR=0x11000`（DmaIntErr/DmaSlvErr/DmaDecErr 全 0）、30 min 长稳 `vdma_err=0`、帧 CRC 与 `fb_crc` 一致 | **不适用当前显示链**（架构已换：无 VTC/vid_out、双帧存同图、显式 cache flush）。相机侧 VDMA 通路未复测 ⇒ 若阶段7 接相机需重验 | DSH（接相机时复验） |

| ③ | **TIMING-17 / I-O delay 未纳入冻结位流、未签核** | 阶段5 **P3q** 的 XDC 只含 TMDS/时钟引脚与 CDC 约束（`p3q.xdc` + `p3q_cdc.xdc`），**未加入 I/O delay（set_input_delay/set_output_delay）**；WNS +0.371 为内部时序，不含 I/O 约束签核 | **仍开放**（对 TMDS 显示影响低——TMDS 为 SERDES 输出、无输入采样；对 MIO/相机接口有意义） | **DSH 可做**（出 I/O delay 约束草案 + 时序复核，属增量，不动冻结位流） |

## 2. 处理建议

- ① 关闭为"**架构变更后不适用**"，条件：阶段7 接相机时对新 VDMA 通路重验 bit11 语义（RunId 单独记录）；
- ② 交 Codex（其阶段3 原任务），明确"SEC 是否仍为交付必需"；若不必需，请 Wong 裁决降级为"不适用"；
- ③ 我方出 I/O delay 约束草案（TMDS 输出不设、MIO/UART/相机接口按手册设），做一次**独立时序复核**（不纳入冻结位流，作为阶段7 前置），约 1 h；
- ④ 记录为环境限制，不阻塞；调试以 UART + JTAG 只读为替代手段。

## 3. 对阶段0–6 结论的影响

无。阶段3 已按"带记录性局限"收尾，本复核只是把 4 条局限的**当前状态**明确化，不改变阶段3 验收结论，也不追溯修改其冻结 tag。
