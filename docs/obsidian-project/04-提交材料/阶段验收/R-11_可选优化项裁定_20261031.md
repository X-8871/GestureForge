# R-11：阶段5 可选优化项裁定（P3p fsync / SG 双缓冲 / tlast_misalign）· 2026-10-31

- 编制：DSH 项目总控；对应遗留 **R-11**
- 结论：**三项均裁定为"当前范围不做"**，理由与复启条件如下；**不构成缺陷，不影响阶段5/6 冻结**

## 1. P3p（VDMA fsync 帧同步版，`25cba4ec…`）—— 不采用

| 项 | 内容 |
|---|---|
| 目的 | 用 `axis_to_video.vs` 做 MM2S fsync，消除"CPU 写帧存 / VDMA 读帧存"的撕裂 |
| 现状 | **已构建、未采用**；P3n/P3q 实测**无撕裂**（Wong 两张照片 + 60 fps 稳定、`vdma_err=0`） |
| 裁定 | **不采用**；保留为"换显示器/长线/更高分辨率后若出现撕裂"的备选 |
| 复启条件 | 目视出现横向撕裂或帧交替残留 ⇒ 切 P3p 位流 + P3p 软件变体（已构建，`EnableSync=1`/`GenLock=SLAVE`/`GenLockRepeat=1`） |
| 代价 | 启用后 VDMA 从"自由运行"变"从模式"，供数不足时可能重复帧而非丢帧——需重新验证 `fps_dis` 与欠载语义 |

## 2. SG（描述符环）双缓冲 —— 不做

| 项 | 内容 |
|---|---|
| 目的 | 用 SG 描述符环做多缓冲/零拷贝，降低 CPU 每帧重编程开销 |
| 现状 | 非 SG + 每帧只写非在读 buffer：**720p60、零欠载、30 min 长稳通过**；CPU 侧开销未成为瓶颈 |
| 裁定 | **不做**；等"需要 >60 fps、或软件单帧渲染时间接近帧周期、或需要 3+ 缓冲"时再评估 |
| 风险提示 | SG 改造会同时影响显示 VDMA 与采集 VDMA 的地址/环管理，属**阶段7+**的架构级改动 |

## 3. `tlast_misalign` 计数 —— 不引出 GPIO

| 项 | 内容 |
|---|---|
| 目的 | 观测 AXIS 流 `tlast` 与像素计数不一致（错位）的次数 |
| 现状 | `axis_to_video` 内部已有该计数器；**从未观测到异常**（整帧 CRC 与 `fb_crc` 一致、30 min 无错误） |
| 裁定 | **不引出**；若后续出现"画面错位/滚动"且 CRC 不一致，再加 GPIO（约 15 min 改动 + 1 次构建） |
| 备注 | 无 ILA（R-02④）下，此类内部计数器是重要观测手段，因此**保留在 RTL 中但不上板**是折中 |

## 4. 对阶段验收的影响

- 三项均为**优化/观测项**，不影响阶段5 G5 冻结与阶段6 G4/G5 结论；
- 在冻结记录中已作为"遗留未做"登记，本文件给出**明确的裁定与复启条件**，避免"未做"被误读为"未验证缺陷"；
- 若阶段7 引入 60 fps 以上、或 4K/多路采集，需重新评估 SG 与 fsync。
