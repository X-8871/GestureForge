# 验收执行手册

依据 [[工程协作规范]] G0—G5。本文规定怎样执行和判定，数值门槛引用任务卡及 [[02-方案设计/B方案实施与阶段验收计划]]。计划内“建议/初始目标”须在对应任务 G0 冻结，不冒充竞赛官方硬性指标。

## 1. 谁写、谁判定

总控定义需求与验收项并负责最终汇总；开发执行测试并归档；审查检查指定版本、独立依据和证据；Wong 提供实物操作结果。开发不能给自己写独立审查通过。共享任务主记录按角色串行填写，不同时编辑。

## 2. 每个关口怎样做

| 关口 | 必查内容 | 失败后动作 |
|---|---|---|
| G0 | 目标边界明确、关键未知关闭、输入输出具体、阈值和方法可执行、修改范围可控 | 核实缺项；不受影响工作继续 |
| G1 | 指定实现版本、适用测试真实执行、预期与实际比较、设计更新、操作单可用 | 修复并做相关回归 |
| G2 | 审查固定提交；关键边界、测试依据、证据版本检查；阻断问题全部关闭 | 回开发；两轮无进展回总控诊断 |
| G3 | 板卡和产物对应，按操作单运行，现场日志/照片可追溯 | 保留现场，核实环境再修复 |
| G4 | 所有任务验收项通过，适用关口完成，未适用有理由，交付可定位 | 缺什么补什么，不提前改完成状态 |
| G5 | 全阶段任务与集成指标满足，同一系统版本，发布和交接可复现 | 标阶段未通过，保留已通过子任务 |

每个验收项结果四选一：通过、失败、未执行、不适用。未执行不能当通过；不适用写技术理由。G4 已验收不代表其所属 S 阶段已通过。

## 3. 证据规则

使用 `D:\FPGA_Competition\report\evidence\任务编号\运行编号\` 作为新任务证据位置，已有证据不搬迁。运行编号如 `20260911-01`，只在执行时创建，不提前填成功。

至少保存：command.txt（命令与环境）、result.txt（原始输出及退出码）、必要波形/报告/数据。大产物按 Git 忽略和交付策略管理，任务记录保留路径与 SHA-256。敏感配置不进入证据。

版本字段：代码提交、脏工作区差异（若有则不得作为冻结验收基线）、工具、配置、数据、模型、bitstream。证据生成后提交记录不会改变被测代码哈希，保留二者关系。

数值比较必须明确绝对误差/逐值一致、输入数与不匹配数。性能必须明确起止事件、预热、全部有效样本和失败计数。准确率明确数据划分和样本组成。时序报告必须是目标顶层及目标约束下的实现结果。

## 4. 审查清单

- 需求是否都有验收项，是否偷换目标或只测成功例？
- 位宽、符号扩展、舍入中点、饱和、复位、握手和异常是否按任务覆盖？
- 独立参考是否只是复制实现；关键边界是否有手算或不同算法依据？
- 日志是否来自指定版本，是否隐藏失败、超时和不适用项？
- XDC 引脚/IOSTANDARD/时钟来源是否可靠，是否用无依据例外掩盖问题？
- 交付文件是否可重建，必要依赖是否明确，真实硬件结论是否有实测？

软件任务不强制增加无关电气检查，文档小修不强制重跑整套硬件。

## 5. 阶段对应及范围

| 阶段 | 核心验收对象 | 最小证据类别 |
|---|---|---|
| S0 | 硬件/接口规格、启动与必要 DDR 自检 | 实物来源表、引脚表、启动和自检日志、冻结规格 |
| S1 | 数据划分、浮点与 INT8 模型 | 数据版本、精度统计、混淆矩阵、导出参数 |
| S2 | 全部需要的算子与整网 RTL | 算子/整网逐值比较、协议边界、综合报告 |
| S3 | PS/PL 整网静态输入 | 分数逐值比对、任务编号对应、时序与位流 |
| S4 | 摄像头/预处理/显示 | 连续采集、格式和帧验证、预处理比对 |
| S5 | 真实输入到交互 M1 | 每类交互、连续运行、基线统计与冻结包 |
| S6 | 系统优化 | 同模型对照、全部延迟样本、吞吐/资源/时序 |
| S7 | 配置、未知输入、恢复 | 边界非法值、故障注入、稳定性与误动作 |
| S8 | 独立复现与提交 | 干净重建、上板复现、材料、协作与技能包 |

具体样本数、阈值和测试条件继续维护在阶段计划；本表不复制第二套数字。S0-T01/T02 只是开工子任务；MAC 单元通过不能标 S2 整网完成。P0—P4 是历史时间安排，S0—S8 是工程阶段，不做一一等同。

## 6. 阶段验收记录的生成方式

达到阶段边界时在本 Obsidian 项目目录下的 `04-提交材料/阶段验收/` 建立实际记录（不是工程根目录），当前不生成九份空报告。记录包含：阶段与冻结版本、阶段计划对应条目、逐项结果与证据、集成配置、资源与时序、遗留影响、恢复/重建入口、判断角色和日期。

可采用表：`要求编号｜计划条目｜阈值与口径｜实际值｜证据｜结果`。最后单独给“阶段通过/未通过”，不能只罗列材料。


## 7. 版本改变与材料可访问性

G3 失败若仅操作条件错误且代码不变，记录纠正条件并复验；若修改源码、约束、模型或运行参数，回 G1 执行受影响测试，G2 复核后重做受影响 G3。标明旧证据适用的旧版本，不套用到新版本。

G4/G5 同时检查：所引用证据实际存在且审查人可访问，路径、版本和校验值对应。大型证据被 Git 忽略不等于已经备份；本地/外部归档位置需说明。缺少可恢复的交付产物时不能声称已具备交付恢复能力。

任务编号与角色字段用于单次任务，项目进程仅保存摘要，不复制整张问题清单。多人/多窗口编辑同一主记录应串行协调，审查区新增内容不意味着源代码版本改变。
