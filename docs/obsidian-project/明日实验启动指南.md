# 明日实验启动指南

适用日期：2026-09-11。本文是实验操作入口，不另建日程系统。依据 [[工程协作规范]]；当前真实状态见 [[项目进程]]。

## 1. 明天先打开什么

1. Obsidian 打开本页。
2. Codex 选择工程路径为 `D:\FPGA_Competition` 的同一个项目。
3. 打开或建立一个总控任务，将 [[项目接手提示词#总控启动]] 的提示词作为首条消息。
4. 先执行 [[03-实验记录/任务记录/S0-T01_开工环境与资料核对]]。未完成的核验写缺口，不猜型号或引脚。
5. 环境可用后执行 [[03-实验记录/任务记录/S0-T02_Python数值基线复核]]。开发与审查使用同一任务编号、不同窗口。

这两个任务不等于整个 S0 通过，也不等于 INT8 RTL 完成。明天是否进入 RTL 由已核实证据决定，不预先承诺一天完成上板。

## 2. 你需要准备

- 板卡正反面型号与 PCB 版本信息；可提供清晰照片，不必抄写全部芯片字样。
- 现有摄像头、显示器/屏幕、下载线、串口线和电源的型号或标签。
- 能打开 Vivado 的电脑；已发现 `D:\Xilinx\2026.1\Vivado\bin\vivado.bat`，仅文件存在不代表许可证、器件支持和下载链路已通过。
- 当前已知 Python 解释器：`C:\Users\22061\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe`。普通 `python` 启动器此前失效，优先用完整路径。

首次资料核对无需上电。供电、接线、板卡版本和引脚尚未形成依据前，不照搬另一块板的 XDC，不烧写 Flash，不执行 SD 恢复出厂操作。

## 3. 窗口之间怎样传递

开发交付后给审查窗口：`按审查启动提示词审查 S0-T02，版本为开发刚交付的完整提交哈希，读取任务主记录。`

审查发现问题后给开发窗口：`处理 S0-T02 审查第 R01 轮的问题，读取任务主记录，只修复阻断项及其必要影响。`

开发修复后给审查窗口：`复核 S0-T02 第 R02 轮，版本为新提交哈希，检查问题清单与相关回归。`

哈希由开发明确交付，你不需要自行猜。传递文件路径和版本即可，不复制全部聊天。当前没有自动转发或后台运行安排。

## 4. 什么时候需要你操作

AI 先执行能执行的软件检查。只有工具不可用或必须现场观察时，才按任务操作单让你执行。反馈只需：步骤、现象、附件、是否更换文件/接线/设置。

失败时保持现场，先保存报错全文，不连续尝试多个不明设置。当天停止时让开发生成交接：当前提交、最后成功步骤、阻碍、证据和下次动作。没有验收通过不归档成完成。

## 5. 明天完成到哪里算有交付

- S0-T01：环境及资料清单有实测/来源或明确缺口，后续上板阻碍清楚。
- S0-T02：4 项现有测试通过并保存原始输出，25 组黄金数据与独立复核一致，完成一次开发—审查—验收流程。
- 板卡身份未闭合时，S0-T01 保留受阻；S0-T02 可独立继续。
- 软件完成不要求你为“个人独立编程”重复实现；若想练习，可另开学习任务。
