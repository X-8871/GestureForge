## 1. 术语与用词规则

### 1.1 术语表（阶段5 使用的受限词表）

| 术语 | 定义 | 依据 |
|---|---|---|
| 分数（score） | `score = sigmoid(objectness) * sigmoid(class)`，由 PS 在 float64 上计算；输入为 PL 的 INT8 原始 logits | `[2A L77]` |
| INT8 logits / 整数分数 | PL 检测头原始 INT8 张量（反量化前）及其中间整数形式；**不得**称为置信度 | `[2A L75]` |
| 置信度（confidence） | 仅当存在**明确的概率转换及其依据**（书面写出转换式与适用条件）时才允许使用的称谓；未校准的 `score` 不等于可靠概率 | `[计划L96]` |
| 原图坐标 | 逆 letterbox 后、原视频帧（采集分辨率）坐标系中的归一化坐标或像素坐标；两者必须显式区分 | `[2A L77]`、`[D2 L9]` |
| 结果年龄（result age） | 见 §2.1 定义；是**待显示结果**与**正在显示的帧**之间时间关系的唯一量化口径 | `[计划L98]` |
| 画面语义 | 被显示帧与叠加结果之间的配对关系（同帧叠加 / 延迟显示 / 最新结果叠加三者之一） | `[计划L98]` |
| 过期结果（stale result） | 结果年龄超过 G0 固定上限、不再允许叠加并被清除的结果 | `[计划L100]`（门槛待 G0） |
| 帧号（frame_id） | 阶段4 结果中的帧标识；显示与日志必须原样携带，不得重新编号 | `[计划L88]`、`[计划L98]` |

### 1.2 用词规则 R1–R4（score vs confidence）

- **R1**：PL 原始 INT8 logits 或未做 sigmoid 的整数分数，在界面、日志、报告、答辩材料中一律显示/书写为「分数（score）」或「整数分数」；**禁止**称为「置信度」`[计划L96]`。
- **R2**：`score = sigmoid(objectness)*sigmoid(class)`（`[2A L77]`）属于概率形式，但在缺少校准证据时，项目统一称谓仍是「分数」。若某处以「置信度」标注 `score`，必须在同一处写出 `[2A L77]` 的转换式依据，并同时声明「未做概率校准，不表示可靠概率」。
- **R3**：任何以「置信度」表述的界面/文档，必须能追溯到 §1.1 的转换依据；无依据即退回「分数」用词。
- **R4**：不得把数值大小等同于可靠概率，也不得用「准确率/可信度」描述 `score` 的数值高低 `[计划L96]`。
- **R5（字段名等价映射）**：D6 评估产物中的 `confidence` 字段与本文 `score` 指同一量（`[D6 L38]` 按 `score_threshold` 排序、`[D6 L31]` 校验 `confidence` 合法性）。阶段5 显示与日志统一使用字段名 `score`；若要复用 D6 产物，必须显式声明 `confidence ≡ score` 并绑定 `[2A L77]` 公式，禁止把两者当作两个不同量各自统计。

阶段5 显示的界面/切图状态是阶段6 状态机的**输出**（`[计划L104]`）。阶段5 只定义如何呈现状态本身（例如状态名、当前 `frame_id`、分数、FPS、延迟、状态机当前状态）；状态迁移与阈值属于阶段6 规格，本文不重复定义，也不在本阶段冒充交互验收。

## 2. 画面语义与叠框布局

### 2.1 显式声明：本轮草案采用「最新结果叠加」（语义 B）

`[计划L98]` 要求三选一并显式声明结果年龄；本草案**显式声明**如下：

- **声明（草案默认，待 G0 确认）：画面语义 = 最新结果叠加（latest-result overlay，语义 B）。** 即：显示管线持续送显**当前采集到的最新帧**；叠加的是**最近一个已发布结果**，二者**通常不是同一帧**。
- **结果年龄定义（语义 B）**：
  - `t_capture(frame_id)`：该帧在采集侧首个有效像素写入帧缓冲的时刻（采集帧起始事件，单调时钟）。
  - `t_result_publish`：该结果的**结果记录发布**时刻（字段集齐、可供显示消费的时刻，`[计划L88]`）。
  - `t_overlay_commit`：把该结果提交给显示输出（送显帧起始事件）的时刻。
  - `age_result = t_overlay_commit − t_result_publish`（**待显示结果**的陈旧度）
  - `age_frame = t_overlay_commit − t_capture(frame_id)`（**画面—结果**时间差；语义 B 下 `age_frame = age_result + (t_result_publish − t_capture(frame_id))`）
  - 两个年龄**必须分别记录**；报告「延迟」时必须写明是哪一个，禁止只报一个数而称为「端到端延迟」。
- **禁止伪称同帧**：语义 B 下，界面、截图、日志与报告**均不得**声称「框与画面同帧」；叠加时必须同时携带该结果的 `frame_id`，并在画面或日志中可见（§2.4）`[计划L98]`。
- **过期清除（语义 B）**：当 `age_frame` 超过 G0 固定的允许延迟（草案建议值见 §8，未冻结）时，该结果判为过期：**不叠加**、从待显示队列清除、并计入过期清除计数。过期清除必须显式记录，不得静默丢弃 `[计划L88]`、`[计划L96]`。
- **与阶段4 S4-A 的同源关系**：阶段4 结果记录中的 `stale` 与 `stale_age_limit`（见 `docs/stage4/S4A_stage4_g0_tracking_and_timing_draft.md` §5.3，草案 200 ms）与本节的过期清除门槛**必须同源**——阶段5 G0 与阶段4 只能固定**同一个**数值，禁止各自冻结两个不同门槛；本文 §8 的 200 ms 仅为待定输入。

## 3. 补边逆映射与坐标误差门槛

### 3.1 冻结的正向几何（引用，不重新定义）

正向 letterbox 由 D2/2A 冻结：整数新宽高按源码整数截断、左上 floor 偏移、补边归一化值 0.5/uint8 128 `[D2 L9]`、`[D2 L10]`；2A 明确逆变换「严格使用 D2 整数 resize 与左上 floor padding」`[2A L77]`。可复算的冻结实现为 `verification/s1_t02_d2_numeric_reference.py::letterbox_geometry`。设源尺寸 `(W_s, H_s)`、目标 `(W_d, H_d)`：

- 若 `W_d/W_s < H_d/H_s`：`new_w = W_d`，`new_h = (H_s*W_d)//W_s`；否则 `new_h = H_d`，`new_w = (W_s*H_d)//H_s`。
- `off_x = (W_d − new_w)//2`，`off_y = (H_d − new_h)//2`（整数除法 ⇒ floor）。

**算术推导样例**（由上述冻结公式计算，非实测；脚本见 §7）：

| 源分辨率 | 目标 | `new_w×new_h` | `off_x, off_y` | 说明 |
|---|---|---|---|---|
| 1280×720（横） | 416×416 | 416×234 | 0, 91 | 非方形横屏 |
| 720×1280（纵） | 416×416 | 234×416 | 91, 0 | 非方形竖屏 |
| 1920×1080 | 416×416 | 416×234 | 0, 91 | 与 1280×720 同几何比例 |
| 640×640（方） | 416×416 | 416×416 | 0, 0 | 无补边退化为纯缩放 |
| 800×600 | 416×416 | 416×312 | 0, 52 | `(416−312)//2` 为偶数 |
| 640×360 | 416×416 | 416×234 | 0, 91 | `(416−234)//2 = 91` |
| 683×384 | 416×416 | 416×233 | 0, 91 | 奇数宽源；总补边 183 为奇数，下侧补边 92（非对称） |

**奇数总补边（half-pixel）用例**：`[2A L77]` 明确「包括奇数总 padding 的半像素差异」，涉及两个独立来源，均**必须保留**，不得为「对称美观」改成 `ceil`、重新居中或改写采样点：

1. **非对称补边**：当 `(W_d − new_w)`（或 `(H_d − new_h)`）为**奇数**时，floor 偏移使左/右（或上/下）两侧补边相差 1 px。例如源 683×384：`new_h = 384*416//683 = 233`，总补边 183 为奇数，`off_y = 91`、下侧补边 92（不等）。此时框必须用**同一** `off_y` 反补边，不得按上下各 91.5 处理。
2. **端点对齐双线性的半像素采样**：D2 冻结的 resize 为端点对齐（`w_scale = (src_w−1)/(new_w−1)`，`[D2 L9]`），当 `new ≠ src` 时映射点一般落在两像素之间；逆映射必须与正向使用同一 `w_scale/h_scale` 语义，不得改用「像素中心对齐」公式。

用例清单与具体分辨率由 §7 脚本按冻结公式枚举并写入证据（含 `(416−new)` 为奇数的样例），本文不预设超出算术推导的数值。

### 3.2 逆映射（草案公式，待 G0 固定）

对每个框的归一化坐标 `(u, v)`（语义：相对 **letterbox 后 416×416 网络输入**的归一化坐标，`[2A L77]` 的裁剪域）：

- 反补边到缩放图坐标：`x_r = u*W_d − off_x`，`y_r = v*H_d − off_y`
- 反缩放到原图**连续像素坐标**（端点对齐，须与 §3.1 正向同一 scale）：`x_px = x_r * (W_s−1)/(new_w−1)`，`y_px = y_r * (H_s−1)/(new_h−1)`
- 原图归一化坐标：`u_orig = x_px / (W_s−1)`，`v_orig = y_px / (H_s−1)`
- 退化情形 `new_w == 1` 或 `new_h == 1`：与冻结实现一致取 `w_scale = h_scale = 0`（`verification/s1_t02_d2_numeric_reference.py` 第 151–152 行），端点对齐逆式不适用，必须走 §3.2 约束 4 的兜底（以阶段4 原图坐标字段为准）。
- **依据与冲突说明**：D2 冻结实现用端点对齐 `w_scale = (W_s−1)/(new_w−1)`、`h_scale = (H_s−1)/(new_h−1)`（同文件第 151–171 行）；本草案早期写法的像素中心对齐形式（源宽 1920、`x_r=415` 时给出 1915.38 px，而端点对齐给出 1919.00 px，差 3.62 px，已超 §3.3-B 的 ≤1.0 px）**已废弃**，逆映射一律以上述端点对齐式为准。

草案约束（待 G0 确认）：

1. 中间量必须用 float64（或精确定义的有理数）计算；**禁止**把 `x_r`、`y_r` 提前取整，否则会引入不可复现的偏差。
2. 仅在实际绘制像素时做一次取整/舍入；取整规则（floor / round-half-away-from-zero，与 D2 `[D2 L17]` 的对称舍入是否一致）必须在 G0 明确。
3. 逆映射实现必须与 `letterbox_geometry` 使用同一份几何来源；不得在显示代码中重写另一套 resize 变体。
4. 若 2A/阶段4 已给出「原图坐标」字段，则显示层**只允许**使用该字段（`[计划L88]`），不得自行反算第二份坐标；本节的公式是给阶段4 缺失该字段时的草案兜底，是否启用待 G0。

### 3.3 坐标误差门槛口径（沿用 2A 比较容限；显示像素层另列草案）

**A. 数值链路（沿用 2A，不新增口径）** `[2A L75]`、`[2A L77]`：

- `score` 绝对误差 ≤ `1e-6`；归一化坐标各分量绝对误差 ≤ `1e-6`；相对误差容限为 `0`。
- 离散字段（`frame_id`、检测数、类别、`source_order`、NMS 决策、输出顺序、框数）必须**完全相同**；任一离散字段不同或数值超限即判该帧不匹配。
- 显示层不得放宽、替代或重新解释上述容限；显示层误差只在 A 通过之后另行评估。

**B. 显示像素层误差（草案建议值，未冻结；G0 必须固定后再验收）**：

| 项 | 草案建议 | 说明 |
|---|---|---|
| 逆映射一致性 | 与 float64 参考实现的像素坐标差 ≤ 1.0 px（逐边、逐框） | 含线宽不参与该比较（比较几何中点线） |
| 绘制保真 | 实际像素边框与几何线偏差 ≤ 1 px，另加线宽端点半像素的 ±0.5 px | 由线宽 2 px 与栅格化引起，需在 G0 明确是否计入 |
| 归零处理 | 裁剪后零面积框必须不绘制，且判定与 2A 一致（finite/raw 正面积、逐边裁剪到 `[0,1]`、裁剪后零面积丢弃） | `[2A L77]` |

## 5. FPS 与延迟的测量起止事件（`[计划L98]`）

**通用要求**：所有时间使用同一单调时钟；事件必须记录为**帧级事件日志**（含 `frame_id`、事件类型、时间戳），任何统计量都必须可由日志重算。时钟源、分辨率、位宽、溢出回绕处理必须记录；不得用挂钟时间混合单调时间。

### 5.1 采集 FPS（采集侧）

- 起事件：采集侧一帧的首个有效像素写入帧缓冲（采集帧起始，记 `t_cap_sof(frame_id)`）。
- 止事件：下一帧的首个有效像素写入帧缓冲（`t_cap_sof(frame_id+1)`）。
- `采集FPS = (N−1) / (t_cap_sof(last) − t_cap_sof(first))`；必须声明是**整段平均**还是滑动窗口（草案建议：同时报告 1 s 滑动窗口与整段平均，未冻结）。
- 分母口径必须声明：接收帧数 vs 有效帧数；丢帧必须单列（§5.5）。

### 5.2 推理 FPS / 推理耗时（推理侧）

必须分别给出两个量，禁止合并：

- **PL 推理耗时** `t_pl(frame_id)`：起 = PS 提交的 `start` 被 PL 接受的时刻（2A：从有效 `start` 接受周期起计数 `[2A L65]`）；止 = PL 完成事件（`done` / `operator_result_valid`，`[2A L67]`）。
- **PS 结果耗时** `t_result(frame_id)`：起 = 同一次 `start` 接受时刻；止 = 结果记录发布时刻（含 PS 解码/NMS，字段集齐，`[计划L88]`）。
- **推理 FPS**：以「已完成并发布结果的帧数 / 观测时长」计；**必须声明**是否剔除超时帧与丢帧帧（草案建议：不剔除——超时与丢帧单列计数，FPS 分母同时给出「全部接收帧」与「有效完成帧」两版，未冻结，G0 固定）。
- 阶段7 才冻结吞吐下限与端到端 P99 `[计划L115]`；本文不承诺任何 FPS 或延迟数值。

### 5.3 显示 FPS（显示侧）

- 起事件：输出帧起始（送显帧的首个有效像素输出或等效的显示帧起始标记）。
- 止事件：下一输出帧起始。
- 显示帧率与「叠加结果更新率」「推理更新率」是**三个不同量**，必须分列；采集/显示帧率不得替代检测更新率 `[计划L115]`。

### 5.4 端到端延迟与结果年龄

- 语义 B（本草案声明）下：
  - `结果年龄 age_result`、`画面—结果时间差 age_frame`：定义见 §2.1；两者**分别报告**（均值、P50、P95、P99 与样本数）。
  - 「端到端延迟」在本语义下只能定义为 `age_frame`，且必须同时说明它是「结果与**当前显示帧**的差」，不是「同一帧的往返延迟」。
- 语义 A 下才可报告「同帧端到端延迟 = t_overlay_commit − t_capture(frame_id)」。
- 允许延迟（上限）由 G0 固定 `[计划L100]`；草案建议值见 §8（未冻结）。
- 分位数必须给出样本数；样本不足时只报最大值与计数，不得用分位数暗示统计强度。阶段7 才冻结 P99 上限与 ≥10000 次有效任务口径 `[计划L116]`。

### 5.5 预热、丢帧与超时（不得隐藏）`[计划L98]`

| 情形 | 必须记录 | 处理规则（草案，未冻结） |
|---|---|---|
| 预热（warmup） | 预热帧数、预热起止时间戳；HUD 显示 `warmup` 状态 | 预热帧**单独统计并单列**；若剔除，必须同时给出含预热与不含预热两版结果 |
| 采集丢帧 | 期望帧号序列中的缺口、缺口长度、时间 | 计数 + 缺口清单；不得用平均 FPS 掩盖 |
| 推理丢帧/跳过 | `frame_id`、原因（队列满/超时/主动跳过） | 计数 + 原因分类 |

| 超时 | `frame_id`、`TIMEOUT_CYCLES`、`ERROR_CODE`、时刻 | 单列，**不重试覆盖、不计入有效完成帧**，不隐藏 |

- 任何以「平均」形式给出的 FPS/延迟，其分母必须能由帧级事件日志复算；不满足则该统计量不得进入报告。
