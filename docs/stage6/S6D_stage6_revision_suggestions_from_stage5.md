# S5-D 对阶段6 v1 草案的修订建议（只建议，不生效）

更新：2026-10-21（UTC+8）。本文件**只给修订建议**，供阶段6 正式准备树（由项目总控另行开启）参考。
**不改写** w4 冻结的 `docs/stage6/S6_stage6_interaction_spec_draft.md`（v1，`d7cf9809…`）与 `s6_interaction_thresholds.json`（`b87234e4…`）。

## 建议清单（每条：引用路径 + 理由 + 影响面）

1. **S6-D-01｜把“显示语义=最新结果叠加”写成阶段6 的前置事实**
   - 引用：`docs/stage6/S6_stage6_interaction_spec_draft.md`（v1）中涉及“当前帧/画面状态”的表述；本树 `docs/stage5/S5A_stage5_display_g0_spec_v2.md` §2/§7。
   - 理由：Wong 已定语义 B（显示帧与结果帧通常不同帧）。阶段6 的“稳定判定窗口/冷却/重触发”若以“画面即结果帧”为前提，会与阶段5 契约冲突。
   - 影响面：状态机的窗口计数应基于**结果 `frame_id` 序列**（而非显示帧），并显式声明所用序列；阈值表的窗口单位建议从“帧”明确为“结果条数”。

2. **S6-D-02｜阈值表补充“序列来源”与“缺失/过期结果”处理**
   - 引用：`docs/stage6/s6_interaction_thresholds.json`（v1）；阶段4 S4-A §5.1（`dropped_frames` 互斥规则）、§5.3（`stale`）。
   - 理由：v1 阈值表未声明窗口序列在**丢帧/超时/过期清除**时如何推进。若不定义，稳态判定在丢帧下会出现不可复现的计数口径。
   - 影响面：建议冻结：窗口只由 `state ∈ {OK,NO_HAND}` 的结果推进；`TIMEOUT/ERROR/DROPPED` 不推进窗口但必须计数；`stale=true` 的结果不得触发动作。

3. **S6-D-03｜未知输入与零框的语义区分**
   - 引用：S6 v1 中“未知输入误接受率”相关条目；阶段5 §3 零框规则。
   - 理由：阶段5 把 `state=NO_HAND`（零框）视为**合法结果**；阶段6 需明确“零框”与“未知手势（有框但类别不可信）”是两种不同输入，误接受率的分母口径必须写明，否则指标不可比。
   - 影响面：阈值表中应分别定义 `no_hand_frames` 与 `unknown_frames`，并声明未知判定依据（例如分数低于阈值、类别不在 `CLASS_ORDER`）。

4. **S6-D-04｜动作与显示状态必须携带 `frame_id` 与年龄**
   - 引用：S6 v1 动作日志条目；阶段5 §7 五元组。
   - 理由：交互动作的证据若不带 `frame_id`/年龄，无法与阶段5 显示证据按帧索引，也无法证明“不是伪称同帧”。
   - 影响面：建议要求动作日志字段：`action`、`trigger_frame_id`、`age_result_ns`、`age_frame_ns`、`display_semantics`。

5. **S6-D-05｜“分数 vs 置信度”用词规则扩展到交互阈值命名**
   - 引用：S6 v1 阈值表中的 `confidence` 类字段（如有）；阶段5 §5。
   - 理由：若阶段6 阈值表使用 `confidence` 而阶段5 用 `score`，会出现同一量的两种命名与两套统计口径。
   - 影响面：阈值表字段名统一为 `score`；若必须使用“置信度”，须同处给出 sigmoid 转换依据与“未校准”声明，并按 R5 声明等价。

## 边界声明

- 以上均为**建议**；本树不修改 v1 草案，不产生阶段6 的冻结结论，也不代阶段6 做阈值决策。
- 阶段6 正式准备树开启时，应以本文件为输入之一，并自行核对 v1 原文与阶段4/5 冻结件。
