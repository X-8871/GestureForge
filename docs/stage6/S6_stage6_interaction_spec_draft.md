## 1. 术语、输入/事件/动作接口

### 1.1 术语

| 术语 | 定义 |
|---|---|
| 帧结果（result） | 某个 `frame_id` 的一次检测结果记录（可为零框）`[计划L88]` |
| 目标（target） | 被状态机跟踪的一个具体检测框实例（类别 + 原图坐标 + 分数 + `frame_id`） |
| 有效手势（valid gesture） | 属于五类之一且通过选择/稳定判定的目标 |
| 未知输入（unknown input） | 不属于五类有效手势的输入场景，含未知手势、无手、非法/异常输入；**不等于**第六类 |
| 未知类别（unknown class） | 结果中出现不在五类内的类别标识；属异常输入，必须记录并按 §7 处理 |
| 动作（action） | 阶段6 的输出：切换 HDMI 图像通道、切换界面/显示状态等 `[计划L104]`；本文只定义事件与唯一性，不定义具体硬件实现 |
| 触发（trigger） | 状态机从 STABLE 产生一次动作的事件；一次触发 = 一次动作事件 |
| 获取（acquisition） | 目标从被选为当前目标到该目标丢失/切换的完整过程；一次获取最多触发一次（草案声明 A，§4.3） |
| 重获（re-acquire） | 目标丢失（LOST）后重新出现并再次满足稳定判定的过程，视为**新的独立获取** |
| 稳定窗口 | 判定目标是否稳定的一组连续帧/时间条件（§4） |

### 1.2 输入事件（每帧一条，必须携带 `frame_id`）

- `E_FRAME_RESULT`：正常结果（含零框）。
- `E_FRAME_TIMEOUT`：本次任务超时（记录 `TIMEOUT_CYCLES`、`ERROR_CODE` 语义 `[2A L65]`）。
- `E_FRAME_DROPPED`：采集或推理丢帧（记录缺口 `frame_id` 与原因）。
- `E_FRAME_STALE`：结果过期被清除（年龄口径见阶段5 规格 §2.1）。
- `E_FRAME_INVALID`：结果非法（类别不在五类、坐标非 finite、分数非 finite、框数超限等）。

事件序列必须严格按 `frame_id` 单调推进；缺失帧以 `E_FRAME_DROPPED` 显式补齐（不得静默压缩时间轴），缺失帧的配对处理规则见 §4.2、§7.2。

### 1.3 动作事件（输出）

- `A_SWITCH_CHANNEL`：HDMI 切图。
- `A_SWITCH_UI`：界面切换。
- `A_DISPLAY_STATE`：显示状态变化。
- 每次动作必须记录：`action_id`（唯一）、类型、触发 `frame_id`、目标类别、分数、状态机来源状态、`t_trigger`、`t_action_effective`、结果（成功/失败/未观测）、抑制原因（若被抑制）。
- `result` 取值语义（统计口径的前置条件）：`success` = 动作**实际生效**（`t_action_effective` 已记录且执行确认）；`fail` = 已提交但执行失败；`unobserved` = 已提交但无观测证据。**只有 `success` 计入成功率分子**（§8.1）；`fail` 计入失败；`unobserved` 单列并按 `NOT_RUN` 处理，既不得计入成功，也不得从分母剔除。仅「触发」但未生效的动作不得算成功。
- 动作唯一性窗口：同一动作在 `T6-A02`（草案 500 ms）内不得重复提交；重复提交尝试必须记录为抑制事件 `S_DEDUP`。

## 2. 交互状态机

### 2.1 状态集合（命名固定，全文与 JSON 一致）

`IDLE`、`CANDIDATE`、`STABLE`、`TRIGGERED`、`COOLDOWN`、`LOST`、`UNKNOWN_RECOVER`（`[计划L104]` 要求的行为在 §3–§7 逐项对应；状态名可自定，但一旦固定必须全文一致）。

| 状态 | 含义 | 该状态下禁止的行为 |
|---|---|---|
| `IDLE` | 无当前目标，等待候选 | 不产生动作 |
| `CANDIDATE` | 已选定一个候选目标，正在累积稳定证据 | 不产生动作 |
| `STABLE` | 稳定判定满足，允许触发 | 不重复触发同一获取 |
| `TRIGGERED` | 已触发一次动作，动作事件已记录 | 不产生第二次动作 |
| `COOLDOWN` | 触发后的抑制期 | 不产生动作 |
| `LOST` | 当前目标丢失 | 不产生动作 |
| `UNKNOWN_RECOVER` | 遭遇未知/异常输入，处于恢复观察 | 不产生动作 |

- **迁移求值顺序（逐帧、首次命中即停）**：P1 异常输入（M2/M13）→ P2 丢失确认（M10）→ P3 当前状态专属推进（M5、M6、M8、M9、M15、M3、M4）→ P4 重获/获取（M1、M14）→ P5 恢复（M12）；未被命中的候选写入 `transition_candidates`，冲突时记录 `S_CONFLICT_RESOLVED` 供复核。
- **`CANDIDATE` 下 M4 与 M10 冲突的取舍**：当两者在同一帧同时满足（例如第 5 帧）时以 **M10 首次命中**（更长确认期优先，避免把短暂抖动或短暂停顿当作丢失）；该帧 M4 不再触发。
- **进入 `COOLDOWN` 时的证据策略（草案，待 G0 固定）**：**保留当前目标标识**，**重置稳定窗口证据**（帧计数、时间窗起点、抖动容忍计数归零）。因此冷却结束后的三种情形互斥且穷尽：目标匹配且窗口重新满足 → M9 → `STABLE`（不再触发）；目标匹配但窗口未满足 → M15 → `CANDIDATE`（重新累积证据）；目标不匹配/丢失 → M8 → `IDLE`。**任何冷却结束情形都有迁移出口，不存在死状态。**
- **M15 路径的下游语义（本轮按选项①声明，非阻断项已闭环）**：M15 的前提是**目标仍匹配**（未丢失、未切换），按 §1.1 的「获取」定义**仍属同一次获取**。因此经 M15 进入的 `CANDIDATE` 即使满足 §4.1 并转入 `STABLE`，**也不再触发**（`M5` 在该路径上不可用）：该 `STABLE` 等同 §4.3 的**维持态**，其出口集合非空且与 M5 互斥 —— **M10（丢失确认）** 或 **§6 目标切换（当前目标不再匹配并由 §3 重选）**之一必达，因此**不产生新的死状态**。同一目标在 M15 路径上不得二次触发。
- **变更边界**：若后续确需「经 M15 后再次触发」，属于把 §4.3 声明 A（一次获取只触发一次）改为备选 B 的**实质语义变更**，必须交 Wong / 阶段6 G0 决策并同步改写 §4.3、M5 与 JSON `trigger_once_while_held`；**本轮不采用**。
- 状态机的“保持期”指目标自 STABLE 起持续匹配的时间段；其触发语义在 §4.3 显式声明。
- 抖动容忍：稳定窗口内允许 `T6-J01`=1 帧短暂中断（该帧不满足匹配但窗口不重置）；是否允许、允许几帧由 G0 固定，草案为 1 帧且必须记录 `S_JITTER_TOLERATED` 事件。

## 3. 多框目标选择规则（`[计划L104]`）

按优先级从高到低，逐帧对「当前目标」与「全部候选框」求值：

1. **维持优先（迟滞）**：若上一状态存在当前目标，且本帧存在与其匹配的框（IoU ≥ `T6-P03`=0.30 **或**中心位移 ≤ `T6-P04`=0.15 归一化，二者取或；匹配还需类别相同），则继续使用该目标，不受其他更高分框影响；若出现更高分且类别不同的框，必须记录 `S_TARGET_HELD` 事件与两条候选信息。
2. **分数优先**：否则在通过最小分数 `T6-P01`=0.35（草案，且必须 ≥ 冻结 NMS 阈值 0.25 `[2A L77]`）的框中选择分数最高者。
3. **平票规则**：分数完全相同时按冻结的稳定同分顺序（head 顺序、row-major cell、anchor 顺序、class_id）`[2A L77]`；若 `source_order` 可用则以其为准（离散字段口径 `[2A L75]`）。
4. **无目标**：若所有框低于 `T6-P01`、或结果为零框、或结果非法，则该帧视为“无目标”，按 M10/M2 处理。
5. **禁止规则**：不得按框面积、像素位置或用未被冻结的顺序重排候选；不得因“画面中央优先”等未冻结启发式改变选择；任何新增启发式必须在 G0 冻结并写入本文与 JSON。

## 4. 稳定判定窗口与保持期触发语义

### 4.1 稳定窗口条件（`[计划L104]`）

草案条件（全部须满足，参数未冻结）：

- 连续帧数 ≥ `T6-S02`=6 帧，且持续时间 ≥ `T6-S01`=200 ms；按 `T6-S03`（取较晚满足者）判定（即两个条件都满足才进入 STABLE）。
- 窗口内每一帧（除允许的 `T6-J01`=1 帧中断外）都存在与当前目标匹配的框，且**类别不变**。
- 窗口内每帧分数 ≥ `T6-P02`=0.30（草案；阈值语义为 2A 的 `score`，`[2A L77]`）。
- 窗口内相邻帧中心位移 ≤ `T6-P05`=0.05（归一化）每帧。
- 窗口内不得出现 `E_FRAME_INVALID`；丢帧（`E_FRAME_DROPPED`）如何处理必须按 §4.2 声明并记录。

### 4.2 丢帧/超时对窗口的影响（草案，待 G0）

- 丢帧**不延长**时间窗（时间继续流逝），但**不增加**帧计数；若因丢帧导致帧数条件无法在合理时限内满足，该次获取按超时处理（记录 `S_WINDOW_TIMEOUT`）。
- 超时帧（`E_FRAME_TIMEOUT`）与非法帧（`E_FRAME_INVALID`）视为窗口中断：按 §7.2 迁移到 `UNKNOWN_RECOVER`，不得当作“仍稳定”继续累积。
- 上述处理方式必须在 G0 固定，并与阶段5 的丢帧/超时计数口径保持同一份日志事实来源。

### 4.3 保持期是否只触发一次（**显式声明**）

- **声明（草案默认 A）：一次获取只触发一次。** 目标进入 `STABLE` 后触发动作一次，随后进入 `TRIGGERED`→`COOLDOWN`；保持期内即使目标持续稳定也**不再触发**。
- 备选 B（已登记、**未声明**）：保持期按固定周期重复触发（周期需另定）。选择 B 时必须同时定义周期、去重与失败重试规则。
- 重新触发条件（草案，配合 M8/M9/M15）：只有 (a) 目标丢失并确认（`LOST`→`IDLE`）后重新满足稳定窗口（重获，§5.2），或 (b) 冷却结束且发生了目标切换（当前目标变为另一个合法目标）时，才允许下一次触发；同一目标在保持期内不得重触发。**M15 路径（冷却结束、目标仍匹配但窗口未满足）既不是 (a) 也不是 (b)**：该路径上即使再次达到稳定，其 `STABLE` 也只是维持态，`M5` 不可用（出口见 §2.2 M15 路径规则）；允许该分支重触发属声明 A→B 的语义变更，须 Wong/阶段6 G0 决定。
- 上述“只触发一次”与“重触发条件”必须由 G0 固定，并写入 JSON `state_machine.trigger_once_while_held`。

### 4.4 冷却（`[计划L104]`）

- 冷却期 `T6-K01`=1000 ms（草案）；冷却自动作事件落盘时刻起计。
- 冷却期内：抑制**所有**触发（包括其他目标），抑制必须记录 `S_COOLDOWN`（含被抑制的目标与分数），不得静默丢弃。
- 冷却结束时的状态取决于当前目标是否存在与是否稳定（M8/M9/M15 三条件互斥且穷尽，证据保留/重置策略见 §2.2）。

## 5. 丢失与重获（`[计划L104]`）

### 5.1 丢失

- 判定：连续 `T6-L01`=5 帧或 `T6-L02`=300 ms（取**较早**满足者，草案）无匹配目标，即确认丢失（M10）；进入 `LOST` 后立即清空当前目标、稳定计数与候选（M11）。
- 丢失原因必须分类记录：零框（无手）、分数低于 `T6-P02`、类别变化、位置突变超阈值、结果非法、丢帧/超时过多。
- 丢失不得立即产生任何动作；不得用“上一次结果”延展目标（禁止无限保持）。

### 5.2 重获

- 重获定义为：`LOST`→`IDLE` 之后，同一目标（类别相同、位置匹配或为重新进入视野）再次满足 §3 选择与 §4 稳定窗口，被当作**新的独立获取**。
- 重获允许再次触发（一次获取一次），但仍受冷却约束：若重获发生在冷却期内，触发被抑制并按 §4.4 记录。
- 重获的“同一目标”判定采用 §3 第 1 条同样的匹配口径；若目标离开视野后重新进入，允许以类别 + 位置邻近判定为同一目标；该规则由 G0 固定。

## 6. 目标切换（手势切换，`[计划L106]`）

- 当前目标存在且出现另一个通过 `T6-P01` 且（与当前目标类别不同或位置不匹配）的框时：
  - 若当前目标仍匹配（第 1 条迟滞成立），维持当前目标并记录 `S_TARGET_HELD`；
  - 若当前目标不匹配（已丢失），则按 §3 重新选择候选，并按 §5 走丢失→重获路径。
- 切换必须记录：旧目标/新目标的类别、分数、`frame_id`、切换原因；切换不得绕过稳定窗口（新目标必须重新满足 §4.1）。
- 手势切换不得与“抖动”混淆：单帧或 `T6-J01` 帧内的类别抖动不构成切换，须由稳定窗口与丢失阈值共同决定。

## 7. 无手/未知输入与恢复（`[计划L104]`、`[计划L106]`）

### 7.1 无手（零框）

- 零框是合法结果（`[计划L88]`）；在 `IDLE` 下保持 `IDLE`；在有目标时按 M10 计入丢失判定。
- 无手期间的状态与计数必须与“丢失/未知”分区统计，便于 T6-02/T6-03 的分母口径对齐。

### 7.2 未知与异常输入

| 情形 | 处理（草案） | 记录 |
|---|---|---|
| 未知类别（不在五类内） | 视为非法输入，不参与选择；迁移 `UNKNOWN_RECOVER`（M2） | `E_FRAME_INVALID`、类别原值 |
| 未知手势但类别合法（如五类中未预定义的动作意图） | 按正常检测处理，但不允许触发未定义动作 | 触发计数；仅记录 |
| 无手 | 零框路径（§7.1） | `boxes=0` |
| 结果非法（非 finite、框数超限、字段缺失） | `UNKNOWN_RECOVER`，丢弃该帧证据 | `E_FRAME_INVALID` + 原因 |
| 丢帧/超时过多 | `UNKNOWN_RECOVER`（M2），不产生动作 | `E_FRAME_DROPPED`/`E_FRAME_TIMEOUT` 计数 |

- 恢复（M12）：连续 `T6-U01`=5 帧合法结果且无未知类别，回到 `IDLE`（当前目标必须为空；恢复后需重新按 §5.2 重获）。
- 恢复期间**禁止**保留旧目标继续触发；恢复后不得把恢复期的中断帧计入稳定窗口。
- **未知输入的误接受必须计入 T6-02 统计**：未知输入样本内出现任何动作事件即判该样本误接受（§8.2）。

### 7.3 未知输入的独立性要求

- `T6-02` 的 200 个样本必须彼此独立（独立场景或独立录制），不得由同一段视频重复切分冒充；样本清单（编号、来源、时长、SHA-256）必须预先登记并在证据中保留，事后不得增删。
- 未知输入不得被改写为 `no_hand` 或其他类别 `[D2 L22]`。

### 8.2 统计口径的共性规则

1. **不得只挑成功视频**：全部试验（含失败、超时、不可判定）必须进入分母并保留原始记录 `[计划L106]`。
2. **样本预先登记**：场景清单、试验次数与顺序、未知输入样本编号与哈希在执行前登记；执行后不得增删样本，缺失样本单独登记为 `NOT_RUN`/`BLOCKED`。
3. **独立性去重**：同一场景/录制片段不得重复计入；发现重复必须合并并在报告中说明。
4. **置信区间**：默认 Clopper-Pearson（精确二项）单侧区间；其他方法须在报告中写明并说明理由。
5. **小数与舍入**：比率保留至 4 位小数，通过判定使用未舍入原值；计数为整数。
6. **分环境报告**：不同输入源/分辨率/光照条件分别给样本数与失败数，最后才可合并。
7. **不隐藏**：丢帧、超时、预热、被抑制的触发、状态机异常迁移一律单列计数（§1.2、§4.4、§10.2）。

### 8.3 阈值与文档的一致性绑定

- 文档阈值表（§8.1）与本 JSON 文件由自检脚本 `s4d_spec_selfcheck.py` 校验：JSON 可 `json.load`、JSON `thresholds` 与 §8.4 镜像块逐字段相等、§8.1 表格行包含对应 `id`、`value_display`、`min_samples` 等关键值。
- 任何一处修改必须同时更新文档、JSON 与自检记录；三者不一致即为缺陷。
- **校验方向性（复审 O1）**：C9 的「参数 ID 全集一致」只能发现「正文引用了 JSON 未定义的 ID」这一方向；因 §8.4 为逐字镜像，反方向（JSON 有键而正文未提及）在本文中恒真、不构成独立证据。
- **一个 ID 可由多个键构成（复审 O2）**：例如 `T6-U00` 由 `T6-U00_anomaly_window_frames` 与 `T6-U00_anomaly_min_count` 两个键共同承载；C9 按 ID 前缀比对，不假设「一 ID 一键」。
