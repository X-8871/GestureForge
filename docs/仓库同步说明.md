# GestureForge 仓库同步说明

工程根目录为 `D:\FPGA_Competition`，远程为 https://github.com/X-8871/GestureForge.git 。工程保留原目录结构，不使用 `D:\FPGA\_Competition`。

`docs/obsidian-project` 仅保存用户指定的 Obsidian 项目目录快照。知识库原目录是编辑源，仓库快照不作为第二个编辑入口。其他 Vault 内容及其 Git 历史不导入本仓库。快照中的库外双链可能无法在 GitHub 跳转，不扩大同步范围修复它们。

## 每次交付

1. 在工程根目录运行 `python scripts/sync_project_notes.py` 预览。
2. 运行 `python scripts/sync_project_notes.py --apply` 更新项目笔记快照。
3. 核对 `git diff`、新增文件、适用测试及敏感信息，仅暂存相关文件。
4. 提交后推送到已核对的远程分支；网络失败时保留本地提交，不能声称已同步 GitHub。

同步脚本不会自动提交、推送或传播删除。发现快照独立改动会停止，必须先协调修改来源。远程拉取的笔记修改需显式核对后回写 Obsidian，禁止两边同时编辑。没有后台自动同步任务。

本机默认 `python` 启动器当前不可用。已验证可使用 Codex 自带解释器：`C:\Users\22061\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe`。在 PowerShell 中用 `& '解释器完整路径' scripts/sync_project_notes.py --apply` 执行；其他电脑使用已安装的 Python 3。

## 排除范围

排除临时浏览器资料、第三方参考视频目录、Vivado 生成缓存、构建产物与常见凭据文件。原始文件不删除。正式发布产物另行准备交付包，不能以缓存代替证据。

## 项目与任务窗口

在同一个 Codex 项目下建立总控、开发和审查任务。项目路径使用工程根目录。审查指定提交且不修改实现；同一任务修复继续使用原窗口，验收与交接完成后归档。无需复制三个相同项目。
