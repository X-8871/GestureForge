# C3 / R-09：阶段6帧周期测量学

## 范围与结论

本目录只交付离线复核方法、CSV 分析程序、单元测试和后续板上采集计划。本轮没有连接板卡、启动硬件服务、停核、改写固件、烧写 PL/QSPI 或执行任何板上采集。

本轮 C3 起始基线为阶段6工作树 HEAD b0f4a688aa618f891b673c9b779f6b68f6e7472c（分支 stage6-interact-prep）；文件位于获批的隔离子目录 legacy_codex_20261031/c3/，未暂存、未提交。阶段4/5证据树用于输入核验的基线另列为 w4 HEAD，不代表 C3 提交。

对 DSH 的 **P = 16673 µs** 复核结果如下：

- 该值来自 P3q 显示程序测得的 **VDMA MM2S 当前读帧存指针 PARKPTR.READSTR 变化周期**。固件观察到 6 次指针变化，以首末 GT 差值除以 5 个间隔；它是显示读帧路径的周期代理。
- 该值**不是相机 SOF 周期**，也不是推理完成周期。P3q 使用 PL axis_to_video 自产 720p60 显示时序；本轮 E2 记录没有相机 VSYNC/SOF 计数或时间戳。
- r03 留存的是 UART 汇总值 5,557,890 GT ticks，没有保存 6 个切换沿的逐沿 GT 时间戳、每次轮询间隔或端点原始读数。因此能够核算汇总数值，不能从原始逐样本数据重建抖动、最大轮询延迟或严格置信区间。
- 阶段6行为规格将 T6-A03 的 P_meas 指向阶段4的实测帧周期；本结果只支持显示读帧侧描述，不能填入 T6-A03。是否已有可用的阶段4相机 SOF实测，应由阶段4冻结材料另行证明。

## 事件和时钟必须分开

| 事件 | 推荐事件定义 | 典型观测源与时钟 | 能回答的问题 | 可否替代相机 P |
|---|---|---|---|---|
| 相机 SOF | 传感器 VSYNC 的有效帧边沿；极性须按当前传感器配置/实测核对 | 相机输入时钟域的 SOF 计数器或无损时间戳；与 GT 同步/换算需留校准依据 | 相机源帧到达周期 | **本身就是相机源 P** |
| VDMA S2MM 帧接收 | 捕获路径接受一帧的 SOF/TUSER，或 S2MM 帧完成事件；必须注明是哪一种 | S2MM 输入/完成计数器；若要源帧周期，还要与相机 SOF 对拍 | 捕获端收帧周期、掉帧/积压 | 否；捕获可能丢帧、延迟或重新定界 |
| VDMA MM2S READSTR 切换 | MM2S PARKPTR.READSTR 的读帧存编号变化 | AXI-Lite 寄存器轮询；事件时间由 PS GT 在轮询代码中观测 | 显示读端帧存选择变化周期 | 否；它位于显示读通路 |
| HDMI 显示刷新 | HDMI 输出 VSYNC/帧边界；同时记录 DE/像素时钟配置 | HDMI TX 像素时钟域/VTC/axis_to_video；最好观测最终输出边界 | 显示链输出刷新周期 | 否；与 MM2S 指针沿的对应关系需另行证实 |
| 推理完成 | 实际推理/解码完成事件；若使用结果块 inf，需是可信 GT 时间戳 | 推理核心 DONE/中断或真实生产端 GT inf | 推理完成率及推理耗时 | 否 |
| 结果发布 | 一致性协议完成后结果可被消费者读取的时刻 | 已冻结 sidecar result_time / GT | 交互层可消费结果的发布时间/年龄 | 否 |

不同事件可有相同的名义频率，但不能因此视为同一事件。若一条链路宣称它们一一对应，必须提供同窗计数、帧 ID 或信号边沿对拍，并报告差值和丢帧情况。

### 复算

vdma_ctrl.c 的 S5Vdma_MeasureReadPeriod() 先读取一次当前 READSTR，随后在运行的 A9 上轮询该寄存器。每次发现编号变化后读取 GT；6 个沿取首沿至末沿的 GT 差并除以 edges - 1 = 5。s5_display_app.c 把 S5_GT_HZ 作为时间换算频率，并对微秒输出作整数截断：

    平均周期 ticks = (t_last - t_first) / 5 = 5,557,890
    GT 名义频率     = 333,333,343 ticks/s
    未截断周期      = 5,557,890 × 1,000,000 / 333,333,343
                    = 16,673.669516 µs
    UART 整数输出   = floor(16,673.669516) = 16,673 µs
    相对 60 Hz 理想周期 16,666.666667 µs = +0.042017%

复判 JSON 用已截断的 16673 µs 得到 +0.038%；使用原始 tick 数复算为 +0.042017%。二者均在该记录所用的 ±1% 显示周期门限内。此处的“原始值”仅指 UART 保留的 tick 汇总数，**不是**原始逐沿 GT 样本。

实现的采集数是 6 个被观察到的指针变化、共 5 个计算间隔。S7b_frmcnt_output.txt 的 1500 条记录读的是 VDMA CR/SR，结果恒定且无沿，不能算作 1500 个 P 样本。UART S5DISP frame 斜率另为约 33,364.67 µs（约 30 Hz 软件更新节拍），不是 60 Hz 显示读周期，更不是相机 SOF 或真实推理完成节拍。

由整除后的 5,557,890 ticks 可反推沿间总跨度约为 27,789,450 ticks（83,368.348 µs）；由于 C 整数除以 5 丢弃余数，原始首末差也可能是 27,789,451 至 27,789,454 ticks。该跨度是从汇总值反推，不是留存的 GT 起止样本。UART 更新斜率另有 73 行、59 对、帧计数差 3480、主机时间跨度 116.109 s；它不能扩充成 16673 µs 的样本数。

因此，16673 µs 可以按其来源记为“本次 P3q 运行中，软件轮询读帧存切换所估的显示读周期”；不应改写成“相机 60 fps”“相机 SOF 已实测”或“推理周期 16.673 ms”。阶段6记录中后续 r12 运行还出现 READSTR 不切换、fps_dis=0、P 未测得，说明该软件测量依赖该运行的指针变化可见性。

## 误差预算与当前不可量化项

周期换算式为 P = ΔGT / (N × f_GT)。频率误差按相反方向近似线性传递：|δP_f|/P ≈ |δf_GT|/f_GT。以下只对已有证据可支持的项给出数值；缺少逐样本证据的项不虚构上限。

| 来源 | 当前可给出的量化 | r03 是否有界 | 处理 |
|---|---:|---|---|
| GT 计数分辨率 | 1 / 333,333,343 s ≈ 3.000 ns；首末计数差量化小于约 1 tick，按 5 间隔均值贡献小于 0.6 ns | 是，按名义频率 | 保留 tick 整数值，避免只用显示出的整微秒 |
| 整数 tick 除以 5 | C 整数除法截断小于 1 tick，即小于约 3.000 ns | 是 | 若要亚微秒精度，输出余数/有理数，不只打印整数 tick |
| 微秒打印截断 | 小于 1 µs；本例精确换算比打印值高约 0.670 µs | 是 | 用原始 ticks 离线复算 |
| 轮询相位与 GT 读数延迟 | 对首末两个边沿时间戳，若每沿总观测延迟在 [0,L]，5 周期均值端点误差最多约 L/5 | **否**；无每次 poll/GT 数据、无实测 L | 新采集保存完整 poll 间隔与每读 GT 前后界；不声称已有数值上限 |
| AXI-Lite 读延迟/可见性 | 代码经 MMIO 读取寄存器；其延迟变化会进入沿检测延迟 | **否**；证据未含总线读时延或 MMU 属性记录 | 确认 VDMA 页为设备型映射，记录每次 GT 前/后值；禁止把缓存命中假设当证据 |
| 停核/XSDB 影响 | r03 的六沿估计在固件内核运行时完成；XSDB GT 开窗/收窗值只用于整窗校验，不是沿时间戳 | P 估计未停核；整窗 GT 不提供沿抖动 | 采集期间不 halt CPU；有停核、复位、重连或缓冲溢出即切断该段 |
| 漏沿/循环指针别名 | 两帧缓冲 READSTR 可能 0/1 往返；两个沿在相邻轮询间发生会回到同一值 | **无界**；未留最大轮询间隔和完整指针序列 | 改用单调 SOF/帧计数器，或证明每次实际读之间的最大时间小于独立验证的最短事件周期 |
| 聚合与抖动 | 6 沿只给出 5 间隔的均值；无逐沿时间戳 | 无法给标准差、最小/最大或尾部延迟 | 新采集至少保存每沿/每计数样本；只保存均值时不得报告 jitter/置信区间 |
| GT 频率校准 | 100 ppm 的频率不确定度会给 16.67 ms 周期带来约 1.67 µs 不确定度 | **否**；333,333,343 是软件换算常量，本次无独立校准 | 绑定时钟树证据及频率容差；不得用 r03 的“host wall approx”校准 |
| 事件语义差异 | 本次源为 MM2S 读帧存变化 | **不能用数值误差预算覆盖** | 这是被测量定义不同，必须换成相机 SOF 事件才能得到相机 P |

r03 复判文件记录 GT 窗口 49,968,139,163 ticks / 333,333,343 = 149.904 s，同时注明主机墙钟约 120 s 且未精确记录。这个粗略墙钟既不是同边界高精度校准，也不能据此推导 GT 的 ppm 误差。

## CSV 与分析程序

analyze_frame_period.py 只在本机离线读取 CSV，计算结果写到标准输出，不接板、不启动 XSDB/Vivado。CSV 一次只放一种事件、时钟、计数器和样本类型：

    sample_index,event_kind,sample_kind,counter_type,counter_modulus,counter_value,clock_id,gt_before,gt_after
    0,camera_sof,counter_snapshot,monotonic,4294967296,100,zynq_gt,123456700,123456710
    1,camera_sof,counter_snapshot,monotonic,4294967296,101,zynq_gt,129012200,129012211

- counter_snapshot：每行是一回计数器读。gt_before/gt_after 是围住这次 MMIO 读的 GT 值。单调计数器以首末时间跨度除以累计计数增量估平均周期，并用 D±1 周期相位项和 GT 读界给保守范围。
- event_bracket：每行的 gt_before/gt_after 直接界定一个事件时刻；相邻事件间隔按两个界相减。若由轮询构造，必须保守使用“上一次读到旧值的 GT 下界”至“本次读到新值的 GT 上界”，不能把本次读寄存器前后两值伪称为 SOF 事件边界。每行必须对应相邻事件，计数差必须恰为 1；差为 0 或大于 1 时拒绝整组输入，不给逐事件 bracket 或周期实测值。
- counter_type=monotonic 用于不回绕的递增计数器，数值回退/回绕时拒绝输入，须把回绕前后的数据分段；工具不按模数推断回绕次数。cyclic_pointer 用于 READSTR 这类循环地址/帧存编号。周期指针默认不形成实测值；需给出独立来源的最短事件周期，并确认 max_read_gap_upper_ticks < min_event_period_ticks，且观测周期区间与此下界不矛盾，才会标记为有条件排除别名。该界还要求每个采样间隔至多发生一个事件，因此模增量大于 1 与界矛盾时拒绝输入，不能选定一个“唯一回绕”解释。
- event_kind 允许 camera_sof、vdma_s2mm_frame、vdma_mm2s_readstore、hdmi_vsync、inference_done、result_publish。工具不会根据事件名称证明硬件连接或业务语义。
- origin 必须显式指定为 captured 或 synthetic。合成演示仅输出 observed_period_us，永不填写 measured_value_us。即使标成 captured，工具也要求人工核对采集身份。
- `--min-event-period-us` 只接受有限正数；NaN、正负 Infinity、零、负数或不能解析的值由 argparse 拒绝，退出码为 2，并在标准错误输出 `claim_status=INVALID_INPUT_NOT_MEASURED`、`measured_value_us=null` 的 JSON 结果。

示例：

    & 'C:\Users\22061\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' -B .\analyze_frame_period.py .\camera_sof.csv --gt-hz 333333343 --origin captured
    & 'C:\Users\22061\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' -B .\analyze_frame_period.py --demo --gt-hz 1000000

第一条命令只应在 CSV 确实是相机 SOF 事件计数/时间界时使用。第二条是合成例，不是采集结果。程序的区间表达与单元测试不替代独立审查或阶段验收。

### 采集前

1. 固定本轮实际用到的工作树提交、阶段4输入采集路径、位流/XSA/ELF 身份、传感器型号及 VSYNC 极性来源；逐字绑定文件哈希和 RunId。

3. 首选在相机输入边沿处使用现有的单调硬件帧起始计数器；另行统计 S2MM 接受的帧起始/完成计数，以核对掉帧。若当前 PL 没有可读的相机 SOF 计数器或时间戳设施，先登记仪器/设计依赖与审批，不在本任务临时改 PL 或冻结设计。
4. GT 频率取自与本次位流/PS 配置匹配的时钟树与 BSP，记录 gt_hz、来源文件哈希及容差。只读取 GT/状态，不以 XSDB 停核后的人工轮询当成逐沿采样。

### 采集窗口

1. 依阶段6板窗规则由当时租约持有人起会话；确认设备身份、PL/应用 SHA、相机在流、GT 单调递增。任何连接异常、身份不符、复位、停核、计数器复位或采集缓冲溢出都立即停止并把该段标作无效/未执行。
2. 先稳定运行 5 s，再用内存环形缓冲保存至少 60 s 或 1000 个相机 SOF（取较晚者）的数据；不要逐沿 UART 打印或让宿主端频繁 mrd。采集内容至少包括单调 SOF 计数、读取该计数时的 GT_before/GT_after、样本序号和最大轮询间隔。需要 jitter 时，必须保存无损逐沿时间戳/FIFO，而不是只保存开始/结束计数。
3. 同窗独立保存相机 SOF、S2MM 接受帧、MM2S READSTR、HDMI 输出 VSYNC、真实推理完成/发布序号；时钟 ID 分列，不合并为一个“帧”。若当前结构无法观测其中某事件，显式记 NOT_AVAILABLE，不得补推。
4. 采完后再读取缓冲和结束 GT，不在测量期间 halt 核。保存原始 CSV、串口摘要、源/位流清单、工具版本、命令/退出码及每个文件 SHA-256。新 manifest 的哈希项声明 hash_basis，仓库文件优先 commit_blob。
5. 离线跑分析器并复核样本数、GT 跨度、单调计数差、循环指针别名检查、相机 SOF 与 S2MM 计数差、丢失/重复边沿和周期区间。只有确认 event_kind=camera_sof 且计数来源/映射被证据证明，才把相应相机周期候选交给阶段6总控判断是否满足 T6-A03 前置。

### 预期输出与异常

- 应有相机 SOF 计数单调、GT 跨度为正、样本窗口与频率来源完整；对 event_bracket 给出每间隔界，对长窗单调计数给出均值及相位/GT 区间。
- 若 SOF 与 S2MM 接收计数不同，报告捕获掉帧/重帧，不可将 S2MM 完成周期直接等同传感器 P。
- 若样本没有相机 SOF、只有 READSTR，输出只能标成显示读帧代理，T6-A03 继续 NOT_RUN。
- 若计数不递增、GT 回退、循环指针最大采样间隔不足以排除别名、无计数频率/容差依据、样本源为合成或事件时间界缺失，输出 NOT_ESTABLISHED；不填补周期、不按显示刷新代替。
