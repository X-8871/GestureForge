## 2. 7-A：现在先建验收矩阵与预算

1. 把每项正式要求映射到来源、版本、测试ID、输入、阈值、证据、状态和责任阶段。
2. 为每个正式配置绑定模型/权重/cfg/预处理/量化/后处理阈值、输入分辨率/颜色、bit/XSA/ELF、软件源码和板卡。
3. 收集实际集成设计的LUT/FF/BRAM/DSP、时钟/约束、DDR地址和带宽预算。2A OOC余量只能提示风险，不能当集成通过。
4. 分项计算采集、预处理、权重/特征图、PS、显示读写、缓存维护流量与同时存活内存；注明峰值与平均的公式及测量方法。
5. 从2B/阶段4实测提出检测吞吐下限、采集到结果及必要显示端到端P99上限、ARM对照目标，交Wong冻结。旧20FPS/100ms/3—5倍不自动恢复为现行目标。
6. 100次预热作为历史方案的起点，在本次G0确认并锁定；每个正式性能配置≥10000次有效任务是阶段计划要求。样本、重复次数及计时边界先确定，测试后不改阈值。

## 3. 7-B：集成版本与时序资源关

1. 由单一集成写入者消费阶段3—6冻结交付，核对接口与依赖组合。阶段5独立显示bit和2B推理bit不能交替下载后声称同一系统集成。
2. 用实际器件目标 `xc7z020clg400-2` 和经实物资料核验的约束构建；历史XA/-1结论只作历史，不混算。
3. 运行适用RTL/软件回归，验证集成后数值语义仍一致。
4. 单个重型实现作业完成后，从同一实现版本出LUT/FF/BRAM/DSP四项利用率、setup/hold、时钟/CDC及约束报告。
5. 初始资源目标各≤85%；WNS/WHS≥0、TNS/THS=0；若既有正式批准有变更，引用明确记录。超限需处理或Wong批准规格变更，不擅自豁免。
6. 对未约束路径、时钟关系和方法学critical逐项说明/关闭。零DRC不等于完整时序签核。

输出：集成清单、地址/带宽预算、实现报告、数值回归、独立审查。bit/XSA/ELF必须是同一可复现构建组合。

## 4. 7-C：性能测量

### 注入阶段

可先做以下测量，但标 `source_kind=injection`：
1. 固定输入序列、随机种子及发送速率；分别记录计划输入、实际接收、丢弃、成功推理、超时/错误。
2. 为每帧记录预处理、PL、PS解码/NMS、排队、显示提交/呈现边界。
3. 每正式配置≥10000次有效任务，预热与失败另列。报告有效吞吐及所有提交任务的成功/失败比例，不能筛快样本。
4. 统一单位与计时源，报告mean/P50/P95/P99、最大值与样本数。不能将互不同时的阶段P99相加当端到端P99。
5. 日志开销做对照测量；串口逐字打印可能改变结果，采用缓冲导出并验证不丢记录。
6. 与ARM对照使用同模型/输入/数值与明确计时范围；模型本体与完整系统分别比较。

### 摄像头阶段

阶段3—6相关前置通过后，用同一冻结配置重测真实采集链：
- 采集/推理/显示不同计数分别报告。
- 若只测到显示提交，不能命名为屏幕呈现延迟；物理呈现使用已验证事件/外部测量方法。
- 吞吐、P99、精度和ARM目标全部按批准值判断；指标尚未冻结时只报测量，不报最终PASS。

### 若做优化

优化前后模型、输入、精度、工具与测量范围一致；每方案至少3次独立运行，收益方向一致，零数值不匹配。调整时钟、缓存、架构分别说明影响；未达到收益不隐藏。

## 5. 7-D：稳定性、异常与恢复

1. 在正式集成配置连续≥1小时，无死机、持续内存泄漏或未解释错配；同时保留帧号/动作/错误/温度等可获得数据，未测项明示。
2. 为每种已定义故障注入≥20次：无输入、超时、坏长度/非法参数、队列满、重复/乱序、软件接口中断等；仅做设计支持且经授权的注入，不默认物理热插拔。
3. 每次核对错误检测→停止使用坏/旧结果→已知状态→新任务恢复；记录实际恢复耗时。
4. “超时后500ms进入已知状态、外部输入恢复后2s恢复任务”为原计划建议，按实际启动成本在G0冻结；不能以这两个值已被本文写出就宣称批准。
5. 验证宣称的运行时配置切换，保留前后bit哈希一致证据；需要重烧bit的切换不能叫同位流运行时切换。
6. 失败时保全该RunId原始证据，排查后新RunId完整复测受影响项；最终证据要体现失败关闭关系。

## 6. 7-E：清洁重建与恢复演练

1. 在明确授权的干净副本/环境按固定源码提交、子模块/依赖、工具版本、许可证能力、模型与归档清单恢复；不得reset/clean共享树。
2. 按正式构建入口重建PL、平台/BSP和应用。若某组件只能复用二进制，明确列为不可从源码重建限制，不能声称全量重建通过。
3. 保存完整命令、耗时、峰值内存、日志、退出码和产物SHA。二进制哈希不一致时检查工具/非确定性来源并按验证策略确认，不自动判断等价。
4. 在独占且获授权硬件上完成约定重建产物板测；仅编译成功不能代替恢复演练。
5. 演练从文档找到已验证的备用bit/ELF、核对哈希、恢复运行；记录操作者、步骤、耗时、异常停止点。
6. 由独立Reviewer按照文档检查/复现适用步骤，关闭缺失依赖、隐含环境和不可用旧缓存路径。

## 7. 7-F：演示与发布包

演示分清三种素材：
- 预录展示视频：解释已有结果，不作为本次实时运行证据。
- 板上注入回放：画面醒目标注输入为回放；现场显示frame_id、真实运行状态与实测指标。
- 现场摄像头：新手势/新顺序现场响应，保留失败与响应延迟，才支撑现场实时交互。

发布包至少含源码提交、配置/模型/权重来源与哈希、XDC、构建/测试/运行脚本、工具依赖、bit/XSA/ELF及清单、完整验收矩阵、性能/精度报告、恢复手册、演示和故障预案。大文件按已有归档规范交付，不强塞Git；不能只交Git元数据却缺恢复必需二进制。
