# B25 裁决：帧号/会话语义（2026-10-29，DSH 项目总控）

## 裁决
**采用口径 1：与阶段4 冻结契约一致。** 不采用"同会话大幅回退即复位"，因为"大幅"未被定义、无法形成稳定判据，且会给阶段6 引入一个与冻结契约不一致的隐式阈值。

## 规则（阶段6 必须按此实现与出文档）
- **R1 同会话严格递增**：同一 `session_id` 内 `frame_id` 必须严格递增（按 32 位无符号序）。**任何减少——无论 1 还是任意大——都是在状态改变前拒绝的 `OUT_OF_ORDER` 异常**；不得复位、不得推进、不得改写会话状态。
- **R2 唯一允许的回绕**：`0xFFFFFFFF → 0x00000000` 视为同会话内合法续排（递增 +1，模 2^32），前提是同一 `session_id` 且期间无复位。
- **R3 `0xFFFFFFFE` 不是特殊值**：不得为它设置"接近回绕"的特殊分支。`0xFFFFFFFE → 0xFFFFFFFF` 正常；`0xFFFFFFFE → 任意更小值` 一律按 R1 拒绝。**文档与机器规格必须统一到这一条**，不得一份写 0xFFFFFFFE、一份写 0xFFFFFFFF 作为两套语义。
- **R4 复位必须换会话**：计数器复位/重启 ⇒ **必须使用新的 `session_id`**。同会话内不定义"复位信号"；阶段6 不自行发明重启信号。
- **R5 变更须走契约流程**：若将来确实需要"同会话重启"，须先修订阶段4 冻结契约并独立复审，**不允许阶段6 自行定义阈值或信号**。

## 对 Codex/阶段6 的具体要求
1. 按 R1–R4 调整实现、文档与测试矩阵；保留"**在状态改变前拒绝**"这一已有正确行为；
2. 增补回归：①回退 1 帧 ②回退 N 帧 ③回退到更小值 ④`0xFFFFFFFF→0` 允许 ⑤`0xFFFFFFFE→0` 必须拒绝 ⑥新 `session_id` 复位允许；
3. 把"`0xFFFFFFFE` 在文档与机器规格间的表达差异"作为**勘误**提交（列明文档路径/原文/改为哪条），**不改冻结契约来源**；
4. 明确：本轮离线修复与验证**不代表 6-B 全部验收或阶段6 G5**，未上板结论照旧标注。

## 边界
- 本裁决只确定阶段6 内部实现口径，**不修改阶段4 冻结契约**；
- 不授权上板、不改 `ENABLE=0`、不 push；
- 若阶段6 认为无法按 R1–R4 实现，须回执说明具体冲突点，由 DSH 重新裁决，不得静默偏离。
