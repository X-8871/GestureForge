# 更正：帧号回绕策略以阶段4 r07 冻结契约为准（2026-10-30，DSH 项目总控）

## 1. 冲突事实
- 阶段4 **r07 冻结契约**：同会话内 `frame_id` **回绕/回退一律拒绝**；
- 我方 `DSH-20261029-004` 的 **R2** 写成"唯一允许 `0xFFFFFFFF → 0x00000000`"——**与冻结契约直接冲突**；
- 阶段6 已按冻结契约实现，并据实指出该冲突，**未擅自实施冲突规则**（做法正确）。

## 2. 更正裁决（生效）
**以阶段4 r07 冻结契约为准：同会话内任何回绕与回退，一律在状态改变前按 `OUT_OF_ORDER` 拒绝（含 `0xFFFFFFFF → 0x00000000`）。**

- **撤回** `DSH-004` 的 **R2**（作废，不再有效）；
- `DSH-004` 的 **R1/R3/R4/R5 维持**：
  - R1 严格递增、任何回退拒绝；
  - R3 `0xFFFFFFFE` 无特殊性（按倒序拒绝）；
  - R4 计数器复位/重启必须新 `session_id`；
  - R5 改契约须走冻结修订 + 独立复审。

## 3. 理由
1. **单一事实源**：冻结契约是上游权威，不为一个极端边界值反向改契约；
2. **可达性**：2^32 帧 @2 fps ≈ 68 年，竞赛窗口内不可达；为不可达边界引入例外只会增加口径分叉；
3. **一致性**：若计数器真到顶，正确做法是**换新 `session_id`**（与 R4 一致），而不是在旧会话里"绕过回绕"。

## 4. 与 H3 单调时间推进规则的协调
- 拒绝必须发生在**任何状态改变之前**：不推进 H3 单调时间、不更新 `last_accepted_frame`、不写账本/回执、不产生序号空洞；
- H3 仅在**接受**的帧上推进；被拒帧**不占序号、不留洞**；
- 拒绝结果可记录为**异常计数/日志**（不改变会话状态机状态）。

## 5. 对阶段6 的要求
1. 回归补/改：`0xFFFFFFFF → 0x00000000` **必须拒绝**；`0xFFFFFFFF → 新 session_id 的 0` **允许**；其余倒序继续按拒绝；
2. 文档勘误：把"回绕"表述统一为"同会话回绕一律拒绝；计数到顶须新 `session_id`"；
3. 仍不闭合项：**6-C 的 C11 与 strict 哈希检查失败**未解决 ⇒ 6-C 整体不可称通过；离线 ≠ 阶段6 G5；未上板。
