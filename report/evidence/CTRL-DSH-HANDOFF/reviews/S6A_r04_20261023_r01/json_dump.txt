============================== hard_invariants ==============================
H-1 :: 状态机核心的输入是一条结果记录 + 显式单调时间 + session_id，输出是状态转移与动作请求；核心不得直接读摄像头、系统墙钟、HDMI 或任何硬件寄存器。
H-2 :: 动作执行层单独隔离，负责提交动作并返回 success/fail/unobserved 与生效时刻；日志保留 action_id 与来源 frame_id，防止重复发送导致重复动作。
H-3 :: 所有超时/失踪/冷却/窗口计时按单调时钟推进；停帧、重复帧或丢弃帧不得把状态永久卡在候选；系统墙钟不得参与任何判定。
H-4 :: 窗口序列按结果条数推进，仅由 state ∈ {OK, NO_HAND}、stale=false、非重复、非倒序的结果推进；匹配计数只由 WINDOW_MATCH 成立的结果推进。NO_HAND 推进时间与结果计数、不推进匹配计数、不得完成稳定窗口；TIMEOUT/ERROR/DROPPED 不推进序列与匹配计数，但必须推进时间并计入异常。
H-5 :: NO_HAND 是合法零框，不是第六类、不是未知、不是错误；不得改写为未知，也不得把其他空标签改写为 NO_HAND。
H-6 :: 不得以 class_id 落在五类内证明未知拒绝；未知拒绝只能由独立未知样本上未发生已提交动作的统计支撑，样本必须包含高分误识别场景。
H-7 :: 所有测试的预期序列必须由行为表独立推导或人工手算；禁止运行状态机生成 expected 后自我比较。
H-8 :: ACTION_SUBMITTED（提交成功）与 ACTION_EFFECTIVE（实际生效）是两类事件，必须分别记录与统计；提交成功不等于生效，仅触发未生效不得算成功。
H-9 :: 本阶段不得触碰板卡/JTAG/COM4/hw_server/HDMI 实物/摄像头，不得烧录。
H-10 :: 冷却全局门：自最近一次真实提交 t_last_submit 起 T6-K01 内，任何状态、任何获取（含目标丢失后重获、异常恢复、目标切换）都不得提交动作；展示状态 COOLDOWN 因丢失/异常提前退出不解除该门；被抑制或失败的提交尝试不更新 t_last_submit；动作执行层在提交前再次校验。
