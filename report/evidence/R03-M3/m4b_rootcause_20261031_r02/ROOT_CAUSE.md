# R-03：47.3秒与旧“heads零差异”疑点的离线根因

结论：**诊断PASS，真实M3成对取样仍BLOCKED**。旧失败窗口把“没有执行比较时的初始化零”写入diff字段，并且当时实际部署的ELF超时常量远低于源码假设。两者叠加产生了表面矛盾；本轮没有修改冻结应用或重跑历史板上数据。

## 1. 固定失败对象的实际ELF是400周期

失败窗口 `w4/report/evidence/S4-T34/s4d_m4b_baseline_2b_20261029_r01` 的IDENT绑定ELF SHA：`ada4b30d98298ec9cea053d97d01e9fea91ae97e70c8a13f7be1bc36079445a7`。本轮对这一精确原件做反汇编，exit0：

- `0x103664/0x10366c` 将r4恢复为 `0x43C00000`；
- `0x103738`：`mov r2, #400`（十进制400，即 `0x190`）；
- `0x10373c`：`str r2, [r4,#40]` → core_timeout `0x43C00028`；
- `0x103744`：同一r2写 `[r4,#44]` → drain_timeout `0x43C0002C`。

所以该失败对象在50MHz下的超时是 **400/50,000,000＝8µs**，不可能等待47.3秒完成。原 `app_elf_registration_r3.json` 也明确记录“旧r2的400周期必然CORE_TIMEOUT”，与真实ELF一致。它不是其他陈旧ELF中提到的 `0x40000000`（21.47483648秒），更不是当前源码的 `0xFFFFFFFF`（85.8993459秒）。不同ELF身份必须分别讨论。此前r01粗略计算了0x40000000；该旧分析保留，由本r02明确更正。

## 2. 失败时diff=0不是实测相等

原UART为 `done=2 / error=5 / pass=0`，打印 `STEP=7 compare heads (done=2)` 后，**没有**真正的 `M4B HEADS diff13=...` 行。

历史源码固定提交 `6c09df12c585568b2737da2116fe43913e0062cb`：d13/d26初值均0，逐字节比较放在 `if (done == 1)` 中，最终RESULT仍无条件打印这些字段。旧ELF控制流也支持这一点：错误终态走 `0x103904→0x103814`，在 `0x103820` 把r7置零并跳过 `0x103954` 开始的invalidate与比较循环，再进入RESULT打印路径。因此旧失败记录的0仅表示**未计算**。

不应以该0推断网络已算完，更不应据此怀疑RTL elapsed计数器。建议未来另立非冻结修订，增加 `comparison_performed` 或将未计算的差异字段输出为null；本轮不改冻结代码。

## 3. 后续47.287秒与零差异是另一组有效证据

本轮逐份复算3个既有成功窗口，均有真实HEADS比较行、`pass=1/done=1/error=0/diff13=0/diff26=0/stale=1`，elapsed均 **47,287ms**：

| 历史RunId | 口径 |
|---|---|
| s4d_m4b_close_20261029_r01 | 2B基线，补齐参考并投毒 |
| s4d_freeze_r2_m4b_2b_20261029_r01 | 2B冻结回归 |
| s4d_freeze_r5_m4b_p2d_20261029_r02 | P2d合并体回归 |

三者尾word均 `0x5A5A5A5A→0x5A5A0506`，`lane01_ok=lane23_ok=1`：有效尾2字节已重写，高2字节保持。head13参考5070B必须补齐到5072B/1268字预置，1267字只写5068B的旧宿主缺陷另有既有证据，不能归咎PL尾lane。

这些是**3份历史窗口的离线复算**，不是本轮新采样，不把同一fixture重复运行当泛化统计；未证明全部输出字节的每次写事务或实时吞吐。47.3秒推理与60Hz显示更新也属于不同事件。

## 4. 本轮边界与恢复

本轮M3板窗只占约59.5秒，因CPU0初始Running而停止；before/after均NOT_RUN，不能宣称M3已关闭。另见 `m3_pair_20261031_r01/INCIDENT.md`。历史候选区6bit变化的具体成因没有被本次窗口排除。

机器复算见本目录 `analysis.json`，旧ELF反汇编 `old_elf_disassembly.txt`，历史源码快照、r3登记副本与4份原始UART字节均保留。analyze_m4b.py只读上游，并要求全新RunId；再次运行必须另立RunId，不覆盖本包。
