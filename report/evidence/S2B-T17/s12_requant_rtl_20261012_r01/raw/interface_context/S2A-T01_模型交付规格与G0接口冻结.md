## 2. 算子、逐层张量与地址

冻结 cfg 有 38 个网络层：21 个卷积、route、maxpool、upsample 与 2 个 YOLO 输出视图。算子只按 cfg sections `1..38` 执行；层号、精确输入引用、属性、输入输出 NCHW 形状、输入输出 scale、INT8 权重和 bias 参数偏移、张量长度及地址，全部列在 [`tiny416_model_manifest.json`](../../../../report/evidence/S2A-T01/tiny416_model_manifest.json)。该清单由 [`s2a_model_delivery.py`](../../../../verification/s2a_model_delivery.py) 从当前 cfg、GF8 包、512 张校准报告与阶段一报告绑定生成。

模型统一 NCHW、单图、逐元素 INT8。route 按 cfg 引用顺序处理来源张量；`groups=1` 时选取完整 C 轴，`groups>1` 时要求仅一个来源且沿 C 轴先切片 `[group_id*C/groups:(group_id+1)*C/groups]`，再按最大来源 scale 重标定并沿 C 轴拼接。tiny416 的 cfg section 4（layer 3）取输入通道 `[32,64)`，section 12（layer 11）取 `[64,128)`。upsample 为最近邻复制；maxpool 按冻结 cfg 的 Darknet size/stride/padding 公式执行；YOLO 层是其前一卷积张量的零拷贝视图。任何未支持 section、groups 或参数不匹配都必须显式报错。

2A 使用 32 位字节寻址的逻辑仿真空间，地址固定如下：

| 对象 | 起始地址/范围 | 说明 |
|---|---|---|
| 输入图像 | `0x00000000`，519,168 bytes | `[1,3,416,416]` CHW INT8 |
| GFINT8W1 参数包 | `0x00100000`，5,903,100 bytes | 包含每卷积层逐输出通道 scale、折叠 bias 和 INT8 权重 |
| 网络特征张量 | `0x01000000` 起至 manifest 的 `end_address_exclusive` | 每层输出独占区间，起始 64-byte 对齐；两个 YOLO 视图与来源卷积共享地址 |
| 检测头 13×13 | manifest `head13.address`，5,070 bytes | `[1,30,13,13]`，stride 32，scale=`0.24267549589862975` |
| 检测头 26×26 | manifest `head26.address`，20,280 bytes | `[1,30,26,26]`，stride 16，scale=`0.30223452951025775` |

这些是 2A 仿真地址。它们不映射到 AX7020 DDR 的物理地址，也不声称完成峰值存储或 Vivado 资源预算。输入/权重/张量的起始地址加长度必须在 32 位地址空间内、不重叠；特征区间中的 64-byte 对齐空隙不是有效对象、不得访问，所有选中字节都必须落在同一个对象或逻辑张量的半开区间内，否则返回 `BAD_RANGE`。

GFINT8W1 头为 little-endian，字段与各层参数偏移由模型清单给出。首层与每层卷积权重均使用每输出通道 INT8；清单同时提供该层 scale、折叠 float32 bias、量化后 INT32 bias。若 cfg、weights、GF8、激活校准证据或清单源码 SHA 任何一项变化，回退 G0 并重建清单和黄金结果。

## 3. PS/PL 控制和 buffer ownership

2A CSR 仿真接口固定为 `csr_valid/csr_ready/csr_write/csr_addr[7:0]/csr_wdata[31:0]/csr_rdata[31:0]`，单 outstanding；`csr_valid/csr_write/csr_addr/csr_wdata` 由 PS 驱动，`csr_ready/csr_rdata` 由 PL 驱动。在上升沿 `csr_valid && csr_ready` 接受一次访问，读值在同周期 `csr_rdata` 返回，不另设响应通道。非硬复位时 `csr_ready=1`。PS 每次接受后必须撤销或更新 valid，避免重复写。CSR 为 2A 仿真寄存器契约，不冻结 AXI-Lite 物理引脚。控制字段宽 32 bit little-endian；地址按 32-bit 对齐，未对齐或保留地址读回 0，写入被忽略；写 RO 字段被忽略。PS 在 idle 时配置命令字段，写 `CMD.start` 发起一个任务；PL 接受有效命令后置 `busy=1` 并取得输入、权重读取权限及 feature/head 写权限。busy 期间 PS 不得改写这些 buffer 和命令字段；非 PS 所有权且 busy/done/error 全清之外的配置写均忽略。完成后 PL 先写两个检测头与 frame_id，再清 busy、置 done、归还所有权；出错时清 busy、置 error、清 done、归还所有权，head 数据标为无效。done/error 互斥并保持到各自 ACK 或复位。PS 清状态后才开始下一任务。

| 偏移 | 字段 | 访问与语义 |
|---:|---|---|
| `0x00` | CMD | W1P bit0=`start`，W1P bit1=`soft_reset` |
| `0x04` | STATUS | RO bit0=`busy`、bit1=`done`、bit2=`error`、bit3=`pl_owns_buffers` |
| `0x08` | ERROR_CODE | RO：0 `NONE`、1 `BAD_ARGUMENT`、2 `BAD_RANGE`、3 `BAD_LENGTH`、4 `UNSUPPORTED_OP`、5 `TIMEOUT`、6 `INTERNAL`、7 `ACCUMULATOR_OVERFLOW` |
| `0x0C` | FRAME_ID | RW while idle；PL 接受 start 时锁存，随 done 结果返回 |
| `0x10` | INPUT_ADDR | RW while idle；本冻结要求 `0x00000000` |
| `0x14` | INPUT_BYTES | RW while idle；必须为 519,168 |
| `0x18` | WEIGHT_ADDR | RW while idle；本冻结要求 `0x00100000` |
| `0x1C` | WEIGHT_BYTES | RW while idle；必须为 5,903,100 |
| `0x20` | FEATURE_BASE | RO；`0x01000000` |
| `0x24` | FEATURE_LIMIT | RO；manifest `end_address_exclusive` |
| `0x28` | TIMEOUT_CYCLES | RW while idle；从有效 start 接受周期起计数，必须大于 0 |
| `0x2C` / `0x30` | HEAD13_ADDR / HEAD13_BYTES | RO；由 model manifest 驱动 |
| `0x34` / `0x38` | HEAD26_ADDR / HEAD26_BYTES | RO；由 model manifest 驱动 |
| `0x3C` | ACK | W1P bit0 清 done；bit1 清 error 和 ERROR_CODE |

硬复位为同步高有效，硬复位时 `csr_ready=0`、`mem_ready=0`；复位期间的任务中止、busy/done/error 清零、缓冲所有权回到 PS、head 输出无效。被接受的 `soft_reset` 具有相同事务语义；若 CMD 同时写 start 和 soft_reset，soft_reset 优先并丢弃 start。`start` 在 busy 或 done/error 尚未 ACK 时被忽略，不改变当前任务或状态。非法长度、错误固定地址或零 timeout 在 start 校验时返回相应错误，非法请求不取得 buffer 所有权。timeout=N 必须大于 0；从 start 接受沿之后开始计数，完成可使用 N 个 PL 时钟周期，在第 N 个后续上升沿完成则完成优先，否则该沿超时并中止；因此 timeout=1 恰给任务一个完整执行周期。同步硬复位优先级最高，其次是 soft_reset、参数/存储/数值错误、正常完成、timeout。INT32 溢出由逐步 INT64 精确和检查，任务报 `ACCUMULATOR_OVERFLOW`，head 输出无效，不允许二补码回绕。reset/timeout 会撤销尚未握手的 memory 请求，且之后不得出现延迟写副作用。ACK 或复位后必须能接受新的合法 start；timeout 周期由测试命令固定并记录，不设隐含常数。

PL 内部算子后端到控制 FSM 的完成事件固定为 `operator_result_valid/operator_error_code[2:0]`，不是 PS 外部引脚或 CSR。后端在上升沿 busy 时给出单周期 valid 脉冲且无 backpressure，错误码同沿稳定；code 0 表示 feature/head 写入已完成，控制 FSM 提交 done；已知非零项目错误码 1..7 原样结束任务，未知非零码转成 `INTERNAL`，并使 head 无效、归还 PS ownership。该事件在 timeout 第 N 个后续上升沿到达时优先于 timeout；code 0 成功完成，非零码按错误完成。

start 参数错误码固定为：`INPUT_ADDR != 0` 或 `WEIGHT_ADDR != 0x00100000` 返回 `BAD_RANGE`；输入/权重 byte 长度不等于表中冻结长度返回 `BAD_LENGTH`；`TIMEOUT_CYCLES == 0` 返回 `BAD_ARGUMENT`。错误 start 不取得 PL buffer 所有权。`FRAME_ID` 是任意 32-bit 不透明值，PL 原样回传。

2A memory testbench 接口采用单 outstanding 32-bit word 请求：`mem_valid/mem_ready/mem_write/mem_addr[31:0]/mem_wdata[31:0]/mem_rstrb[3:0]/mem_wstrb[3:0]/mem_rdata[31:0]/mem_error_code[2:0]`。`mem_valid/mem_write/mem_addr/mem_wdata/mem_rstrb/mem_wstrb` 由 PL 驱动，`mem_ready/mem_rdata/mem_error_code` 由 testbench memory model 驱动。地址为 32-bit 字节地址，`mem_addr[1:0]` 必须为 0，否则映射为 `BAD_RANGE`；word little-endian，每个 byte lane 对应 `mem_addr+lane`。未握手时 valid、地址、方向、数据和两个 strobe 保持稳定；读数据与 `mem_error_code` 在握手周期返回。成功传输的 error code 为 `0/NONE`；零 strobe 或读写 strobe 冲突返回 `1/BAD_ARGUMENT`；未对齐、选中字节越出单个允许对象/张量的半开区间、跨对象访问、访问 64-byte 对齐空隙或向输入/权重写入返回 `2/BAD_RANGE`；memory model 存储故障返回 `6/INTERNAL`。PL 将握手返回的 `1/2/6` 原样写入 CSR `ERROR_CODE` 并中止任务；任何其他非零响应码按 `INTERNAL` 处理。错误请求没有内存副作用。例如 5,070-byte 的 head13 尾 word 只选择 lane `0011`；不得因为 word 对齐而越过其逻辑张量尾部。读请求要求 `mem_rstrb!=0 && mem_wstrb==0`；仅选中的读 lane 返回数据，未选择 lane 在 `mem_rdata` 中为 0。写请求要求 `mem_wstrb!=0 && mem_rstrb==0`；未选择 lane 无副作用。testbench memory model 空闲或复位时拉低 `mem_ready` 并将 error code 置 0；PL busy 且拥有 buffer 时，该模型按冻结停顿周期控制 ready，传输须满足 `mem_valid && mem_ready`。reset/timeout 撤销未握手请求且不产生延迟写副作用。物理 AXI/DMA/cache 绑定留到已获准的 2B G0，不由本仿真协议冒充。

## 4. 检测头与 PS 解码/NMS

PL 输出两组原始 INT8 logits，分别为 `[1,30,13,13]` 和 `[1,30,26,26]` 连续 NCHW。通道编号 `channel=anchor_local*10+entry`，entry 顺序 `x,y,w,h,objectness,class0..class4`；查看时 reshape 为 `[anchor=3,entry=10,row,col]`。PS 先以各头清单中的 scale 将 INT8 乘成 float64 logits，再调用 D9 tiny416 参考语义解码。PL 不执行 sigmoid、exp、阈值或 NMS。PC 黄金与仿真联调必须先要求两头所有 INT8 字节完全相同，再解码；frame_id、检测数、类别、source_order、NMS 决策和输出顺序必须完全相同，score 绝对误差不超过 `1e-6`，归一化坐标各分量绝对误差不超过 `1e-6`，相对误差容限固定为 0。任一离散字段不同或数值超过上述容限即判该帧不匹配。

anchors=`[(10,14),(23,27),(37,58),(81,82),(135,169),(344,319)]`；stride 32 head mask=`[3,4,5]`，stride 16 head mask=`[1,2,3]`；`classes=5`、`scale_x_y=1.05`、`new_coords=0`。score=`sigmoid(objectness)*sigmoid(class)`。letterbox 逆变换严格使用 D2 整数 resize 与左上 floor padding；坐标 finite/raw 正面积校验后逐边裁剪到 `[0,1]`，裁剪后零面积丢弃。阈值为 `score >= 0.25`；稳定同分顺序为 head 顺序、row-major cell、anchor 顺序、class_id；每图先按分数稳定排序并截断到 15 个，再执行类别内 greedy NMS，IoU=`0.45`，跨类别不抑制。此处逐项遵守 D6/D9 已冻结行为，包括奇数总 padding 的半像素差异。

## 5. 固定测试集、随机性和误差

PS 解析/NMS 绑定 D9 基线提交中的 CPU 夹具，基线为 `0ce55634c4e07000b0f8c1640b3b6ba4ab072386`，测试源码 SHA-256 `7c5aebac28f316c16e4fbef80905c73b21036cfeab80115c926f143605277f5a`。夹具覆盖手算坐标/分数、空输出、同类抑制/异类保留、阈值等号、奇数补边、边界裁剪和 15 框上限；它们是独立检测头输入，不冒充卷积网络图片输入。109 个网络输入中的 2 张官方多 GT 图片保证了多目标场景进入整网黄金；实际检测头的多候选、抑制和输出顺序仍须通过整网 CPU 黄金与 D9 fixture 验证。

每个 cfg 算子层固定 1,000 个随机输出点和 16 个定向向量；另对共享 INT8 MAC 基元固定 1,000 个随机点积向量和 16 个定向向量。所有逐层向量使用机器清单里的实际 NCHW 形状、kernel、stride、padding、activation、scale，不缩小或替换模型参数。机器清单逐项给出 MAC 的 K、activation/weight 字节、bias、INT64 精确和及 INT32 首次溢出位置；逐卷积层给出精确输出 NCHW 目标、输入 reduction 字节、对应 GFINT8W1 权重字节、bias、累加顺序、scale 和 padding；逐 route 层给出目标坐标、来源张量、group 通道切片、输入/重标定/拼接后通道字节。case_index `0..15` 与名称一一对应且不扩展；机器清单中的 materialized 向量为所有实际 cfg 算子及共享 MAC 的规范输入；maxpool 向量逐 tap 给出窗口坐标、源值、padding 候选和最大值，upsample 向量给出输出查询、映射源坐标及精确复制值，YOLO 向量给出头部别名、通道/网格坐标和字节偏移。route 分组切片先于重标定；case 9 在来源 scale 不同的层，按 cfg 来源顺序选择首个 scale 不等于目标最大 scale 的来源，将其所选通道填为 `-127`、其他来源填零，并要求重标定后的值确实变化；所有来源 scale 相同时则明确退化为 `[-1,+1]` identity-path 向量。tiny416 的三个 maxpool 都是 `2×2/stride 2/Darknet padding 参数 1`，窗口从输入原点开始且实际侧 padding 为零；逐层池化用例只检查这些真实窗口，卷积 1×1 层也不伪造 padding。通用卷积 3×3 零填充和有外部边界的 Darknet maxpool 则使用清单中单独列出的原语夹具，不计入模型层用例。xorshift32 使用一个共享流，初始种子 `20260922`；每个选择器消耗一个 uint32 并对上界取模，每个 INT8 值将低字节按 `(byte % 255)-127` 映射；算子名 ASCII 顺序，层号升序，每层先随机 case `0..999` 后定向 case `0..15`，定向用例不消耗随机状态。共享 MAC 作为单一实例插入 `int8_mac` 的 ASCII 顺序位置，1000 个随机 case 按 case_index 对 21 个卷积层 K 长度取模循环。CSR 在硬复位外恒定 ready，不存在 CSR 停顿向量；PS 每次接受后必须在下一上升沿前撤销或更新 valid。只有 memory request 使用停顿周期 `[0,1,2,7,3]`；测试平台对每种 memory transfer class 按序拉低 mem_ready 对应周期数，请求字段保持稳定，随后首个 ready-high 上升沿接受请求；completion/timeout 边界、待决写复位/超时取消与恢复行为见机器清单固定刺激。

协议错误恢复刺激固定两组可执行路径。memory model 对活动任务的合法 feature 读分别注入 response code 6 与未知非零 code 7；PS/PL 结果必须为 CSR `ERROR_CODE=INTERNAL(6)`、`error=1`、`busy=done=pl_owns_buffers=0`、ownership 回到 PS、head 无效，失败读无副作用，ACK 后接受下一合法 start。共享 MAC 的定向 `case_index=9`（首次 INT32 溢出 product index 0）仅在 MAC 算子单测中验证；控制 FSM 恢复另用 behavioral backend stub：合法 start 被接受且 STATUS.busy=1 后，testbench 在内部完成接口对 `operator_result_valid` 脉冲一个上升沿并给 `operator_error_code=7`。控制器必须以 `ACCUMULATOR_OVERFLOW(7)` 结束并保持同样的错误状态、无效 head、PS ownership 与 ACK 后恢复。该 stub 事件只验证错误控制路径，不声称 case 9 是 cfg/GF8 卷积向量或整网输入。memory response code 7 按未知码映射到 INTERNAL，与 CSR 错误码 7 的累加溢出语义分开。测试必须断言两组刺激及其预期。

整网 CPU 黄金要求保存每项输入的逐层整数张量，并逐值对上述固定输入比较，mismatch 必须为零。头解码结果使用同一 CPU D9 函数对完全相同的 INT8 头重建，比较类别、分数、坐标、source_order 与框数；无非确定性排序。固定输入的原图与预处理张量摘要、模型参数、算子 plan、随机种子和 CPU 黄金输出必须在证据索引中相互绑定。
