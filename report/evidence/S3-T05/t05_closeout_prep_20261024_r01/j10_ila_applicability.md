# J10「半屏黑」与「无 ILA」：适用范围与依据绑定（2026-10-24 准备版）

- 依据：015 r03 §2.4 两行 ——
  「J10半屏黑：明确当前部署为已验证 J11/CMOS2 单路；J10故障保留开放。若正式需求要求 J10，须修复；
  **仅在有明确批准的部署范围排除依据时**可列该版本不适用，**不能自行宣布故障关闭**」；
  「无 ILA：属当前许可/工具能力限制，使用可审查的仿真、计数/状态寄存器、cache 一致性取帧及受控转储补足必要证据；
  **不因无 ILA 免掉功能/时序/耐久标准**，不在本轮强行改许可或植入调试核」。
- 性质：**范围与依据绑定声明**（不是故障关闭结论）。

## 1. J10「半屏黑」

| 项 | 内容 |
|---|---|
| 当前部署范围 | **已验证 J11/CMOS2 单路**（`board/stage3/hardware/an5642_j11_cmos2.xdc`，sha256 `2dae928c…`）；复测与实时彩色证据均在 J11 上取得 |
| J10 约束现状 | `board/stage3/hardware/an5642_j10_cmos2.xdc`（sha256 `07fe96ad…`）与官方 XDC **16/16 一致** ⇒ 现象**不是映射错误** |
| 现象 | Wong 目视「上半黑、下半黄白」，**未定性**（既有 STATE 记录；无根因结论） |
| 处置 | **保持开放（OPEN）**：不作为当前部署的通过条件，也不宣布关闭 |
| 何时可列 NOT_APPLICABLE | 仅当有**明确批准的部署范围排除依据**（例如 Wong/治理层书面决定"本版本只交付 J11 单路、J10 不在验收范围"），并在报告中绑定该批准记录的 ID 与日期 |
| 当前是否已有该批准 | **无**（本轮实查：未见针对 J10 的部署范围排除批准）⇒ 故**不得**写"不适用"，只能写 OPEN |
| 若正式需求要求 J10 | 须修复（硬件/接线/传感器侧）后再验收；本轮不改接线、不测电气 |

## 2. 无 ILA（BASIC 许可）

| 项 | 内容 |
|---|---|
| 事实 | BASIC 许可 `D:\Xilinx_licenses\basic_only.lic` **不支持** `create_debug_core`（Vivado `12-29205`）⇒ 无 ILA 波形 |
| 替代证据工具（现有、可审查） | ① 计数器/状态寄存器（`FrmCnt`、S2MM SR、UART 诊断、`S3_DIAG*`）；② cache 一致性的取帧（`Xil_DCacheInvalidateRange` + v6 指纹 / v11 freeze / v12 bars）；③ 受控转储（`stop → mrd → con`，参数化 base/stride 来自运行期回读）；④ 离线仿真（本项目此前未做 RTL 仿真，属**开放**而非豁免） |
| 边界 | **不因无 ILA 免掉**功能/时序/耐久标准；不可用 ILA 的项目须以①–④的**组合**补足必要证据，并如实写明哪些证据无法取得 |
| 本轮不做 | 不改许可、不植入调试核（`bd_insert_ila.tcl`/`netlist_insert_ila.tcl` 仅留档，**不在本轮执行**） |
| 关闭条件 | 与本项相关的验收（如 VDMA 路径错误、帧同步、时序）以①–④的证据组合逐项满足；无 ILA 本身**不是**"不适用"理由，而是**证据手段限制**，须在对应报告中说明并获得可接受的替代证据 |

## 3. 使用本文件的方式

- 任何"不适用/豁免/排除"结论都必须**引用本文件**并写明：批准记录 ID、日期、批准的部署范围（bit/XSA/ELF 哈希）、适用边界。
- 无批准记录 ⇒ 对应项写 **OPEN**，在验收表中**继续阻断**该维度。
- 本文件不改变 015 §2.4 的任何判定口径；不新增豁免。
