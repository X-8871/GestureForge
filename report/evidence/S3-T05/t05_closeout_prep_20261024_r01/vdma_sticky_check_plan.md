- 依据：015 r03 §2.4「保留启动原值、错误位解释和运行增量，核对是否复现及影响；**不能只清寄存器后称零错误**，

**纪律**：不得只清寄存器后宣称零错误；不得用"清后无复现"替代解释与影响判定。

## 2. 核对步骤（单次硬件窗口内，按 018 §3.3 记录）

1. **窗口与身份**：记录开始/结束时刻、独占持有方、bit/XSA/ELF 实测哈希（`7cb33068…` / `1f5b138e…` / `1457cda4…`）、COM4 与 JTAG 使用、`hw_server` 是否为自起（自起则用后终止）。
2. **启动原值**：上电/下载后**不清**即读 S2MM SR，记录原始值与逐位解码（同时读 `CR`、`VSIZE`、`HSIZE`、`FRMDLY`、`ADDR`、`MM2S_SR` 作对照）。
3. **位含义复核**：以 AXI VDMA 寄存器规范（PG020，S2MM SR 位定义）核对项目既有解码表；两者不一致时记录差异，**不沿用未复核的位名**。
4. **清 sticky**：SR 写 1-清（记录写入值），随后**立即**回读确认清除结果。
5. **运行增量**：在当前彩色部署下连续运行（与耐久项同一窗口），按固定间隔（建议 60 s）记录 SR 与 `FrmCnt`/`IOC` 类计数，直到窗口结束；记录任何 S2MM halted/error 事件与画面异常时刻。
6. **复现判定**：
   - 若 `0x00015810`（或等价位集）**再次出现** ⇒ 记录首次出现时刻、当时的 `VSIZE/HSIZE/STRIDE` 实际流尺寸与 S2MM 状态，判定影响（丢帧/错位/停流）并与帧计数对齐。
   - 若**未再出现** ⇒ 仍须给出解释假设（例如仅在启动/下载过渡期出现）与支持证据；**不得**仅凭"未复现"关闭。
7. **影响与关闭条件**：
   - **CLOSED**：位集有可复现的成因解释 + 与观测现象一致 + 修复/规避有证据（或明确证明仅启动瞬态且不影响功能），并在匹配版本上复核。
   - **OPEN（默认）**：无解释或无影响判定 ⇒ 继续阻断相应验收（015 §2.4）。
8. **收尾**：记录板上最终状态（当前流是否恢复实时彩色、`0x503D=0x00`）、JTAG/COM4/HDMI 与自起服务收尾、恢复入口（bit/ELF/地址）、未关闭项。
