# VDMA S2MM `FSZ_MORE`（`0x00015810` 的置位位）根因分析材料（不猜，只列依据与待证）

- 现象基线：见 `report/evidence/S3-T05/t05_stage3_window_20261024_r01/vdma_sticky_result.md`
  （启动原值 `0x00015810`、两次独立启动复现、一次性 W1C 后 31 min 未复现、无功能影响；判定 PARTIAL）。
- 本文件只做**根因分析材料**：把"已证实"与"假设"分开，并给出可离线/可后续执行的具体核对项。**不含未证实的断言。**

## 1. 已证实的事实（本版实测）

| # | 事实 | 证据 |
|---|---|---|
| F1 | 置位位集 = `INT(0x10) + FSZ_MORE(0x800) + ERR_IRQ(0x4000)`（+帧计数状态位 `0x1000`） | 应用自身 `S3_DIAG5_SR_DECODE`；`addr_map_final2.txt` |
| F2 | **两次独立启动**都在应用启动阶段出现同一值（`phase=0` 时 `0x00014810`，`t=5 s` 起 `0x00015810`） | `uart_window.log`、`uart_restore.stdout` |
| F3 | 清一次后再运行 **31 分钟 / 7 次回读**，错误位**未复现**，SR 恒为 `0x00011000`（仅状态位） | `endurance_probes.txt` |
| F4 | 全程无功能影响：`HALTED=0`、`IDLE=0`、`MM2S_SR=0x00011000`、活写标记 5/5、帧指纹随时间变化 | 同上 + `uart_window.log` |
| F5 | S2MM 配置：`VSIZE=0x2D0(720)`、`HSIZE=0x0F00(3840)`、`STRIDE=0x0F00`、单缓冲 `ADDR=0x00110C00`（与 MM2S 同一缓冲） | `address_facts.md` |
| F6 | IP 配置：`C_INCLUDE_S2MM=1`、`C_INCLUDE_S2MM_SF=1`（store-and-forward）、`C_SMM_SOF_ENABLE=1`、`C_S_AXIS_S2MM_TDATA_WIDTH=24` | `t05_sw_20261020_r01/sr_bit_sources/design_axi_vdma_1_config.txt`（IP 配置文本） |

## 2. `FSZ_MORE` 的含义（**证据边界**）

- 项目既有解码表与应用打印把该位命名为 **`FSZ_MORE`**（"Frame Size More"）。该命名**沿用既有项目证据**，本轮**未**独立核对官方手册原文。
- **盘上无 PG020 / AXI VDMA 官方手册**（本轮实查：`D:\codex-worktrees\dbdf`、`D:\FPGA\AX7Z020` 下按 `*pg020*`/`*axi_vdma*`/`*vdma*.pdf` 检索，仅命中 XDC/配置等文件，**无官方 PDF**）。
  ⇒ 因此"`FSZ_MORE` 的精确定义、置位条件、是否 sticky"等**必须**以官方手册核对后写入本文件 §5；
  **在此之前不得把任何触发机制写成结论。**

## 3. 候选触发机制（**假设 + 各自的核对方法**；均未被证实）

| H | 假设 | 支持它的观察 | 反驳/风险 | 如何核对 |
|---|---|---|---|---|
| H1 | **启动瞬态**：S2MM 先启动（VSIZE/HSIZE 已写）而 DVP 数据流尚未稳定，首个/首个若干帧的字节数多于配置帧长 ⇒ 置位 | F2（每次启动都出现、只出现一次）、F3（清后不再出现） | 未直接测到"启动瞬间的数据量" | 在启动窗口内（t=0…30 s）以**更密采样**读 SR（如每 0.5 s）+ 记录 `FRMCNT`，确定置位的精确时刻与持续时长 |
| H2 | **SOF 修复检测器的首个 SOF 边界**：`GAP_THRESH=16384` 的 hblank 低检测在复位后首帧可能尚未满足（既有构建限制里已登记"复位后第一帧可能没有 SOF"） ⇒ 该帧跨界，S2MM 按"更多数据"判 | 与 F2 的"仅启动阶段"一致；构建记录的 `limitations` 明确写了首帧 SOF 风险 | 属推断，未与 SR 时刻对齐 | 把 H2 的预测时刻（复位后首帧）与 H1 测得的置位时刻**对齐核对**；必要时用 `v9`/`v11` 类只读应用在启动前后各读一次 SR |
| H3 | **帧长寄存器写入与数据流到达的次序**：`VSIZE/HSIZE/STRIDE` 的写入与 S2MM 启动次序造成一次"按旧/零尺寸"的判定 | F5 的寄存器值在稳定态正确 | 未观测到中间态寄存器值 | 启动窗口内连续读 `0x430100A0/A4/A8/AC` 与 `SR`，检查是否出现尺寸=0 的窗口 |
| H4 | **DRE/位宽转换（32→24 bit）** 在启动边界产生额外 beat | F6 显示 `C_INCLUDE_S2MM_DRE=1`、TDATA=24 | 无直接证据 | 读 VDMA 手册的 DRE 行为；或对照"无 DRE 配置"的既有 run |
