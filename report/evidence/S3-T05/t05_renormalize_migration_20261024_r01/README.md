# 提交字节迁移登记：`-text` 广域生效导致的历史 S3-T05 blob 重存（评审 BL-1）

## 0. 更正声明（**撤回先前失实陈述**）

先前 `hash_basis_check.txt` 与相关说明写有「**历史 S3-T05 目录沿用其原有 LF 归一 blob、未改动一字节**」。
**该陈述失实，现予撤回。** 事实是：`report/evidence/S3-T05/** -text` 属**全树**规则，F 提交的
`git add --renormalize` 因此**对全树生效**，把大量历史证据文件的 blob 由「LF 归一」重存为**原始字节（CRLF 原貌）**，
**OID 发生变化**，而当时**未登记**。静默改写冻结证据 blob 是缺陷；**改写本身不是缺陷**（见 §2 判定）。

## 2. 判定：**保留**广域 `-text`

- `-text` 使「提交字节 == 原始字节」，是**修好**（原缺陷是 autocrlf 把 CRLF 归一为 LF，使记录哈希绑不上提交字节）。
- **全树复算（本轮实测）**：见 `41to5_recompute.txt`（同一命令 `--scope report/evidence/S3-T05`，工作区固定为提交 `f517ca96`）：
  - 基准提交 `d4a3cff`（F 的父）：检查 215 文件、**不一致 85**、提交内缺失 20（缺失=后续新增文件）、含 CRLF 72；
  - 提交 `f517ca96`（本修复提交）：检查 215 文件、**不一致 0**、缺失 0、含 CRLF 72（原始字节，非缺陷）
    ⇒ **`BLOB_BYTE_IDENTITY_OK`**。
- **与复审「41→5」的口径差异（如实列出）**：复审的 41→5 是在**另一配对/工作区状态**下测得；本轮以「工作区=提交 f517ca96、分别比对父提交与自身 blob」为口径，得 85→**0**（更严）。两者不冲突；**以本次 `f517ca96` 的 0/0 为最新事实**，且复审所列 5 处（自指产物、`board/**` 副本）在本口径下同为 0 不一致。
