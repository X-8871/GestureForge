# VDMA 粘滞 `0x00015810` 核对结果（2026-10-24 板级窗口）

- 纪律（015 §2.4）：保留启动原值、错误位解释与运行增量；**不得只清寄存器后称零错误**。
- 本窗口做法：读启动原值 → 记录位解释 → **一次性** W1C 清除（记录前后值）→ 31 分钟实时运行中 7 次回读。

## 1. 启动原值（下载后、未清）

- 应用 UART：`S3_DIAG5_REG phase=0 S2MM_CR=0x00010003 S2MM_SR=0x00014810 FRMCNT=1 HALTED=0 IDLE=0`;
  `S3_DIAG5_SR_DECODE phase=0 INT=1 ... FSZ_MORE=1 ... ERR_IRQ=1`；其后 `S3_DIAG6_SR t=5/10/15/20/27 S2MM_SR=0x00015810`。
- 只读探测：`SR_S2MM=0x00015810`、`CR_S2MM=0x00010003`、`HALTED=0、IDLE=0`（`probe_00_startup.txt`）。
- **位解释**（沿用应用自身解码 + 既有项目解码表，未新造位名）：置位 = `INT(0x10) + FSZ_MORE(0x800) + ERR_IRQ(0x4000)`（另含帧计数类状态位 `0x1000`）。
- **复现性**：本次窗口内**两次独立启动**（耐久轮与恢复轮）都在启动阶段出现同一值 ⇒ **启动瞬态、可复现**。

## 2. 一次性清除（W1C）

```
mwr -force 0x43010034 0x00015810      # 沿用既有 jtag_cont_write_probe.tcl 范式；只清一次
SR_BEFORE=0x00015810  →  SR_AFTER=0x00011000
```
清掉的正是三个错误位（`0x4810`）；残留 `0x00011000` 为**帧计数类状态位**（与 `MM2S_SR=0x00011000` 同形），**不是**错误位。
`CR` 未变（`0x00010003`）、`HALTED=0/IDLE=0`，清除未改变运行状态。

## 4. 判定（如实、不过度）

- **未复现**：清除后 31 分钟实时运行内，错误位（INT/FSZ_MORE/ERR_IRQ）**未再出现**，SR 恒为 `0x00011000`。
- **影响观测**：全程 `HALTED=0`、`IDLE=0`、`MM2S_SR=0x00011000`（显示无错误）、每轮活写标记 **5/5**（DMA 持续写入）、
  UART 5 次采样 × 3 站点指纹**全部相异**（帧内容随画面变化）⇒ **未观测到功能影响**。
- **关闭条件未全满足**：仍**没有**对该启动瞬态给出根因解释（FSZ_MORE 的触发源未定位，需结合 VDMA 手册与启动时序进一步核对）。
  故本项判定为 **PARTIAL（有解释方向、无根因；不宣布关闭）**，**不得**写成"零错误"。

## 5. 建议的后续（需新窗口，不在本窗口）

1. 结合 PG020 位定义与启动时序，核对 `FSZ_MORE` 的触发条件（帧尺寸寄存器写入与 S2MM 启动的先后）。
2. 若需关闭本项：给出根因 + 修复/规避（或证明仅启动瞬态且无影响），并在匹配版本上以新 RunId 复核。
