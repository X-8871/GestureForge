# VDMA 粘滞状态根因离线补充

## 1. 范围与结论

本记录只复核仓库内已保存的运行日志、IP 配置/元数据/HDL 摘录和阶段3应用补丁，进一步校准 `0x00015810` 的解释。未操作板卡、未运行 Vivado、未生成波形或仿真，也未修改设计代码。

**结论保持 `PARTIAL`：** bit11 的来源在已存 HDL 摘录中是组合状态信号；现有寄存器快照和稳态耐久记录不足以确定本次运行是哪一种输入边界触发，更不足以关闭 VDMA 未决项。

## 2. 可复核事实

1. UART 日志首次 `S3_DIAG5_REG phase=0` 记录 `S2MM_SR=0x00014810`；同一日志 `t=5` 首次记录 `0x00015810`。两值异或为 `0x00001000`：bit11（`0x800`）在首次采样时已经置位，`t=5` 仅新增 bit12（`0x1000`）。bit4（`0x10`）及 bit14（`0x4000`）也已在首次采样出现；bit16–23 的 `FRMCNT=1` 是寄存器计数状态字段，不等于已接收帧数。
2. 已提交的 IP 元数据把 bit11（`0x800`）命名为 `SOFLateErr`，描述称其不使 VDMA halt，且当输入帧尺寸大于编程的 `VSIZE` 时置位。已提交的 S2MM DMASR HDL 组装摘录将该位连接到 `s2mm_fsize_more_or_sof_late_bit`。因此本地材料支持该位与帧尺寸/SOF 类错误有关，但**位名和快照不能区分内部信号中的具体触发分支**。旧应用日志的 `FSZ_MORE` 是应用解码标签，不能据此把本次事件唯一归因为“帧多”。
3. IP 元数据对 bit4 `VDMAIntErr` 列出零 HSIZE/VSIZE、helper core/DataMover 内部错误及帧尺寸小于 VSIZE 等来源。当前首次回读的 HSIZE/VSIZE 为非零，状态同时显示 `HALTED=0`、`IDLE=0`；这不支持将 bit4 单独解释成独立的 DataMover 故障，也不能排除初始化期间的瞬态或证明具体原因。
4. 版本化应用补丁显示，执行 `vdma_write_init(...)` 前有 15 秒等待，调用后才打印 `S3_DIAG5_REG phase=0`。这把观察时点限定为 VDMA 初始化调用之后；没有更密的状态采样，因此无法确定 bit11 在复位、配置还是启动的哪一步首次出现。补丁注释中关于首帧/等待的解释是待证假设，不作为实测结论。
5. 既有窗口材料记录一次 W1C 清除后连续耐久期间状态稳定为 `0x00011000`，功能未受影响。它说明该轮清除后的稳态未重现，不解释启动时的置位来源。
6. 已提交配置摘录显示 AXI-MM 侧 64 bit、AXI-Stream 侧 24 bit，启用 DRE。现存证据没有证明所谓“32→24 位转换”实际存在或导致该状态；该说法不应作为根因结论。

## 3. 假设状态

| 假设 | 当前判断 | 仍缺证据 |
|---|---|---|
| 传感器连续出流时 S2MM 在帧中途启动，首个帧/SOF 边界迟到 | 与 bit11 的 SOF/帧尺寸类语义及启动时出现相容；**未证实** | 复位、初始化、首个 SOF/TLAST 的时序观测，或能等价区分边界的运行期证据 |
| HSIZE/VSIZE 写入或初始化次序造成瞬态 | 当前稳态寄存器值正确并不能排除瞬态；**未证实** | 初始化各步骤前后的寄存器与状态快照 |
| 独立 DataMover/总线故障 | 现有状态和寄存器不支持直接归因；**未证实** | 独立错误响应/波形或足以区分来源的诊断证据 |

## 4. 关闭条件与限制

- 在获准的后续硬件窗口中，围绕 S2MM 复位、配置、启动和首个帧边界记录足够密的状态；如可用，保存能区分 `TUSER`/`TLAST` 到达时序的观测。当前记录没有这类数据。
- 对 `SOFLateErr` 的手册定义仍需按本项目对应的官方版本资料核对。本包使用仓库已提交的 IP 元数据和 HDL 摘录，不把它们等同于已独立核对的 PG020 原文。
- BASIC 许可下本轮无 ILA；本轮未执行板测、Vivado、仿真或正式手册核验。
- 本清单与独立复审通过也只覆盖离线证据和解释边界；VDMA 根因保持开放，阶段3 G5 未通过、未冻结。
