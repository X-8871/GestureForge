## 1. 通道与位映射

| 项 | 值 |
|---|---|
| 传感器/格式 | OV5640（AN5642 模块）／DVP→RGB565（`0x4300=0x60`、`0x501F=0x01`） |
| 通道 | 模块插 **J11**，走模块 CMOS2；约束 `board/stage3/hardware/an5642_j11_cmos2.xdc` |
| 帧缓冲 | 内存序 `B,G,R`，1280×720，每行 3840 B；行地址 = `FRAME0 + y×stride`（运行期回读） |
| 可疑单线 | `cmos_d[9]` → FPGA **F17**（LVCMOS33 / Bank35）= 两个 DVP 字节各自的 MSB |
| 字节/字段布局 | 第一字节 = `{b[4:0], g[5:3]}`（MSB=`B[4]`）、第二字节 = `{g[2:0], r[4:0]}`（MSB=`G[2]`）；16 位字 `R=word[4:0]`、`G=word[10:5]`、`B=word[15:11]` |
| 后果 | `B[4]` 丢失 ⇒ 帧缓冲 **offset0（蓝）bit7** 恒 0；`G[2]` 丢失 ⇒ **offset1（绿）bit4** 恒 0；`R[4:0]` 不在丢失字节的 MSB ⇒ **offset2（红）完好**（对照组 C1） |
| 命名限制（N-1） | 「蓝/绿」是帧缓冲通道名；字节↔通道对应来自归档网表（offset0=B、offset1=G、offset2=R）；**DVP 字节序 = 厂商源码 + 网表双重依据**（已入库参考 `report/evidence/S3-T05/t05_github_ref_20261020_r01/cmos_8_16bit_ref.v`，blob sha256 `08a32535…`，拼接语句 `pdata_o <= {pdata_i_d0,pdata_i};` 先到字节进高半字；**不引用行号**——该文件含混合行尾，按 `\n` 计 83 行、`splitlines()` 计 167 行，原『157』系该计数假象，按 `\n` 行计为 **79**）。**计数可复现（Q-2）**：dbdf 内 `cmos_8_16bit*.v` **47 份**（45 恰同名）、**47/47 含该语句**。**命名限制仍保留**：阶段B 报告用数值判据（offset0 bit7、offset1 bit4、offset2 完整）陈述，不单独依赖通道命名 |

## 2. 期望值（由上次位丢失算术给出）

| 量 | 仍为旧缺陷 | 修好 | 判据 |
|---|---|---|---|
| 白条 R8 | 248 | 248 | C1：`≥240`（对照组，不区分） |
| 白条 G8 | 236 | **252** | C2：`≥248`（区分） |
| 白条 B8 | 120 | **248** | C3：`≥240`（区分；等价「蓝出现 >127」） |
| 白条 R5 / G6 / B5 | 31 / 59 / 15 | 31 / **63** / **31** | C2/C3 的字段形式 |
| 白条中性度 | `|G−B|=116` | `≤4` | C4：三通道差 `≤8` |
| 黑条 | 0,4,0 | 0,4,0 | C5：`R=0, G≤8, B≤8`（负样本） |
| 蓝 bit7 / 绿 bit4 置位率 | 0.000% / 0.000% | 均 `>0` | C6（区分） |
| 字段位可辨数（C7） | **14/16**（对齐口径；严格口径 13/16） | **16/16** | C7：16 字段位 = `5+6+5`；8 结构性低位 = `3+2+3`；黑条字段值 ≤ 容差（R/B 1、G 2）不计不可辨 |

**C7 两种口径（评审 B-1/B-2 关闭依据）**：16 个字段位 = R 字段 5 + G 字段 6 + B 字段 5；8 个结构性恒 0 低位 = R 3 + G 2 + B 3（`16+8=24=3×8`）。
对齐口径（默认，与 C5 的 `G≤8` 一致）：缺陷 **14/16**、修好 **16/16**；严格口径（黑条字段位必须为 0）：缺陷 **13/16**（多出的第 3 位是黑条 1 LSB 残差 `G=4 ⇒ G6=1` 造成的 `G6 bit0`）、修好最多 **15/16** —— 与 C5 冲突，故仅作对照（`--strict-black-bits`），不作验收口径。

8 位显示值是**移位扩展**（`248=31<<3`、`252=63<<2`），**不是 255**；容差用于吸收 5/6/5 映射的 1 LSB 残差。

## 3. 边界（必须随结论一起说明）

1. **「每个字节 8 位逐位可辨」不可字面达成**：RGB565 为 5/6/5 移位扩展，R/B 显示字节 bit2..0、G 显示字节 bit1..0 结构性恒 0（合计 **8 位**）；可辨的是 **16 个字段位**（R5+G6+B5）。依据：`5+6+5=16`、`3+2+3=8`、`16+8=24=3×8`。
2. 真彩验收 = 机器部分（C1–C7 + C4 中性度）**且** Wong 目视「不偏黄、不偏青」；脚本始终输出 `requires_human_visual=true`。
3. `0x503D` 内部彩条只测数传通路，不证明真实场景色彩；写入仅易失，用后必须恢复并回读。
4. 判定通过不等于 G3/G4/G5，也不等于独立审查通过。
5. **前提**：本仓库 `core.autocrlf=true`，按工作区口径复核哈希/自证须 `git -c core.autocrlf=false clone`（或 `git cat-file blob`）；转储地址必须运行期回读（缺地址执行器 `exit 4`）。

## 4. 结论规则

| 判定 | 条件 | 退出码 | 动作 |
|---|---|---|---|
| `BIT_INTEGRITY_PASS` | C1–C7 全通过 | 0 | 配合目视 → 可建议关闭颜色子项 |
| `DEFECT_REPRODUCED` | 旧签名成立且白条 G/B 未满量程 | 1 | 判板侧/连接侧方向，颜色保持 `DEFERRED` |
| `INCONCLUSIVE_ATYPICAL` | 例如只修好一路 | 3 | 人工判读，**不得当通过** |
| `USAGE_OR_INPUT_ERROR` | 缺文件/长度非法/彩条段不足 | 2 | 修正输入重跑 |

## 5. 复现缺陷时的定位顺序

2×2 交叉矩阵（新旧模块 × J11/J10）→ 触点目视 → 线序/33Ω/F17 → 对照另一条 MSB 线（D8/J18）连续性 → 原厂例程/另一套板复现。详见 README §6 与 JSON 的 `hardware_localization_if_defect_reproduced`。
