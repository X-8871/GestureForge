# S6-C 动作回执边界与防旁路范围

## 用途和输入

本包记录阶段6内部 `ActionReceiptBoundary` 对 `GestureInteractionCore.note_action_ack()` 的离线适配。边界把完整 ACK JSON 业务对象作为 `action_id` 指纹，接收时钟单独由调用方显式提供；重复 ACK 的核心内部 `duplicate_ack_ignored` 标志不属于业务负载。会话复位经 `reset_session()` 进入同一边界，以保留核心跨会话 action ID 去重历史。

适用实现为源文件 `src/stage6/s6_receipts.py`，核心基线由输入清单按工作树字节哈希绑定。该适配不提供真实 transport、动作后端、阶段5显示回执或有效状态观测接口，也不消费阶段4实时帧/时钟数据。

## 旁路检测

- 每次边界 ACK 处理开始时核对核心 `action_log` 的条数与完整顺序敏感内容摘要，并核对核心已见 ID 集合与边界所跟踪 ID 一致。
- 对相对预期快照新出现的已跟踪 `action_id` 旁路日志，去除核心重复标志后比较完整业务负载；相同负载和不同/不可核验负载都 fail-closed，并返回不同诊断。其他未跟踪 ACK 追加、已有日志改写、日志截断或复位绕过、已见 ID 账本不一致也 fail-closed。
- 核心调用前再次检查账本；核心调用后只接受一条与本次输入对应的预期追加，并核对旧日志前缀和已见 ID 账本，避免把旁路记录纳入新基线。
- 核心 `E_TICK` 等不修改 ACK 日志/已见 ID 账本的普通状态处理不会被误判为 ACK 旁路。

## 防护边界和限制

`GestureInteractionCore.note_action_ack()` 仍是公开可调用的方法；本次遵守“不改核心公共语义”的约束，没有在核心内加入适配器共享锁或关闭直接调用。因此，该边界可检测两个边界调用之间已经发生的串行旁路，但不能从 API 层阻止外部直接调用，也不能保证与外部直接写入并发时的原子互斥或回滚。并发旁路若落在核心调用附近，前后核验会尽量 fail-closed；旁路调用自身已经造成的核心副作用不能由适配器撤销。集成部署必须让本边界成为 ACK 日志和计数的唯一写入口；若需要跨线程/进程强保证，须由核心或后端提供正式共享串行化契约后再实现。

测试中的直接调用是 fail-closed 检测模拟，不是现实 transport 测量或硬件动作证据。包内合成 ACK 不证明 `ACTION_EFFECTIVE` 的真实外部观测。
